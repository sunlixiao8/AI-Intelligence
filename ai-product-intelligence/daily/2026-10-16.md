# 1. Chefgpt

**来源链接：** https://trustmrr.com/startup/chefgpt  
**TrustMRR 摘要：** FOR SALE ChefGPT，Health & Fitness，Revenue $2.2k，Price $125k，Multiple 4.6x。

## 1.1 产品

- **名称：** ChefGPT
- **类别：** Health & Fitness / AI 膳食与食谱助手（从名称和分类推测）
- **目标用户：** 家庭做饭人群、健身/减脂人群、忙碌家长、想减少外卖的人。
- **产品形态：** 摘要未说明。推测可能是 AI 食谱生成、膳食计划、购物清单类工具。**证据不足，需打开 TrustMRR 详情页和官网验证。**

## 1.2 用户问题

它可能解决的是：

- 每天不知道吃什么；
- 冰箱里有食材但不会搭配；
- 有健身、减脂、控糖目标，但不会设计食谱；
- 做饭决策高频、琐碎、重复，愿意为“省时间 + 更健康”付费。

用户不只是好奇试用，而是因为“吃饭”是每天发生的高频问题。只要产品能稳定给出可执行食谱和购物清单，就有订阅可能。

## 1.3 商业信号

- **定价模式：** 未知。TrustMRR 摘要没有给定价页、订阅价格或付费积分。
- **月收入估算：** 平台标注 **$2.2k/月**。
- **收入类型：** 推测收入 / 平台披露收入，不是官方财报。
- **置信度：中低。** 因为来自 TrustMRR 聚合页，未打开详情页验证。
- **估值信号：** 售价 $125k，按 $2.2k/月计算年收入约 $26.4k，售价约为年收入 4.7 倍，与 Multiple 4.6x 接近。
- **牵引力：** 仅确认在 TrustMRR 挂牌出售。没有评论、流量、用户数、融资等证据。

## 1.4 为什么可能赚钱

- **使用频率：** 高。吃饭、备餐、购物清单是每日或每周重复。
- **紧迫程度：** 中高。健康目标、减脂、控糖、过敏人群有真实痛点。
- **预算负责人：** 个人或家庭。个人付费决策快，但客单价通常低。
- **切换成本：** 低。用户很容易换到 ChatGPT、菜谱 App 或小红书。
- **可能赚钱的原因：** 如果它把“生成食谱”变成“持续计划 + 购物清单 + 偏好记忆”，就能从一次性工具变成习惯产品。TrustMRR 给到 4.6x 年收入倍数，说明市场认为它可能有一定留存或品牌价值，但收入绝对值仍小。

## 1.5 产品逻辑与技术路径

**初学者 MVP 范围：**

1. 用户输入：食材、目标（减脂/增肌/控糖）、忌口、人数、预算。
2. AI 输出：7 天食谱、每餐营养估算、购物清单、备餐步骤。
3. 用户可保存、替换某餐、导出清单。
4. 订阅收费：$5-$9/月，或按周计划收费。

**推荐技术栈：**

- 前端：Next.js + Tailwind CSS
- 后端/数据库/认证：Supabase
- 支付：Stripe 或 Lemon Squeezy
- AI：OpenAI API 或同类模型
- 结构化输出：JSON Schema / function calling
- 数据分析：PostHog 或 Plausible

**AI 用法：**

- 生成：食谱、步骤、替代方案
- 抽取：从用户输入抽取忌口、目标、预算
- 分类：食材类别、营养标签
- 检索：可接入食谱库或营养数据库，减少幻觉
- 工作流：计划生成 → 购物清单 → 提醒 → 用户反馈 → 下周计划

**如果我来开发，最大问题：**

不是“生成食谱”，而是**保证可执行、安全、可留存**。  
- 过敏、孕期、糖尿病等场景不能只靠大模型自由生成；
- 营养估算容易不准；
- 用户第一周觉得新鲜，第二周可能不用；
- 获客成本高，因为菜谱内容免费且竞争激烈。

**降低难度的捷径：**

- 只做一个垂直人群，例如“高蛋白备餐”或“忙碌家长 30 分钟晚餐”；
- 先人工审核 100 个食谱模板，AI 只做组合和替换；
- 第一版不做自动营养计算，只做“目标标签 + 购物清单”；
- 用微信群/邮件交付，验证付费后再做 App。

## 1.6 适合 OPC 初学者的机会

- **更小众版本：** 高蛋白备餐、孕期友好、低 FODMAP、控糖晚餐、学生宿舍快手菜。
- **第一批访谈客户：** 健身爱好者、减脂人群、忙碌家长、备餐博主。
- **1 周验证实验：**
  1. 做一个落地页，承诺“输入目标，7 天食谱 + 购物清单”。
  2. 找 10 个健身用户，免费手动生成 7 天计划。
  3. 问他们是否愿意付 $5/月继续使用。
  4. 如果 10 人中有 3 人愿意预付，再做自动化。

## 2.5 产品逻辑与技术路径

**初学者 MVP 范围：**

1. 用户上传截图；
2. 视觉模型识别布局、文字、颜色、组件；
3. 生成 React + Tailwind 代码；
4. 在浏览器里预览；
5. 用户复制代码或下载项目；
6. 收费：按次、订阅或积分。

**推荐技术栈：**

- 前端：Next.js + Tailwind CSS
- 预览：Sandpack、iframe 或 StackBlitz
- AI：OpenAI Vision、Claude Vision 或同类多模态模型
- 后端：Next.js API Routes 或 FastAPI
- 支付：Stripe
- 存储：Supabase Storage

**AI 用法：**

- 视觉：识别截图布局
- 抽取：文字、颜色、间距、组件边界
- 生成：HTML/CSS/React 代码
- 智能体工作流：生成 → 预览 → 用户指出问题 → 局部修改
- 检索：可接入组件库、设计系统文档

**如果我来开发，最大问题：**

从“截图能生成一个像样的页面”到“生成生产可用代码”之间差距巨大。  
- 复杂布局、响应式、交互状态、表单校验很难一次生成；
- 模型会幻觉出不存在的组件或样式；
- 用户期望“一键完美”，但实际需要反复修改；
- 大厂和开源免费替代品多，定价压力大。

**降低难度的捷径：**

- 只支持一种技术栈：React + Tailwind；
- 只做单页、静态、无复杂交互；
- 不承诺完整项目，只输出可复制组件；
- 先做垂直场景，例如邮件 HTML、后台表格、营销落地页。

## 2.6 适合 OPC 初学者的机会

- **更小众版本：**
  - 截图转邮件 HTML，兼容 Outlook/Gmail；
  - 截图转 Webflow/Framer 组件；
  - 设计系统 token 转换；
  - 截图转无障碍检查报告。
- **第一批访谈客户：** 前端开发者、自由职业者、设计工程师、做邮件营销的人。
- **1 周验证实验：**

  3. 记录他们手动修改了多久；

**推荐技术栈：**

- 前端：Next.js + Tailwind
- 存储：Supabase Storage
- 图像处理：分割模型 + 透视变换
- AI 图像：Stable Diffusion / ControlNet / 商用图像 API
- 支付：Stripe
- 部署：Vercel

**AI 用法：**

- 视觉：识别墙面、光线、透视
- 分割：分离墙面和家具
- 生成：合成挂画效果
- 检索：匹配商品 SKU 和尺寸

**如果我来开发，最大问题：**

不是生成一张好看的图，而是**逼真、尺寸正确、能对应真实商品**。  
- 生成图可能漂亮但不真实，导致买家收货后落差；
- 尺寸比例、材质、光影很难自动准确；
- 需要商品供应链、打印、物流；
- 消费者低频，获客成本高；
- 如果没有卖家合作，很难规模化。

**降低难度的捷径：**

- 只做“挂画预览”，不做完整室内设计；
- 与 Etsy/Printful 卖家合作，按张收费；
- 第一版用人工 + AI 修图，验证卖家是否愿意付费；
- 不碰库存和物流，只做预览工具。

## 4.6 适合 OPC 初学者的机会

- **更小众版本：** 为 Etsy 墙艺卖家做白标房间预览；为画廊做 AR/图片预览；为租房族做可移除墙贴预览。
- **第一批访谈客户：** Etsy 墙艺卖家、Shopify 家居卖家、室内设计师。
- **1 周验证实验：**
  1. 找 10 个 Etsy 墙艺卖家；
  2. 免费帮他们做 5 张买家房间预览图；
  3. 问是否愿意为买家提供该功能；
  4. 测试定价：$5/张或 $19/月。

# 6. 今日模式

**模式：AI 产品的价值不在“AI”，而在“工作流嵌入深度”。**

今天四个产品给了同一个信号：

1. **Chefgpt**：如果只是生成菜谱，价值低；如果变成每周膳食计划、购物清单、偏好记忆，价值高。
2. **Screenshot to Code**：如果只是生成代码片段，容易被大厂替代；如果能嵌入设计系统、组件库、开发流程，价值高。它的 0.7x 年收入倍数说明市场对护城河有怀疑。
3. **Lyro**：如果只是聊天机器人，竞争激烈；如果能接入商家知识库、预约、CRM，价值高。
4. **walldecor.io**：如果只是生成图片，价值低；如果能帮助卖家提高转化、降低退货，价值高。

**给个人创业者的启发：**

- 不要做“通用 AI 工具”，要做“垂直流程工具”；
- 不要只卖生成，要卖“持续结果”；
- 不要只服务消费者，要尽量找到有预算的卖家/企业主；
- 收入绝对值小的产品也能卖 $7.5k-$125k，说明微型 SaaS 可以资产化，但前提是收入可验证、留存真实。

# 8. 用户访谈问题

可以直接拿去问潜在用户：

1. **“你上一次因为【做饭/客服回复/做前端页面/挑墙画】卡住是什么时候？当时你具体做了什么，花了多久？”**  
   目的：确认问题是否真实、高频、具体。

2. **“如果有一个工具能自动完成【核心结果】，但需要你上传【数据/截图/房间照片/知识库】，你最担心什么？什么情况下你会直接付费？”**  
   目的：识别信任障碍和付费触发点。

3. **“你现在为【相关工具/服务】每月花多少钱？如果新工具每月 $X，你会在什么条件下从现有方案切换？”**  
   目的：确认预算、替代方案和切换成本。

# 9. 下一步验证清单

本期证据最大问题是没有打开 TrustMRR 产品详情页，也没有官网定价、评论、流量。建议下一步：

1. 打开每个 TrustMRR 产品页，确认：
   - Revenue 是月收入还是年收入；
   - 是否 verified；
   - 是否有官网、创始人、增长数据。
2. 查每个产品官网定价页，确认：
   - 订阅价格；
   - 免费试用；
   - 目标客户。
3. 查 G2/Capterra/Chrome Web Store/Shopify App Store，确认：
   - 评论数和评分；
   - 真实用户抱怨；
   - 安装量或排名。
4. 对 Lyro 和 walldecor.io，先验证产品功能，再决定是否值得模仿。
5. 对 Chefgpt 和 Screenshot to Code，重点验证留存和竞争壁垒。

**一句话总结：**  
今日最值得个人创业者学习的不是“做一个 AI 工具”，而是找到一个高频、具体、有人愿意持续付费的流程，然后用 AI 把其中 30% 的重复劳动自动化。
