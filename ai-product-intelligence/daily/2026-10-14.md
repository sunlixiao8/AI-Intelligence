# 01 · Ecomz AI

**多租户电商建站 + 移动 App 生成平台**

| 项目 | 内容 |
|---|---|
| URL | https://trustmrr.com/startup/ecomz-ai |
| 类别 | AI / E-commerce SaaS |
| 状态 | 正在出售（FOR SALE） |
| 挂牌价 | $49,000 |
| 倍数 | 5.0x |

### 1. 产品

根据 TrustMRR 挂牌标题（**这是本期我掌握的关于它的全部事实**）：

> "Multi-Tenant SaaS eCommerce Store Builder and Mobile App Generator Platform"

翻译一下：一个**多租户 SaaS**，让客户**搭电商店铺**，并且能**生成配套的移动 App**。

- **目标用户**：推测是中小商家、想快速开店的卖家、以及想做**垂直电商平台**的创业者（因为是多租户，说明有「平台方」和「商家」两层）。
- **类别**：E-commerce / 建站工具。
- **这里的「AI」体现在哪**：**未知**。挂牌分类没有说明。可能用于生成商品文案、生成店铺页面、或生成 App 界面。这是你第一步要验证的。

### 2. 用户问题

**（以下为商业推理，非事实）**

如果这个描述成立，它解决的是一个**真实且反复出现**的问题链条：

1. 商家想开店 → Shopify 抽成、模板同质化、月费$29-$399。
2. 商家想要自己的 App → 原生 App 开发外包 ¥5万-$5万，且上架后没人下载。
3. 有人想做**垂直电商平台**（比如「只卖手作」、「只卖二手乐器」）→ 自己搭一套多租户系统 + App，成本和周期都劝退。

**用户为什么可能付费，而不只是试用？**

关键在于**它是不是嵌进了「收钱」这条链路**。建站工具如果是「一次性做好就放着」，续费会掉；但如果它承接了订单、支付、App 推送，商家**不敢随便停**。

### 5. 产品逻辑与技术路径（重点：你会遇到什么大问题）

**适合初学者的 MVP 范围（大幅收窄）**：

```
上传 30 张商品图 + 一段文字描述
   ↓
AI 生成：商品标题、卖点、详情页文案
   ↓
生成一个「可分享的单页店铺链接」（非多租户！）
   ↓
接入 Stripe Payment Link 收款
```

**先不要碰**：多租户、App 生成、自定义域名、模板系统。**这四个是吞噬初学者 3 个月的地方。**

**核心工作流**：
1. 用户上传商品图与基础信息
2. 视觉模型识别品类/风格 → 文本模型生成文案
3. 模板引擎渲染静态店铺页
4. 生成收款链接
5. **（第二版）**接入第三方履约与物流

**推荐技术栈**：
- 前端：Next.js + Tailwind CSS
- 后端：Next.js API Routes（第一版不需要独立后端）
- 数据库/认证：Supabase（第一版甚至可以不做登录，用魔法链接）
- 文件存储：Supabase Storage
- 支付：Stripe Payment Links（**这是最省事的捷径，不要一上来写支付系统**）
- AI：OpenAI API（视觉 + 文本）；文案生成用结构化输出（JSON schema）保证字段可控
- 部署：Vercel

**AI 用法**：主要是**生成（文案）+ 抽取（从杂乱商品信息里结构化字段）+ 视觉（识别商品品类和风格）**。**这个阶段不需要智能体。**

### 如果「我」来开发，会遇到的最大问题

**不是 AI，是这三个：**

1. **多租户的数据隔离**——这是最容易被低估的坑。一旦有 2 家客户，你就必须回答：数据怎么隔离？模板怎么隔离？一个客户的 bug 会不会影响所有人？用什么字段做租户键？**这个决策一旦做错，后期改造成本极高。** 第一版最省事的做法是：**根本不共享数据库**，一个客户一个 Supabase project，用配置表路由。丑，但能活。
2. **移动 App 生成 / 上架**——这是本项目最重的部分。App Store 审核、证书管理、打包流水线、每个客户一个 App 还是共用一个壳 App？**这一块足够单独开一家公司。** 如果你的 MVP 想 1 周上线，**直接砍掉 App**。
3. **AI 生成内容的质量下限**——电商文案一旦生成得「空、假、糊」，商家会立刻不信任你。你需要的不是更强的模型，而是**品类化的提示词模板 + 少量示例商品**。这是脏活，但是护城河。

**捷径**：第一版做 **「AI 商品详情页生成器 + 收款链接」**，不叫「建站平台」。它能让你 1 周内拿到第一批真实付费，并且验证「商家愿不愿意为 AI 文案付钱」这个最小假设。

### 6. 适合 OPC 初学者的机会

**更小众的切入版本（选一个）：**

- **垂直版**：只做「手作 / 手工皂 / 独立咖啡豆」的一页式 AI 店铺。放弃通用性，换取模板质量。
- **工具版**：不做店铺，只做「**AI 商品详情页生成器**」，输出可直接粘贴回 Shopify / 小红书 / Etsy 的文案。**这个版本 3 天能做完，且不承担建站责任。**
- **反向版**：不做生成，做「**竞品详情页拆解**」——输入竞品链接，输出它用了什么卖点结构。卖家更愿意为「赚钱情报」付费，而不是为「写文案」付费。

**第一批访谈对象**：在 Etsy / 小红书 / 微店上**已经开了店、月销 50-500 单、自己一个人做**的卖家。不要访谈「想开店」的人，他们不付钱。

**1 周验证实验**：
> 找 10 个这样的卖家，手工帮他们生成 3 个商品的 AI 详情页（用你的 prompt，不做产品）。问他们：**「如果每月 ¥99，你要不要？」** 记录他们犹豫的具体理由。**3 天内没收到至少 2 个「现在就付」，就换品类。**

### 5. 产品逻辑与技术路径（重点：你会遇到什么大问题）

**⚠️ 本节建立在「它确实是广告情报工具」的推测上。如果推测错了，本节作废。**

**适合初学者的 MVP 范围**：

```
用户输入 1 个竞品 Facebook 主页 URL
   ↓
抓取该主页正在投放的广告素材（文案 + 图片）
   ↓
AI 分类：这是「打折？对比？UGC？痛点直击？」
   ↓
输出一页简报：素材列表 + 分类标签 + 风格统计
```

**核心工作流**：抓取 → 去重 → 结构化 → 分类 → 展示 + 订阅提醒

**推荐技术栈**：
- 前端：Next.js + Tailwind
- 抓取：**这是最大变量**。优先找官方 API；没有就评估合规的第三方数据源；最后才考虑自建爬虫
- 后端：FastAPI（抓取任务与 API 分离）
- 数据库：Supabase（Postgres）
- 任务队列：**必需**（抓取是慢任务，不能阻塞请求）
- AI：多模态模型做素材分类（图像 + 文案一起看），用**少量自定义标签**而非自由生成
- 数据可视化：Recharts 或简单表格

**AI 用法**：**分类 + 抽取**为主。**不要用 AI 生成广告创意**——卖家不信任 AI 的创意，他们信任「别人跑过的数据」。

### 如果「我」来开发，会遇到的最大问题

**1. 数据源合法性 + 稳定性（致命级）**

这是**不是技术问题，是生存问题**。你需要回答：
- 官方 API 有吗？配额多少？字段够吗？
- 如果没有官方 API，抓取是否违反 ToS？**你的整个生意建立在别人的地基上。**
- 平台改版时，你的抓取多久能修好？**这个修复速度就是你的续费率。**

**初学者最容易犯的错**：先把产品做完，最后才去验证数据源。**应该反过来。**

**2. 反爬与规模化**

小规模抓没问题，一旦有 100 个付费用户、每人每天要更新 50 个竞品，你会立刻遇到：IP 封禁、验证码、限速、成本暴涨。**你需要代理池 + 排队 + 缓存，这些都不是初学者一周能搞定的。**

**3. AI 分类的一致性**

同一个广告，今天分类为「促销」，明天分类为「UGC」——用户会立刻失去信任。解决方案：**固定标签体系 + 少量示例 + 结构化输出（JSON schema）+ 缓存结果**，不要每次重新跑模型。

**捷径第一版**：
> **不做抓取，只做人工 + AI 混合**。用户提交竞品链接，你（或你的 AI 助手）**人工整理**一份报告，48 小时交付。定价 ¥199/份。**用 20 份订单验证需求，再决定要不要建自动化。** 这看起来「不优雅」，但能让你在**不碰任何数据源风险**的前提下拿到第一批真金白银。

### 6. 适合 OPC 初学者的机会

**更小众的版本：**

- **垂直平台版**：只做**一个平台**（比如只做 TikTok Shop 或只做 Pinterest），把这个平台的广告库做到最好用，而不是「全平台覆盖」。
- **垂直品类版**：只服务**一个品类**的卖家（如宠物用品、家居），因为同品类广告的套路高度相似，你的分类模型会更准。
- **周报订阅版**：不做工具，做**付费邮件**——每周精选 20 条跑得最好的广告 + 拆解。¥99/月。**这个版本零技术风险，1 天能上线。**

**第一批访谈对象**：月广告预算 ¥5,000-50,000 的独立站卖家 / TikTok Shop 卖家。**不要访谈广告代理商**（他们自己就有工具），不要访谈只做自然流量的卖家。

**1 周验证实验**：
> 手工整理 5 个竞品的 20 条广告，做成一份 PDF，在一个卖家社群免费发。观察：**有多少人主动私信问「能不能帮我看我的竞品」？** 超过 5 个人问，说明需求成立。

**适合初学者的 MVP 范围**：

```
用户上传 PDF
   ↓
提取文本 + 识别结构（章节标题、段落、图片位置）
   ↓
生成符合 EPUB 3 规范的 .epub 文件
   ↓
（第一版）下载
```

**技术栈**：
- 前端：Next.js + Tailwind（拖拽上传）
- 文件处理：**Python**（`PyMuPDF` / `pdfplumber` 提取，`ebooklib` 生成 EPUB）。**这类任务 Python 生态远好于 Node.js。**
- 后端：FastAPI（专门处理文件转换）
- 存储：Supabase Storage 或 S3（临时存放上传文件，**设置 24 小时自动删除**）
- 队列：**必需**（转换是 10 秒级任务，不能同步等）
- 支付：Stripe / Lemon Squeezy

**AI 用法**：**这一版其实可以不用 AI**。但如果要用，最有价值的用法是 **「章节结构识别 + 标题层级抽取」**——这恰好是规则最难处理、模型最擅长的部分。

### 如果「我」来开发，会遇到的最大问题

**1. PDF 解析的「无结构」问题（最大坑）**

PDF 本质上是**「在什么坐标画什么字符」**，它**没有段落、没有标题、没有章节**。你要从坐标、字号、字重里**反推结构**。

具体你会遇到：
- **双栏排版的 PDF**：字符流会左右跳跃，读出来是乱的
- **扫描版 PDF**：根本没有文字，只有图（需要 OCR，成本翻倍）
- **页眉页脚**：每一页都有，抽出来会变成垃圾段落
- **脚注**：位置在页面底部，但逻辑上属于正文
- **表格**：PDF 里的表格是最难还原的结构

**这不是「写个转换器」能解决的，这是一个持续打补丁的工程。**

**捷径**：**第一版只支持「单栏、文字型、无复杂表格」的 PDF**，其余返回「暂不支持」。**接受不完美，比追求 100% 覆盖率快 10 倍。**

**2. EPUB 规范的正确性**

EPUB 是一套**严格的规范**：META-INF、OPF、NCX/NAV、XHTML 内容文档、manifest、spine……生成一个**能通过 Apple Books 和 KDP 校验**的 EPUB，比生成一个「能打开的 EPUB」难得多。

验证工具：`epubcheck`（官方校验器）。**把它放进你的测试流程。**

**3. 排队与成本**

文件转换是 CPU/IO 密集型任务。100 个用户同时上传，你的服务器会挂。**必须用队列 + 独立 worker**。如果你用无服务器函数，注意**超时限制**（Vercel 默认 10-60 秒，转换大文件会超）。

### 6. 适合 OPC 初学者的机会

**这个产品的核心启示：**

> **「无聊的格式转换」是一门被严重低估的生意。它不依赖任何平台、不需要 AI、不会腐化，而且能卖出高倍数。**

**三个具体方向：**

- **AI 增强版转换**：不做通用转换，做 **「PDF → 结构化 EPUB 带 AI 章节识别」**。同样的输入，你输出的是**目录正确的电子书**，而不是一堆乱段落。可以收更高的价。
- **垂直格式版**：比如「**微信公众号文章 → EPUB**」「**Notion 导出 → EPUB**」「**PDF 论文 → 带引用格式的 EPUB**」。**越垂直，越不用处理边界情况。**
- **打包服务版**：不只转换，还帮你**生成封面 + 元数据 + 上架 KDP 的文件包**。从工具变成「服务」，客单价从 $10 到 $99。

**第一批访谈对象**：自出版作者、独立出版社编辑、**在小红书/知乎教人写书的人**。问他们「上一次转换格式崩了是什么时候」。

**1 周验证实验**：
> 做一个**只支持单栏 PDF 的转换页**，免费，但要求留下邮箱。**看 7 天有多少人上传、多少人二次上传。** 二次上传率 > 20%，说明这是一个会重复发生的需求，值得收费。

> **在动手之前，问自己一个问题：这个产品的核心输入，是「用户给我的」，还是「我从别人家页面上拿的」？**
>
> - 前者 → 你的资产会升值，因为你能休息。
> - 后者 → 你的资产会贬值，因为你必须永远跟着别人跑。

**再补充一层**：不要因为 Carry 只有 1.8x 就认为它不该做。**它的需求是真的**——$472/月对一个人来说也是钱。关键是你要**清楚地知道自己买的是什么**：
- 如果你要的是**现金流**，Carry 类工具可以在 1 周内上线并开始收钱。
- 如果你要的是**能卖掉的资产**，你必须往「不依赖别人 UI」的方向设计。

# 建造雷达

三个受今日产品启发的小产品想法。**都按「1 周能做出可收费版本」来设计。**

### 雷达 1：「AI 对话 → 结构化卡片」（Cap. 对应 Carry）

**问题**：长 AI 对话是有价值的，但导出的 Markdown 太原始，不便于复用。

**做法**：
- 输入一段对话（粘贴或上传 .md）
- AI 抽取：**结论 / 决策 / 待办 / 关键引用 / 代码片段**
- 输出：可直接导入 Notion / Obsidian 的结构化卡片，带标签

**为什么它比 Carry 抗腐化**：它的输入是**用户自己粘贴的文本**，不是爬取的网页 DOM。平台改版杀不死它。

**技术栈**：Next.js + Supabase + OpenAI（结构化输出必须用 JSON Schema） + Lemon Squeezy
**定价**：$5/月，或按次 ¥9
**1 周能不能做出来**：**能**。核心是 prompt 工程 + 一个干净的输入输出界面。

---

### 雷达 2：「竞品广告周报」（对应 AdTruffle）

**问题**：卖家想知道竞品在投什么，但不想买一个工具。

**做法**：
- 用户提交 3 个竞品链接
- 你（人工 + AI 辅助）**48 小时**交付一份 PDF 周报：竞品广告素材 + 卖点拆解 + 素材风格统计
- 订阅制：每周自动来一份

**为什么这是好起点**：**零技术风险、零数据源风险、立即能收钱**。如果 20 份卖得出去，再考虑自动化。

**技术栈**：Notion（内部管理） + GPT 辅助整理 + Stripe 收款。**第一版甚至不需要开发。**
**定价**：¥199/份，¥599/月订阅
**1 周能不能做出来**：**能，而且可能 2 天**。

---

### 雷达 3：「垂直文档 → 多格式输出」（对应 Convert2EPUB）

**问题**：通用转换工具处理不了某个垂直场景的格式细节。

**做法**（选一个垂直方向）：
- **简历** → PDF / DOCX / 网页版三格式一键输出（针对求职者）
- **论文** → 带正确引用的 EPUB（针对研究者）
- **公众号文章** → 可离线阅读的 EPUB（针对读者）

**为什么好**：**垂直 = 不需要处理所有边界情况**。你只需要把这一个场景做对，就能收钱。

**技术栈**：Next.js + FastAPI + Python 文件库 + 队列（**如果只做少量任务，可以用简单的后台任务替代 Redis**）
**定价**：¥19/次 或 ¥49/月
**1 周能不能做出来**：**勉强能**，前提是砍掉所有边缘格式。**最大的时间黑洞是「排版还原度」——第一版接受不完美。**

# 用户访谈问题

三个可以直接拿去问人的问题。**注意：不要问「你会用吗」，要问「过去发生过什么」。**

### 问题 1（验证 Carry 类需求）

> **「回想一下最近 30 天，你有没有把一段 AI 对话的内容复制到别的地方？当时你在做什么？最后它存在哪了？」**

**为什么这么问**：
- 「有没有」比「要不要」更真实。
- 「当时你在做什么」能暴露真实场景（写方案 vs 学代码 vs 记笔记，是完全不同的产品）。
- 「最后存在哪」直接告诉你**你该集成哪个工具**。如果答案是「截图发微信」，你的产品方向可能不是 Markdown。

### 问题 2（验证 Ecomz AI 类需求）

> **「你的店铺现在用什么建的？最近一次改它是为了什么？改的过程中哪一步最烦？」**

**为什么这么问**：
- 「现在用什么」判断切换成本。
- 「最近一次改是为了什么」暴露真实的高频动作（是上新？是改价？是写文案？）。
- 「哪一步最烦」直接指向 MVP 应该做的那一步。**AI 只需要解决那一步，不需要重做整个建站。**

### 问题 3（验证 AdTruffle / 情报类需求）

> **「你上一次为了搞懂竞品在干什么，具体做了什么动作？花了多久？做完之后你做了什么决定？」**

**为什么这么问**：
- 「具体做了什么动作」比「你想不想有工具」更能暴露真实工作流。
- 「花了多久」是定价的锚——如果他说花了 3 小时，你的产品值 ¥199；如果他说花了 5 分钟随手看看，就别做了。
- 「做了什么决定」是最关键的：**如果看完竞品情报后他没有改变任何行动，说明这个情报没有价值。**

**你在选题时，用这句话做最后的检验：**

> **「如果我删掉 AI 两个字，这个产品还剩下什么给客户的价值？」**

剩下的东西，才是你的生意。
