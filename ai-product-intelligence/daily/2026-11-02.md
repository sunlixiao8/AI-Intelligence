## 一、今天先学一个技能：如何从"估值页"反推商业真相

TrustMRR 每张挂牌卡片只有三个数字：**Revenue、Price、Multiple（倍数）**。大多数人只看 Revenue，但真正的信息量在**倍数**里。

我用今天的四个产品做个反推验证：

| 产品 | Revenue（月） | Price | Multiple | 反推验证 |
|---|---|---|---|---|
| Figmentor | $1.6k | $43k | 2.2x | 1,600 × 12 × 2.2 = **$42,240** ≈ $43k ✓ |
| LinkPost | $3.7k | $79k | 1.8x | 3,700 × 12 × 1.8 = **$79,920** ≈ $79k ✓ |
| Mold Identifier | $52 | $699 | 1.1x | 52 × 12 × 1.1 = **$686** ≈ $699 ✓ |
| Store Stock Checker | $24k | $135k | **0.5x** | 24,000 × 12 × 0.5 = **$144k** ≈ $135k ✓ |

**【推断，置信度中高】** 三条结论：
1. **"Revenue" 字段 = 月收入**（因为只有按月计算，倍数公式才成立）。这是有用的校准——很多读者会误以为是年收入。
2. **倍数 = 挂牌价 ÷ 年收入**。
3. 健康微型 SaaS 的成交区间约在 **2–3x 年收入**。低于 1x 是危险信号。

**所以 Store Stock Checker 的 0.5x 是什么意思？**

它月入 $24k（年化 $288k），却只卖 $135k——**不到半年收入的价钱**。市场在告诉你：**买家认为这个收入不可持续或不可转移**。常见原因：单一客户贡献大部分收入、流量来自一次性的病毒事件、收入其实是一次性买断而非订阅、或者卖家在挂羊头。

同一页还有一个更极端的：Stealth Company（E-commerce）$26k/月，挂 $48k，**0.2x**。年化 $312k 的生意卖 $48k。这不是打折，这是**清仓**。

> **给初学者的可复用动作**：以后看到任何"月入 X 美元"的故事，第一件事是去找它的年化收入与估值/融资/售价的比例。**收入的绝对值告诉你生意多大，倍数告诉你生意多健康。**

顺便做一个数据源可靠性校准：**Rezi** 在 TrustMRR 排行榜显示 $240,923 MRR，在 Indie Hackers 显示 $208,479/月（verified）。同一家公司，两个"可信"数据源相差 13.5%。**这不是有人在撒谎，而是口径不同**（是否含税、是否含一次性收入、统计窗口是 30 天还是自然月）。

**结论**：任何单一来源的收入数字，误差带至少 ±15%。本期我给出的所有收入区间，都据此放宽。

## 二、产品拆解

### 产品 1｜Store Stock Checker —— 本期收入最高，也是最好的"反常识"教材

**1. 产品**
- 名称：Store Stock Checker
- URL：https://trustmrr.com/startup/store-stock-checker
- 类别：Analytics（分析）
- 目标用户 **【推断，低置信度】**：独立站 / Shopify 店主、DTC 品牌运营、多 SKU 电商的库存负责人

> 注：摘要中该产品仅有名称、分类、收入三项信息。以下场景描述为基于"库存检查"这一功能的合理推断，**未经验证**。

**2. 用户问题**

电商最贵的错误不是"卖不出去"，是"卖得出去但没货"。

- 你花钱买流量，用户点进来，加购，发现断货 → 广告费白烧，还可能被平台降权。
- 断货导致的排名下滑，恢复需要数周。
- 库存数据分散在 ERP、平台后台、线下仓库三处，靠人工 Excel 对账，**天然滞后 3–7 天**。
- 补货决策靠"感觉"，而供应链的交期是 30–60 天。

**【推断】** 这个痛点的关键属性是：**损失可以直接换算成钱**（断货 SKU 的历史日均销量 × 断货天数 × 客单价）。这是所有 to-B 产品里最值钱的一种叙事结构——你不是在卖效率，你是在卖"避免损失"。

**3. 商业信号**

- 定价模式：**【未知】**，未访问定价页。按品类惯例推测为月订阅 + 按 SKU 数/店铺数分层。
- **月收入估算：$20,000–$26,000/月**
  - **置信度：中**
  - 证据：TrustMRR 挂牌页展示 Revenue $24k，挂牌价 $135k，倍数 0.5x（https://trustmrr.com/startup/store-stock-checker）。收入数字未经独立核实，且 Rezi 的跨源差异提示 ±15% 误差带。
- 增长/牵引力证据：**【未知】**。无评论数、无安装量、无融资信息。
- **危险信号（重要）**：0.5x 倍数。在微型 SaaS 交易市场，这是"卖家急于脱手"的定价。

**4. 为什么可能赚钱**

| 维度 | 判断 |
|---|---|
| 使用频率 | 高。库存是每天变化的，仪表盘会被每天打开 |
| 紧迫程度 | 高。断货是"钱在流血"，不是"以后再说" |
| 预算负责人 | 店主本人或电商运营主管。**决策链极短，一个人就能签字** |
| 切换成本 | 中高。一旦接入了店铺数据并配置了告警规则，迁移成本不低 |
| **但是** | 0.5x 倍数说明**有人在用脚投票说这门生意不好卖**。可能的解释：收入高度集中在少数客户、或者它本质是"一次性部署费"而非订阅 |

**这正是今天最值钱的一课**：一个产品可以有漂亮的收入数字，同时是一个糟糕的生意。你要学会同时看这两件事。

**5. 产品逻辑与技术路径**

**MVP 范围（4 周内可做）**
```
CSV / Shopify 授权 → 拉取 SKU + 库存 + 近 90 天销量
  → 计算：日均销量、库存天数、预计断货日
  → 判定：断货风险 = (库存天数 < 供应商交期 + 安全库存)
  → 输出：每日一封邮件「这 7 个 SKU 会在 21 天内断货，预计损失 $X」
```

**核心工作流**：数据接入 → 指标计算 → 风险分级 → 告警投递 → 损失归因报表

**需要的数据/输入**：SKU 清单、当前库存、历史销量（至少 60 天）、供应商交期、客单价

**推荐技术栈**：Next.js + Supabase（存 SKU 与销量快照）+ Shopify Admin API / CSV 上传 + Inngest 或 Vercel Cron 做每日任务 + Resend 发邮件

**AI 模型用法**：**这一步几乎不需要 AI。** 核心是移动平均和阈值判断。LLM 只在一个地方有意义：把"SKU-A 将在 18 天后断货"翻译成一段像人写的补货建议，附带上周销量异常的解释。**这是一个非常好的教学点——今天收入最高的产品，AI 含量最低。**

**如果我来开发，会遇到的最大难点**

1. **数据质量会杀死第一版。** 店主的库存数字经常是错的（线下刚出了一批货没录系统）。你的告警如果误报两次，用户就会把你关掉。解决方法：第一版必须让用户能一键标记"这个是对的/错的"，并且**只在置信度足够高时才发告警**——宁可漏报，不可误报。
2. **Shopify API 的现实约束。** 大店铺有几十万 variant，普通 REST 接口拉不动，必须用 Bulk Operations（异步 GraphQL），一次要跑几分钟到几十分钟。这个异步任务编排，对没做过后台任务队列的初学者是硬墙。
3. **预测不准 → 信任崩塌。** 千万别上"AI 预测模型"。你的数据量根本不够。**用最简单的规则，并且把规则明明白白写在界面上**（"因为你的交期是 45 天，我建议你保持在 60 天库存"）。可解释的笨规则，胜过高准确率的黑箱。

**捷径**：第一版**完全不做 Shopify 集成**。做一个"上传 CSV → 生成断货风险报告"的网页。用户每周上传一次，你每周给他一份 PDF。这能让你在 1 周内验证需求，而且**顺便告诉你他会不会为这份报告付钱**。

**6. 适合 OPC 初学者的机会**

- **更小的切入口**：只服务"SKU 数 20–200 的小店"。大厂（Inventory Planner 等）做全量 ERP 对接，你只做"7 天内会断货的 Top 10 SKU"，用邮件推送，不做仪表盘。
- **第一批该访谈的人**：在 Shopify 社区 / r/shopify / 小红书"独立站"话题下，找那些发帖抱怨过断货的店主。找 5 个。
- **1 周验证实验**：手工为 3 个店主做一份"断货风险清单"（你人肉算），免费给他们。看他们会不会追问"下周还有吗"。如果会 → 做成自动的。

### 产品 2｜LinkPost —— AI 内容分发，最典型的"看起来简单、做起来要命"

**1. 产品**
- 名称：LinkPost
- URL：https://trustmrr.com/startup/linkpost
- 类别：AI（摘要中分类为 Artificial Intelligence）
- 目标用户 **【推断，低置信度】**：内容创作者、个人 IP、社媒运营、增长负责人

> 注：摘要仅显示 "LinkPost, Artificial Intelligence, Revenue $3.7k, Price $79k"。以下为基于名称的推断：**Link + Post = 把一个链接/长内容，转化成多平台可发布的内容**。可能是"一稿多发"或"链接转社交文案"。

**2. 用户问题**

**【推断】** 如果你写一篇 2000 字文章，想让它在 X、LinkedIn、邮件通讯、小红书、公众号都出现，你实际要做的是：

| 平台 | 你要做的事 | 耗时 |
|---|---|---|
| X | 拆成 6–8 条推文的 thread，每条 ≤280 字符 | 20 min |
| LinkedIn | 改成 200 字、专业语气、开头三行必须抓人 | 15 min |
| 邮件通讯 | 加一个引子，加 CTA | 10 min |
| 小红书 | 改成口语化、加 emoji、加 5 个 tag | 15 min |
| 公众号 | 排版、加头图 | 20 min |

**单篇 80 分钟，每周 2 篇 = 每周 2.7 小时。** 这个痛点的高频性质是：**它每周都在发生，而且永远不会消失**。

**3. 商业信号**

- 定价模式：**【未知】**
- **月收入估算：$3,300–$4,200/月**
  - **置信度：中**
  - 证据：TrustMRR 挂牌页 Revenue $3.7k，Price $79k，Multiple 1.8x（https://trustmrr.com/startup/linkpost）
- 牵引力：**【未知】**
- **健康度解读**：1.8x 是偏低但不算危险的区间。说明买家认为它有真实价值，但对增长没信心。

**4. 为什么可能赚钱**

- **使用频率**：极高。这是"每次发内容都要用"的工具，是工作流的一部分，不是偶发需求。
- **紧迫程度**：中。不发也不会死，但会一直焦虑。
- **预算负责人**：个人创作者自己，或小团队的 growth lead。决策快。
- **切换成本**：**低** —— 这是它最大的商业弱点。用户随时能换。所以这类产品必须靠"平台接入数量"和"模板库"建立护城河，但这两个都容易被抄。
- **赛道参照（重要）**：TrustMRR 排行榜上，社交排程工具 **Postiz 做到 $351,828 MRR**，Indie Hackers 显示 $377,411/月。这说明**这个赛道的天花板非常高**——但也意味着你面对的是一个已经有成熟玩家的红海。**你必须切一个他们不做的细分。**

**5. 产品逻辑与技术路径**

**MVP 范围（3 周）**
```
输入一个 URL
  → 抓取正文（Readability / Jina Reader）
  → 抽取：核心论点 3 个、金句 5 句、数据点
  → 并行生成 4 个平台版本（不同 prompt、不同长度、不同语气）
  → 输出到一个编辑面板，每个版本可微调
  → 一键复制（v1 不做自动发布）
```

**技术栈**：Next.js + Supabase（存内容与历史）+ OpenAI / Claude（结构化输出用 JSON mode）+ Vercel AI SDK（流式输出体验）+ Stripe

**AI 模型用法**：主要是**生成 + 风格迁移**。进阶一点可以做 RAG——把你过去 50 篇高互动内容存进 pgvector，生成时检索 3 篇作为 few-shot 示例，让输出更像"你写的"。这是唯一能让用户觉得"离不开"的技术点。

**如果我来开发，会遇到的最大难点**

**难点一（真正的墙）：平台发布 API。**

这是 90% 的初学者会低估的地方。真实情况大致是：

| 平台 | 能否自动发布 | 现实 |
|---|---|---|
| X | 能，但 API 按量收费且限流严格 | 免费额度对小团队基本不够 |
| LinkedIn | 要申请开发者权限，审核周期长 | 个人账号发布权限收紧 |
| 小红书 / 抖音 | **几乎无官方发布 API** | 只能做浏览器自动化，脆弱 + 违反 ToS |
| 公众号 | 有接口但需要认证服务号 | 个人订阅号走不通 |
| 邮件 | 最容易，Resend/Postmark 直接搞定 | 无阻力 |

**【推断，中置信度】** 如果 LinkPost 的核心卖点是"自动发布"，它大概率只覆盖了 API 开放的那几个平台，或者用浏览器自动化打了擦边球——**后者意味着随时可能被封，也意味着它的收入随时可能断崖**。这可能正是它只卖 1.8x 倍数的原因之一。

**难点二：内容抓取。** 很多站点有反爬（Cloudflare、付费墙）。你会花 30% 的时间在这上面。

**捷径（强烈建议）**：**v1 完全不做自动发布。** 只做"生成 + 一键复制 + 稍后提醒"。把最难的 20% 砍掉，你能提前 2 个月上线。等有 50 个付费用户愿意为"自动发"多付 $10/月，再去做那 20%。

**6. 适合 OPC 初学者的机会**

- **切入口**：不做"全平台"。做 **"长文 → LinkedIn + 邮件通讯" 两件套**。这两个平台 API 最友好、用户最有钱、内容最需要"专业感"。或者反过来做 **"播客/视频 → 文字稿 → 5 条推文"**，切的是"有内容但没时间写"的人群。
- **第一批该访谈的人**：在 X 上找粉丝 1k–20k、每周发 3 篇以上、且内容跨平台的创作者。找 10 个，看他们现在的手工流程。
- **1 周验证实验**：你手动帮 3 个创作者把他们的一篇文章改成 4 个平台版本，用你自己的 ChatGPT 做。交付后问："如果这东西每周自动出现，你愿意付多少？"——**不要问"你会不会付"，要问"付多少"。**

### 产品 3｜Figmentor —— 设计工具，学"如何把主观判断变成客观规则"

**1. 产品**
- 名称：Figmentor
- URL：https://trustmrr.com/startup/figmentor
- 类别：Design Tools（设计工具）
- 目标用户 **【推断，低置信度】**：独立设计师、设计学习者、小型设计团队。名称 "Fig" + "mentor" 暗示与 Figma 生态相关，且带有"指导/教练"属性。

**2. 用户问题**

**【推断】** 设计这件事最痛的不是"不会画"，是**"画完了没人告诉你哪里不对"**。

- 初级设计师 / 独立开发者 / 非设计背景的创始人，做出来的界面"感觉怪但说不清哪里怪"。
- 找资深设计师评审，一次几百到几千元，还要排队。
- 设计社群发帖求反馈，回复率低，且质量参差。
- 结果：**能力提升的反馈环断了。** 这直接卡住职业发展和接单能力。

**为什么付费**：这是一个"职业能力"问题。设计师愿意为"能接到更好的单"付费，这比"省时间"的付费意愿更强。但它的天花板也低——**因为"变好"是渐进的，用户很难感知到 ROI**。

**3. 商业信号**

- 定价模式：**【未知】**
- **月收入估算：$1,400–$1,800/月**（年化约 $17k–$22k）
  - **置信度：中**
  - 证据：TrustMRR 挂牌页 Revenue $1.6k，Price $43k，Multiple 2.2x（https://trustmrr.com/startup/figmentor）
- **健康度解读**：2.2x 是本期最健康的倍数，落在正常区间。说明市场认为这是一个**真实、可持续、虽小但干净的生意**。
- 牵引力：**【未知】**

**4. 为什么可能赚钱**

| 维度 | 判断 |
|---|---|
| 使用频率 | 中。做一个项目用一次，不是每天 |
| 紧迫程度 | 低-中。"变强"是长期需求，不是今天必须解决 |
| 预算负责人 | 设计师个人（自掏腰包），或小团队 lead |
| 分发优势 | **这是关键**：如果它是 Figma 插件，就天然拥有 Figma Community 的搜索流量。这是零成本的获客渠道 |
| 弱点 | $1.6k/月很可能说明它卡在"有用但非必需"的位置——用户用完就走，不续订 |

**5. 产品逻辑与技术路径**

**MVP 范围（2–3 周，如果是 Figma 插件）**
```
用户选中一个 Frame
  → 插件读取设计属性（不读像素，读结构化数据）
  → 规则引擎检查客观项：
     · 间距是否落在 4/8pt 网格
     · 文字对比度是否 ≥ 4.5:1（WCAG AA）
     · 字号阶梯是否 ≤ 5 级
     · 颜色数量是否 ≤ 8
     · 触控目标是否 ≥ 44×44
  → 输出打分 + 逐条问题清单
  → LLM 把问题清单转成"人话建议"
```

**技术栈**：Figma Plugin API（TypeScript）+ 插件 UI（React）+ 后端 Next.js（存规则集与用户配置）+ OpenAI（只用在"把规则翻译成人话"）

**AI 模型用法**：**这里的 AI 含量应该刻意压低**。对比度、间距、字号阶梯都是**确定性计算**，用 AI 做只会引入错误。LLM 唯一该做的是"解释"——把 `contrast ratio 3.1:1` 翻译成"这个灰色按钮上的白字，在户外光线下会看不清"。

**如果我来开发，会遇到的最大难点**

1. **Figma 插件的沙盒限制会把初学者卡住。** 插件运行在一个受限的 iframe 里，**不能直接发网络请求**。你必须通过 `figma.ui.postMessage` 把数据传到 UI，UI 再 fetch 后端，后端返回后再 postMessage 回插件主线程。这个"主线程 ↔ UI 线程"的双向通信，第一次做的人平均要卡 2–3 天。
2. **"好设计"是主观的，这是产品设计上最致命的陷阱。** 如果你让 AI 说"这个布局不好看"，用户会觉得 AI 在胡说，然后卸载。**唯一能赚钱的做法是：只评判客观项，绝不评判审美。** 这是一个"克制"的产品决策，不是技术决策。
3. **Figma Community 的审核与分发**：插件上架要过审，且 Community 的推荐算法不由你控制。
4. Figma 官方自己也在不断加 AI 功能（自动布局建议、设计系统检查），**平台风险是真实存在的**。

**捷径**：**先不做插件，做一个网页版**——用户上传截图 → 你用视觉模型 + 规则给出报告。这能让你在 3 天内验证"有没有人想要这个报告"，成本几乎为零。验证通过后再花 2 周做插件。

**6. 适合 OPC 初学者的机会**

- **更小的切入口**：不做"通用设计评审"，做 **"无障碍（a11y）合规检查"**。这是纯客观的、有法律驱动的（欧美 ADA / EAA 合规）、有明确付费方的（企业必须合规），而且**不需要 AI 判断审美**。这是从"主观产品"转向"客观产品"的经典切法。
- **第一批该访谈的人**：Figma Community 上发布过免费检查类插件的作者（看他们的 install 数和评论）、以及在小红书/B站教设计的博主。
- **1 周验证实验**：手工评审 5 个公开的 Dribbble 作品，写成"客观问题清单"，发到设计社群。看有没有人问"你能看看我的吗"。

### 产品 4｜Mold Identifier —— 最小的收入，最好的一课

**1. 产品**
- 名称：Mold Identifier
- URL：https://trustmrr.com/startup/mold-identifier
- 类别：Artificial Intelligence
- 目标用户 **【推断，低置信度】**：普通房主 / 租客。遇到墙面黑斑，不确定是霉菌还是污渍。

**2. 用户问题**

**【推断】** 浴室墙角出现一片黑斑。你的第一反应是搜"墙上黑色斑点是什么"。

真实决策链：
1. 这是霉吗？有毒吗？对孩子/宠物有影响吗？（**健康焦虑**）
2. 要不要花钱请专业检测？（美国市场 $200–$600）
3. 还是自己买瓶除霉剂就行？（$10）

**这是一个典型的高焦虑 + 高信息不对称 + 有明确付费替代品（专业检测）的场景。** 这三个属性叠加，是消费级 AI 应用最好的土壤。

**3. 商业信号**

- 定价模式：**【未知】**。推测为 App 内单次解锁或低价订阅。
- **月收入估算：$40–$70/月**
  - **置信度：中**
  - 证据：TrustMRR 挂牌页 Revenue $52，Price $699，Multiple 1.1x（https://trustmrr.com/startup/mold-identifier）
- **健康度解读**：$52/月 = 可能只有 10–20 个付费用户。这不是一门生意，这是一个**验证阶段的实验**。而 1.1x 的倍数说明卖家自己也这么认为——几乎是以"成本价 + 一点点"在转手。

**4. 为什么可能赚钱（以及为什么这个产品没赚到钱）**

这是今天最有教学价值的一个。它同时展示了**正确的方向和错误的商业模式**：

✅ **方向是对的**：
- 痛点真实且带焦虑（健康）
- 有明确的付费替代品（$200+ 专业检测）
- 拍照即用的交互，门槛极低
- 目标人群巨大（每个有房子的家庭）

❌ **模式是错的**：
- **这是一次性需求。** 你一生中大概只会识别 1–2 次霉菌。**一次性需求不能做订阅。** $52/月的收入几乎可以肯定在说明：用户装一次、用一次、卸载。
- 这个品类（植物识别、蘑菇识别、石头识别、虫子识别）在 App Store 有大量同类，说明**技术模板可复用**，但也说明**竞争激烈、留存极差**。
- **信任成本高**：用户凭什么相信一个 App 说"没事"？

> **今日最重要的商业洞察之一**：判断一个产品该不该做订阅，先问"用户一个月会用几次"。答案 <1 的，做一次性付费 + 导流分成，不要做订阅。Mold Identifier 的 $52/月就是这个错误的直接代价。

**5. 产品逻辑与技术路径**

**MVP 范围（1 周，这是本期最容易复刻的）**
```
拍照 / 上传图片
  → 视觉模型分类：霉菌 / 霉斑 / 水渍 / 污垢 / 返碱（efflorescence）
  → 输出：可能性排序（不是唯一答案）+ 判断依据（颜色、纹理、位置）
  → 输出：下一步该做什么（自己处理 / 找专业人 / 立即撤离）
  → 免责声明：非医疗/环境检测建议
```

**技术栈**：Next.js + Supabase Storage（存图）+ OpenAI Vision 或 Gemini Flash（成本极低，单张图 <$0.01）+ Stripe 单次解锁 $2.99

**AI 模型用法**：**纯视觉分类 + 生成**。用 few-shot 给模型 5–10 张标注图（霉菌/水渍/返碱各 2–3 张），让它输出结构化的 JSON：`{likely: "mold", confidence: 0.72, reasoning: "...", next_steps: [...]}`。

**如果我来开发，会遇到的最大难点**

1. **责任风险是不对称的。** 你判错了"这个没毒"，用户在婴儿房里住了三个月。这个风险不是技术问题，是**产品形态问题**。解法：**永远输出概率区间 + 永远建议"如不确定请找专业评估"**，并且引用 CDC / EPA 的公开指导，而不是自己编。这一条如果做不好，你会惹上不该惹的麻烦。
2. **模型在"相似物"上会翻车。** 霉菌、水渍、返碱（墙面白色粉末）、烟熏痕迹，在低质量手机照片里极其相似。**你必须诚实地输出"我不确定"**——这恰恰是大多数 AI 产品不敢做的事。
3. **留存为零。** 你会花 80% 的精力去获客，然后看着每个用户只用一次。
4. **App Store 审核**：健康相关的声明会被额外审查。

**捷径 / 更聪明的商业模式**：**别卖订阅。卖线索。**

免费识别 → 如果判定为"需要专业处理" → 把用户导流给本地除霉服务商 / 空气检测公司 / 除湿机电商，**按线索或成交抽成**。你的识别工具是获客漏斗，不是利润中心。这样一次性需求的弱点就变成了优势（你不需要他们回来）。

**6. 适合 OPC 初学者的机会**

- **把单点做成矩阵**：`家装问题识别器` —— 霉菌 / 墙面返碱 / 地板虫蛀 / 瓷砖空鼓 / 电路老化（别做石棉，法律风险过高）。同一个技术架构，5 个入口，5 组 SEO 关键词。
- **第一批该访谈的人**：Reddit 的 r/HomeImprovement、r/Mold 里发过照片求鉴定的用户（他们的原帖就是最好的需求证明）。
- **1 周验证实验**：爬 50 个 r/Mold 的"帮我看看这是什么"帖子，你手动用 GPT-4V 跑一遍，把结果发回帖子。看有多少人回复"谢谢"、多少人问"你是怎么判断的"。**这就是零成本的需求验证。**

## 五、今日模式（一个可复用的商业洞察）

> **"需求频率 × 损失可量化程度"决定了你能不能收订阅费。**
>
> - 高频 + 损失可量化（库存断货）：**月订阅，价格可以很高，客户天天回来**
> - 高频 + 损失不可量化（内容分发）：**月订阅，但价格被压，且随时被替代**
> - 低频 + 损失可量化（霉菌识别）：**单次付费 + 导流分成，绝不做订阅**
> - 低频 + 损失不可量化（设计评审）：**按次付费或买断，天花板低**
>
> **把这两个轴画出来，你 90% 的"该不该做订阅"的问题就自动有答案了。**

配套的一个读数据习惯：

> **收入的绝对值告诉你生意多大，交易倍数告诉你生意多健康。** 看到任何"月入 X"的故事，先算 `年化收入` 和 `估值/售价倍数`，再看它落在哪个区间。0.5x 是清仓，2–3x 是正常，你看不到 5x 以上的微型 SaaS，因为那意味着市场认为它极稳——而极稳的小生意通常不卖。

## 六、建造雷达（受今日启发的 3 个小产品）

**雷达 1｜"断货预感器"（最推荐，因为需求最硬）**

- 做什么：给小电商店主（20–200 SKU）每日一封邮件，只讲一件事——"这 7 个 SKU 在 21 天内会断货，按历史销量估算你将损失 $X"。
- 为什么能成：损失用钱计价，预算负责人是店主本人，决策链 1 人。
- 最小验证：不做集成。让店主上传昨天的库存 CSV，你人肉跑脚本，24 小时内回一份报告。**先卖 3 份再写代码。**
- 定价假设：$19/月（需验证）。
- 核心技术风险：数据质量差 → 误报 → 被关掉。第一版宁可漏报。

**雷达 2｜"两平台一稿多发"（切最窄的 AI 内容工具）**

- 做什么：只做「长文 URL → LinkedIn 帖子 + 邮件通讯草稿」。**不碰 X、不碰小红书、不碰自动发布。**
- 为什么能成：API 最友好的两个平台，用户最有钱，且这两个平台的内容都需要"专业感"（正好是 LLM 的强项）。
- 最小验证：手动帮 3 个创作者做一次，问"如果每周自动出现，你付多少"。
- 差异化点：用 pgvector 存用户过去的高互动内容做 few-shot，让输出"像他写的"。这是唯一难抄的部分。
- 定价假设：$12/月（需验证）。

**雷达 3｜"客观设计合规检查"（反直觉，但护城河最深）**

- 做什么：Figma 插件 / 网页截图上传 → 只检查**客观项**：对比度（WCAG）、间距网格、字号阶梯、触控尺寸、色板数量。**绝不评判审美。**
- 为什么能成：客观问题可以量化、可复现、有法律驱动（欧美无障碍合规），且**不依赖 AI 判断**，所以不会显得"AI 味重"。
- 最小验证：做一个网页版，用户上传截图，你返回一份带分数的 PDF。3 天能做完。
- 定价假设：免费版看 3 项，付费版看全部 + 导出报告，$9/月或 $29 买断。

## 七、用户访谈问题（可以直接复制去问）

这三题的设计原则是：**问过去的行为和金额，不问未来的意愿。** 因为人对"你会付钱吗"的回答毫无预测力，但对"你上次花了多少"的回答相当准确。

**问题 1（验证痛点 + 量化损失）**
> "上一次你因为库存/缺货而丢掉订单，是什么时候？大概丢了多少钱？当时你是怎么发现的？"

追问：`是别人告诉你的，还是你自己查出来的？`（这一个追问能告诉你，你的产品该不该做告警推送）

**问题 2（验证工作流，看而不听）**
> "你现在把一篇新文章发到所有平台，具体步骤是什么？能打开电脑演示一遍吗？"

追问：`哪一步最烦？这一步你每次花多久？` —— **不要说"如果有个工具能……你会用吗"，让他演示，你自己数时间。**

**问题 3（验证现有替代方案与付费历史）**
> "在做这件事上，你过去 12 个月花过钱吗？花在什么上？多少钱？为什么最后没继续用（或继续用了）？"

追问：`如果明天那个工具消失了，你会怎么办？` —— 这个问题能测出真实的依赖度，比任何 NPS 分数都准。

**备选（针对消费级识别类产品）**
> "你上次发现墙上有黑斑时，第一反应是搜什么？后来你花钱了吗？花了多少？还是自己处理了？"

1. **收入的绝对值告诉你生意多大，交易倍数告诉你生意多健康。** $24k/月 卖 $135k（0.5x），比 $1.6k/月 卖 $43k（2.2x）更值得警惕。
2. **需求频率决定收费模式。** 一生只用 1 次的工具，做订阅就是自杀（Mold Identifier 的 $52/月）。高频 + 损失可量化，才是订阅的沃土（Store Stock Checker）。
3. **收入最高的产品，AI 含量最低。** 不要为了用 AI 而用 AI。今天四个产品里，$24k/月的那个几乎不用 LLM。
