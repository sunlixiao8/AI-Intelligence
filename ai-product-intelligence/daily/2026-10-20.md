# 产品一：Carry —— 给"AI 重度用户"当搬运工

**来源**：[TrustMRR · Carry](https://trustmrr.com/startup/carry)（🟡 平台披露）
**类别**：Utilities
**一句话定位**：自动把 ChatGPT / Claude / Grok 的对话保存成 Markdown

### 1. 产品与用户

- **名称 / URL**：Carry（官网地址未在摘要中出现，需核实）
- **类别**：浏览器工具 / 数据导出
- **目标用户**：把 AI 当生产力工具的重度用户 —— 写作者、开发者、研究员、做知识管理（Obsidian / Notion / Logseq）的人

### 2. 用户问题

这是一个**"AI 时代的新摩擦"**，而且非常具体：

你用 ChatGPT 聊了 40 轮，终于把方案想清楚了。然后呢？

- 网页刷新/对话丢失 → 内容没了
- 想存进 Obsidian → 手动全选复制，代码块格式全乱，公式变成乱码
- 想跨平台对比 Claude 和 GPT 的答案 → 两个标签页来回翻
- 想搜索三个月前的某个结论 → 平台内搜索基本不可用

**为什么愿意付费而不只是好奇**：这不是"想试试"的需求，是**每周甚至每天都会痛一次的摩擦**。而且痛的人恰好是"已经在为 AI 付费"的人群——他们已经证明了有付费习惯，$5/月对他们来说是零决策成本。

> ⚠️ **置信度提示**：产品实际功能、定价、是否真的是浏览器扩展，摘要中**没有直接证据**。以上是基于产品名 "Carry: Save ChatGPT, Claude & Grok to Markdown Automatically" 和 Utilities 类别的推断（🔴 推测）。需去 Chrome Web Store 核实。

### 3. 商业信号

- **定价模式**：未知（推测为订阅或一次性买断，$3–$10/月 或 $19–$49 买断区间）
- **月收入**：**$354/月**（🟡 平台披露，置信度：中）
- **挂牌价**：$10,000，倍数 2.4x
- **增长证据**：未知。摘要中无评论数、安装量、发布记录

**这个数字怎么读**：
$354/月 ≈ 年收入 $4,248，卖 $10,000。也就是说市场对这个产品的定价是"**2.4 年回本**"。对比 gtm.help 的 5.6x、Salah Lock 的 7.5x，Carry 的倍数偏低——通常意味着买家认为**它的收入不够稳定，或者维护成本偏高**（这正是下面技术部分要讲的）。

### 4. 为什么可能赚钱（也为什么可能不赚）

**支撑它的因素：**

- **使用频率极高**：知识工作者每天用 AI，每次用都可能需要归档
- **切换成本会累积**：一旦你的历史对话都躺在 Obsidian 里，你就不想换工具了
- **分发渠道自带流量**：Chrome Web Store 搜索 "ChatGPT export"、"save chatgpt" 这类词有稳定长尾需求，不需要投广告
- **决策人 = 使用者**：无需说服老板，个人直接刷卡

**压制它的因素（必须看清）：**

- **客单价极低**：$354/月，如果定价 $5/月，只有约 70 个付费用户
- **平台风险 100% 外部化**：OpenAI 明天加一个"原生导出"按钮，产品价值腰斩
- **维护成本刚性**：三家平台前端改版，你就得改三次
- **天花板明确**：这个品类很难做到 $10k MRR，因为它是"功能"不是"系统"

**这就是本期最重要的商业课**：$354/月 的真实含义不是"这个生意能做"，而是"**这个生意的维护成本必须压到 $100/月以下才划算**"。

### 5. 产品逻辑与技术路径

**核心工作流**：
```
用户打开某个 AI 对话 → 点击扩展按钮
  → 抓取当前会话的消息数组（角色、内容、时间戳）
  → 序列化为 Markdown（代码块 / 表格 / LaTeX / 图片链接）
  → 输出到：下载 .md / Obsidian 本地库 / Notion API
```

**适合初学者的 MVP 范围（1 周）**：
- 只支持 1 个平台（选 ChatGPT，用户基数最大）
- 只支持 1 个导出目标（下载 .md 文件）
- 只处理文本 + 代码块，**放弃图片和表格**

**推荐技术栈**：

| 层 | 选择 | 理由 |
|---|---|---|
| 扩展 | Chrome MV3 + TypeScript | 必须，别用跨浏览器框架给自己加负担 |
| HTML→MD | Turndown | 成熟库，省掉 80% 序列化工作 |
| 前端 UI | 扩展 popup 纯 HTML/CSS | 不需要 Next.js，杀鸡用牛刀 |
| 云同步（可选） | Supabase | 需要账号体系时再上 |
| 支付 | Lemon Squeezy | 面向全球个人开发者，比 Stripe 少一层税务麻烦 |

**AI 模型用法**：这里 AI 只是**配角**——可选做一个"自动生成对话标题 + 打标签 + 提取待办事项"的后处理。真正的主体是 DOM 解析，不要本末倒置。

### 🔥 如果我来开发，会遇到的最大问题

**问题一：上游改版是永久的、不可预测的运维税**

这是这类产品的**结构性诅咒**。ChatGPT / Claude 的前端平均每 2–6 周就有一次结构调整，你的 CSS 选择器或 API 拦截逻辑随时会碎。你卖的是 $5/月的订阅，但用户期望的是"永远能用"。**一次改版没跟上，你会在一周内收到 20 封退款邮件。**

→ 缓解：优先拦截**网络响应**而不是解析 DOM（数据结构比 DOM 稳定得多）；写自动化冒烟测试，每天定时跑一遍，发现失效立刻告警。

**问题二：多模态内容的保真度是深坑**

代码块还好，但一旦涉及：LaTeX 公式、表格、Artifact / Canvas 组件、图片、（未来的）语音，序列化复杂度会指数上升。用户对"格式丢失"的容忍度极低——他们花 $5/月就是为了格式不丢。

→ 捷径：**明确宣布不支持什么**。MVP 阶段的产品页直接写"暂不支持图片和 Artifact"，比做到 80% 然后被差评强。

**问题三：隐私与 ToS**

用户把完整对话导给你，而对话里可能有公司机密、个人信息。如果你把数据传到自己服务器，会直接撞上信任墙。

→ 捷径：**本地优先（local-first）**。所有解析在浏览器内完成，不经过你的服务器。这既是技术方案，也是最好的营销文案。

**更简单的第一版（甚至不需要扩展）**：
做一个**网页版"剪贴板清洗器"**——用户手动全选复制对话内容，粘贴进你的网页，你输出干净的 Markdown。零扩展权限、零上架审核、零 DOM 维护，**一天就能上线**。付费点放在"批量处理 + 云同步 + 模板"。

### 6. 适合 OPC 初学者的机会

- **更小众的版本**：
  - 专做**中文 AI 平台**（豆包 / Kimi / 通义 / DeepSeek）的对话归档 —— 英文工具基本不做这块，而中文用户的知识管理需求一样强
  - 专做**垂直场景**：把 AI 对话自动整理成"客户会议纪要"或"代码评审记录"
  - 做"**AI 对话全文搜索**"：本地建立索引，跨平台搜历史对话
- **第一批访谈对象**：Obsidian / Notion 中文社区的重度用户、独立开发者、做内容的人
- **1 周验证实验**：写一个 Greasyfork 油猴脚本（免费），发到 V2EX 和 Obsidian 中文论坛，标题「一键把 ChatGPT 对话存成 Obsidian 笔记」。**只看两个数**：3 天内安装量 > 200？有没有人在评论里问"能不能支持 Claude"？——有人主动要求扩展平台，就是付费信号

# 产品二：Skinmaxx —— AI + 护肤的垂直切口

**来源**：[TrustMRR · Skinmaxx](https://trustmrr.com/startup/skinmaxx)（🟡 平台披露）
**类别**：Artificial Intelligence
**一句话定位**：推测为 AI 驱动的护肤方案/产品推荐工具

> ⚠️ **证据强度：低**。摘要中只有"Skinmaxx / Artificial Intelligence / Revenue $578 / Price $17k"三个事实。以下产品形态为基于名称（"skin" + "maxx" 的 self-improvement 命名法）和 AI 类别的**推断**（🔴），必须去官网核实后才可采信。

### 1. 产品与用户

- **类别**：消费级 AI / 美妆护肤
- **目标用户**：有护肤困扰但不懂成分的普通消费者（尤其 18–35 岁女性），以及被"成分党"内容教育过、想要个性化答案的人

### 2. 用户问题

护肤是一个**高频、高焦虑、高信息不对称**的消费场景：

- "我这套流程到底对不对？"
- "博主推荐的 A 醇，我能和我正在用的水杨酸一起用吗？"
- "我到底是油皮还是混油？为什么网上说的都不一样？"
- 每年在护肤上花几千块，但**没有一个工具能告诉我"你不需要买这个"**

**为什么愿意付费**：护肤决策的成本很高——买错一瓶就是几百块 + 烂脸风险。一个 $10/月的工具如果能避免一次错误购买，ROI 立刻为正。而且这个品类的用户**习惯为"指导"付费**（咨询、课程、社群）。

### 3. 商业信号

- **定价模式**：未知（推测为订阅 $5–$15/月 或一次性报告 $9–$29）
- **月收入**：**$578/月**（🟡 平台披露，置信度：中低——无法核实）
- **挂牌价**：$17,000，倍数 2.4x
- **增长证据**：未知。无评论数、下载量、社交粉丝数

**怎么读这个数字**：$578/月，倍数 2.4x——和 Carry 一样属于"低价快出"档。这个收入体量对应的大概是 50–150 个付费用户，说明**产品验证了需求，但没找到规模化获客方式**。这是消费级 AI 产品的典型卡点（下一节会讲）。

### 4. 为什么可能赚钱

**支撑因素：**

- **需求频次高**：护肤是每日行为，不是一次性咨询
- **用户价格敏感度低于决策焦虑**：花几百块买错产品的痛，远大于 $10/月的订阅费
- **内容天然适合传播**：成分科普、方案对比，小红书/TikTok 天然适配
- **数据可累积**：用户录入的护肤台越多，推荐越准，切换成本越高

**压制因素（对个人创业者尤其致命）：**

- **获客成本（CAC）极高**：美妆类广告 CPM 是全网最贵的品类之一，个人创业者**打不起广告**
- **信任门槛**：用户凭什么相信一个 AI 的护肤建议？没有皮肤科医生背书，转化率会很低
- **合规风险**：一旦措辞越界到"诊断/治疗"，在美国 FDA、中国化妆品监督管理条例下都是雷区
- **错误成本高**：推荐错组合导致烂脸 → 差评 + 潜在法律风险

### 5. 产品逻辑与技术路径

**核心工作流（建议的 MVP 形态）**：
```
用户录入在用的产品（搜索品牌 / 扫条形码 / 手输成分）
  → 系统解析 INCI 成分表
  → 规则引擎检查成分冲突（如 视黄醇 × 果酸 / 过氧化苯甲酰 × 维A酸）
  → LLM 把冲突结果翻译成"人话"（为什么不能一起用、怎么错开用）
  → 生成早晚流程表，可保存、可分享
```

**推荐技术栈**：

| 层 | 选择 |
|---|---|
| 前端 | Next.js + Tailwind |
| 后端/认证/DB | Supabase |
| AI | OpenAI API（只用于"解释"和"生成流程"，**不用于判断冲突**） |
| 检索 | Supabase pgvector（成分/产品语义检索） |
| 支付 | Stripe / Lemon Squeezy |

**AI 模型用法**：**检索增强生成（RAG）** —— 核心是把成分规则库作为检索源，LLM 只负责把检索到的规则组织成人话。**绝对不要**让 LLM 自由发挥护肤建议。

**需要的数据**：
1. 成分冲突规则表（人工整理 100–300 条，这是你真正的资产）
2. 产品 SKU 库（可用开放数据如 Open Beauty Facts 起步，再靠用户 UGC 补充）
3. 成分功效解释文本（可由 LLM 生成后人工审核）

### 🔥 如果我来开发，会遇到的最大问题

**问题一：数据冷启动是真正的护城河，也是真正的深渊**

做这个产品，80% 的工作量不是 AI，是**建立一个准确的产品成分数据库**。用户搜"兰蔻小黑瓶"，你得能返回正确的成分表。靠手动录入 10 万 SKU 是不可能的；靠条形码 API，覆盖率和国内品牌支持度都是问题。

→ 捷径：**别做全品类**。只做"成分冲突检查器"这一个功能，用户**手动输入成分名**（而不是搜产品）。这砍掉了 90% 的数据工作，保留了 100% 的核心价值。

**问题二：合规措辞的边界极难把握**

"你的皮肤屏障受损，建议停用酸类" —— 这句话已经非常接近医疗建议了。在欧盟和美国，"cosmetic claims" 有严格清单；在国内，化妆品不得宣称医疗作用。一旦越界，你可能收到平台下架通知或监管函。

→ 捷径：产品里**永久固定**免责声明，措辞只用"成分搭配建议"而非"诊断"；**别做图像皮肤检测**——那会把产品从"化妆品"推向"医疗器械"，是个人开发者绝对不该碰的领域。

**问题三：视觉模型在消费级照片上根本不可靠**

如果你本能地想"上传自拍 → AI 判断肤质"，请立刻打住。手机前置摄像头 + 各异的光线 + 无标定的色卡 = 判断结果基本等于随机。用户拍两次得到两种结论，信任瞬间归零。

→ 捷径：**结构化问卷 >> 图像判断**。问 8 个问题（洗脸后 30 分钟的出油情况、季节变化、既往过敏史），比一张照片准得多，而且零合规风险。

### 6. 适合 OPC 初学者的机会

- **更小众的版本**：
  - **孕期/哺乳期安全护肤检查器**（人群极明确，焦虑度极高，现有工具几乎没有）
  - **敏感肌专用**成分冲突检查（排除所有高刺激成分）
  - **男士护肤极简方案**（3 步以内，反"成分党"路线）
- **第一批访谈对象**：小红书护肤话题下的提问者、皮肤科门诊候诊人群（脱敏访谈）、成分党社群
- **1 周验证实验**：做一个纯静态网页「成分冲突速查表」，输入两个成分名输出能不能一起用。发小红书笔记 + 知乎回答"XX 和 XX 能一起用吗"这类长尾问题。**看 7 天内自然搜索来的 UV 和评论区追问**——如果有人在评论里问"那我的整套流程呢"，说明单点工具 → 个性化方案的转化路径成立

# 产品三：thecontentcook —— $2.2k/月的"内容 + 订阅"老派生意

**来源**：[TrustMRR · thecontentcook](https://trustmrr.com/startup/thecontentcook)（🟡 平台披露）
**类别**：Health & Fitness
**一句话定位**：推测为健康/健身领域的内容型订阅产品

> ⚠️ **证据强度：低**。摘要中只有类别和收入。产品究竟是内容站、食谱订阅、健身计划课程还是 SaaS，**完全未知**。下面我按"最可能的形态"（内容 + 订阅）做拆解，重点是**商业模式的可迁移性**，而不是这个产品本身。

### 1. 产品与用户

- **类别**：健康健身（非 AI）
- **推测用户**：想改善饮食/健身但缺乏系统方法的人
- **推测形态**：内容库（食谱/训练计划）+ 定期更新 + 邮件/社群 + 订阅费

### 2. 用户问题

健康健身领域的核心痛点不是"不知道要运动"，而是**"知道但做不到"**：

- 收藏了 200 个健身视频，一个没练
- 看了无数食谱，到饭点还是点外卖
- 需要的是**"这周吃什么、今天练什么"的现成答案**，而不是更多信息

**为什么愿意付费**：付费买的不是信息（信息免费），而是**减少决策 + 承诺机制**。订阅制让用户产生"我花了钱所以要执行"的心理约束。

### 3. 商业信号

- **定价模式**：未知（推测为 $10–$30/月订阅，或年费）
- **月收入**：**$2.2k/月**（🟡 平台披露，置信度：中低）
- **挂牌价**：$80,000，倍数 3.0x
- **增长证据**：未知

**怎么读这个数字**：这是本期**收入最高**的产品，$2.2k/月 ≈ 年收入 $26.4k。倍数 3.0x 属于中位。相比 Carry 的 $354，它说明一件事：**内容型订阅的单价和留存天花板，远高于工具型小产品**。健康健身用户习惯按月付费，而且内容可以持续产出、不需要应对上游改版。

**但也要看清对面**：$2.2k/月 卖 $80k，等于创始人认为"继续做下去不如一次性套现"。这个体量在内容行业通常意味着**增长已经停滞**——SEO 位次稳定了，新用户进不来了。

### 4. 为什么可能赚钱

**支撑因素：**

- **订阅制 + 内容复利**：一篇好内容能带来 3 年的自然流量，边际成本趋零
- **用户不看广告**：健康类用户对"被推销"极度反感，但对"被指导"愿意付费
- **AI 时代反而是利好**：内容泛滥让"有人味的、可信的策展"更值钱

**压制因素：**

- **增长极慢**：SEO 从 0 到有流量要 6–12 个月，这对个人创业者是现金流灾难
- **YMYL 惩罚**：健康类内容被 Google 归为 "Your Money or Your Life"，对作者权威性（E-E-A-T）要求极高，AI 批量生成的站几乎必被降权
- **内容永动机压力**：订阅用户期待持续更新，你必须一直产出

### 5. 产品逻辑与技术路径（如果做成 AI 增强版）

**核心工作流**：
```
内容库（食谱/计划）→ 用户偏好问卷（目标/忌口/时长/器材）
  → 生成个性化每周计划 → 邮件/App 推送 → 用户打卡 → 下周调整
```

**推荐技术栈**：

| 层 | 选择 |
|---|---|
| 站点 | Next.js + MDX（内容用文件管理，别急着上 CMS） |
| 邮件/订阅 | Beehiiv / ConvertKit（比自建强 10 倍） |
| 支付 | Stripe（订阅）或 Lemon Squeezy |
| AI | OpenAI API（用于个性化替换、营养估算） |
| 数据 | Supabase（用户偏好 + 打卡记录） |

**AI 模型用法**：
1. **结构化抽取**：把食谱统一成 Schema.org Recipe 格式（利于 SEO）
2. **个性化改写**："把这份 4 人份食谱改成 1 人份、去掉乳制品"
3. **生成 SEO 长尾内容**，但**必须人工审核 + 真人署名**
4. **营养估算**（注意：只能给区间，不能给精确值）

### 🔥 如果我来开发，会遇到的最大问题

**问题一：AI 生成内容在这个品类是"负资产"**

这是最容易踩的坑。你会本能地想：用 GPT 批量生成 500 篇"XX 食物的热量"，快速铺 SEO。结果是：Google 的 helpful content 系统 + YMYL 判定，会让你**连索引都进不去**。而健康类内容恰恰是 YMYL 最严格的领域。

→ 捷径：**反着做**。内容量少而深，每篇都有真人（哪怕是你自己，但要有可验证的身份）背书，标注信息来源和更新日期。10 篇精品 > 500 篇 AI 水文。

**问题二：个人化的健康建议 = 医疗建议**

"你每天应该摄入 120g 蛋白质" —— 对肾病患者可能是危险的。任何针对个体健康状况的建议都可能构成医疗行为。

→ 捷径：只做**"基于公开指南的通用计划"**（如基于 WHO / 中国居民膳食指南），不做个体化医学建议；人群定得越窄越好（如"健身增肌人群"而非"所有想健康的人"），并在入口处明确排除患病人群。

**问题三：内容是资产，但现金流是负债**

这个生意的本质是"**先投入 6–12 个月无收入的内容生产，再收获**"。对需要尽快验证的个人创业者，这是最危险的模式。

→ 捷径：**别从大站做起**。从"一个细分人群的每周餐单邮件"做起——邮件列表是唯一你不受算法影响的资产。100 个愿意付 $9/月的订阅者 = $900/月，已经超过本期 thecontentcook 收入的一半。

### 6. 适合 OPC 初学者的机会

- **更小众的版本**：
  - **特定人群的周餐单订阅**：增肌人群 / 孕期 / 糖尿病前期（注意合规边界）/ 单人食
  - **"一周 5 顿 20 分钟晚餐"** —— 极窄的承诺，比"健康饮食"好卖 100 倍
- **第一批访谈对象**：健身房里认真训练但不请私教的人；小红书"减脂餐"话题的收藏者（收藏了但没做过的人 = 最大的痛点人群）
- **1 周验证实验**：写 5 篇"一周晚餐计划"的样板内容，做一个落地页，**只收邮件不收钱**。挂到 2 个社群，看 7 天能收多少邮箱。**低于 50 个 = 需求不成立；超过 150 个 = 可以开始做付费版**

# 产品四：gtm.help —— $1.1k/月、5.6 倍溢价的 B2B 信号

**来源**：[TrustMRR · gtm.help](https://trustmrr.com/startup/gtm-help)（🟡 平台披露）
**类别**：Marketing
**一句话定位**：Go-To-Market 相关的服务或工具

> ⚠️ **证据强度：极低**。除名称、类别、$1.1k 月收入、$75k 挂牌价外，**摘要中无任何信息**。域名 gtm.help 暗示是 GTM（go-to-market）领域，可能是外呼工具、线索服务、咨询落地页或内容站。以下为**推断**（🔴），必须核实。

### 1. 为什么仍然值得分析

即便信息极少，它有两个信号值得注意：

1. **倍数 5.6x —— 本期最高**（Salah Lock 的 7.5x 除外，那是 $138 的微型项目）。买家愿意为它付 5.6 年收入，说明市场认为**它的收入可持续性强**。在 B2B 营销领域，这通常意味着"订阅 + 客户留存高"。
2. **B2B 的预算逻辑**，和个人消费产品完全不同——这是初学者最容易忽略的一课。

### 2. 用户问题

GTM（go-to-market）人群的痛点是**结构性的、每天重复的**：

- SDR / 销售：每天要找 50 个潜在客户，写 50 封不重复的开场白
- 创始人：想知道"谁最近在招这个岗位 / 谁刚融了钱 / 谁换了技术栈"——这些是购买信号
- 但这些信息散落在招聘网站、新闻、LinkedIn、G2 里，**手动拼装每天要 2 小时**

**为什么愿意付费**：这是**直接的收入杠杆**。一个 SDR 月薪 $4k，如果工具能让他多约到 2 个会，$100/月的工具费是零决策。**B2B 工具的价格锚定的是"人力成本"，不是"竞品价格"**。

### 3. 商业信号

- **定价模式**：未知（B2B SaaS 常见 $99–$499/月，或按线索量计费）
- **月收入**：**$1.1k/月**（🟡 平台披露，置信度：低）
- **挂牌价**：$75,000，倍数 5.6x
- **增长证据**：未知

**怎么读这个数字**：$1.1k/月，如果是 $200/月的定价，只有 5–6 个客户。**B2B 产品的特征是"客户数极少但单价极高"** —— 5 个客户就能撑起一个副业，这是个人创业者最应该关注的模型。

### 4. 为什么可能赚钱

- **预算负责人明确**：不是"用户觉得好用"，是"老板批预算"
- **ROI 可计算**：多约一个会议 = 多少钱，可以算给对方听
- **切换成本高**：工具一旦嵌入销售流程（CRM 集成、团队共享），换掉很麻烦
- **个人创业者可以做**：第一批客户只需要 5–10 个，靠创始人直销完全够

**压制因素**：
- **销售周期长**：B2B 从接触到成交通常 1–3 个月
- **数据合规**：抓取 LinkedIn 等平台有明确的 ToS 和法律风险（hiQ vs LinkedIn 案之后，美国仍不稳定；欧盟 GDPR 更严）
- **冷启动靠人肉**：头 5 个客户几乎一定是创始人一家家谈来的

### 5. 产品逻辑与技术路径

**建议的 MVP 形态（窄到极致）**：
```
用户定义 ICP（行业 + 规模 + 技术栈）
  → 系统从公开来源聚合"购买信号"（新招聘 JD、融资新闻、高管变动）
  → LLM 生成"为什么现在联系他"的理由 + 个性化开场白
  → 输出 CSV / 推送到 CRM
```

**推荐技术栈**：
- 前端：Next.js
- 后端/DB：Supabase
- 数据源：**优先用第三方 API**（Apollo、Clay、PredictLeads），而不是自己爬
- AI：OpenAI API（生成个性化开场白）
- 定时任务：Supabase Cron / GitHub Actions

**AI 模型用法**：主要用**生成 + 抽取**——从非结构化文本（新闻、JD）里抽取结构化信号，再生成话术。不需要复杂 agent。

### 🔥 如果我来开发，会遇到的最大问题

**问题一：数据获取是法律和成本的双重雷区**

你会本能地想"爬 LinkedIn"。这条路会同时撞上：ToS 违约、IP 封禁、GDPR/个人信息保护法的合规问题。而用第三方 API，成本可能直接吃掉你全部毛利（Apollo 企业版动辄 $500+/月）。

→ 捷径：
1. **用公开、低风险的数据源**：招聘网站（公开 JD）、公司官网、新闻、GitHub、应用商店更新日志
2. **人工 + AI 混合**：不做全自动。每周人工筛 30 个信号，AI 帮你写话术。**这反而是更好的产品**——客户买的是"高质量的 30 个"，不是"垃圾的 3000 个"

**问题二：冷邮件的送达率和合规**

你生成的再好，进垃圾箱就是 0。冷邮件需要域名预热、SPF/DKIM/DMARC 配置、退订机制、发信量控制。这是一整套运营知识，不是写代码能解决的。而且各国反垃圾邮件法（CAN-SPAM、GDPR）对 B2B 冷邮件有明确约束。

→ 捷径：**别做"发送"，只做"准备"**。产品只输出"目标名单 + 个性化话术 + 联系理由"，发送交给客户自己的邮箱工具。这砍掉了 80% 的运维和合规负担。

**问题三：幻觉会直接毁掉客户品牌**

AI 生成的"我注意到贵司最近在扩张"——如果对方根本没扩张，这封信会瞬间损害客户关系。B2B 场景对错误**零容忍**。

→ 捷径：**每一条信号都必须附原始来源链接**，让用户能一键核实。产品设计的核心不是"生成得多好"，而是"可验证"。

### 6. 适合 OPC 初学者的机会

- **更小众的版本**：
  - **中文 B2B 信号周报**：只服务一个垂直行业（如跨境电商服务商 / SaaS 出海），每周 10 个目标客户 + 联系理由，$99/月，人工 + AI
  - **Chrome 扩展版**：不采集数据，只在用户打开某个公司页面时，帮 TA 生成开场白（零合规风险）
  - **"跟进邮件"生成器**：不碰首封，只做第 2、3、4 封跟进——这是销售最讨厌也最容易忘的部分
- **第一批访谈对象**：3–10 人规模的 B2B SaaS 销售、独立顾问、出海服务商
- **1 周验证实验**：手动（Excel + ChatGPT）帮 3 个销售朋友做一周的信号名单，**免费**。观察：他们会真的用吗？会回复客户吗？一周后问一句"如果我收 $99/月继续做，你付吗？"——**口头说好不算，让对方预付一个月才算**

## 今日模式

### 模式：**"$354/月 的产品在教你算维护成本的账"**

今天 4 个产品，月收入分别是 $354 / $578 / $1.1k / $2.2k。如果只看收入，结论是"这些都很小，不值得做"。但把**挂牌倍数**和**产品形态**放在一起看，得到一个更有用的框架：

| 产品 | 月收入 | 倍数 | 隐含判断 |
|---|---|---|---|
| Carry | $354 | 2.4x | 买家认为**维护成本高、平台依赖强** |
| Skinmaxx | $578 | 2.4x | 同上，且**获客成本高** |
| thecontentcook | $2.2k | 3.0x | 内容资产，**但增长停滞** |
| gtm.help | $1.1k | **5.6x** | **B2B 客户留存 + 预算稳定** |

**可复用的三条洞察：**

**① 收入规模不重要，"维护成本 / 收入"的比值才决定生死。**
Carry 每月收 $354，但每次上游改版都要动代码。如果你的维护成本是 $200/月的时间价值，净利润只剩 $154——这不是生意，是兼职。**选产品时先问：这个产品每月需要我主动维护几次？**

**② B2B 的估值溢价来自"客户不会因为一次故障就走"。**
gtm.help 的 5.6x 倍数是本期最高。B2B 客户迁移成本高、决策慢但留存久，所以买家愿意付 5.6 年收入。而消费级工具（Carry、Skinmaxx）用户随时可以取消，买家只肯付 2.4 年。**同样的收入，B2B 值 2 倍价。**

**③ 卖"准备"比卖"执行"更安全。**
今天表现最好的两个技术切口，共同点是**都不碰执行环节**：Carry 只导出不托管，gtm.help（建议版）只准备名单不发送。执行环节 = 上游依赖 + 法律风险 + 运维负担。**砍掉执行，你就砍掉了 80% 的麻烦。**

## 用户访谈问题（3 个，可直接用）

> 访谈原则：**只问过去的行为，不问未来的意愿**。"你会用吗"永远得到假的"会"。

**Q1（针对 Carry 类归档工具）**
> "你上一次想把一整段 AI 对话留下来，是什么时候？当时你具体是怎么保存的？保存完之后，你后来真的再翻出来用过吗？"

*追问点*：如果对方说"我就截了个图"，说明真实需求强度低于你的假设。如果对方说"我复制到 Notion 了但格式全乱"，这是最贵的痛点。

**Q2（针对 Skinmaxx 类护肤工具）**
> "你现在同时在用几支护肤品？最近一次你拿不准'这两个能不能一起用'是什么时候？当时你是怎么判断的——问人、搜小红书、还是直接试？"

*追问点*：如果对方的答案是"直接试"，说明这个决策没有任何可信工具支撑，机会真实存在。如果答案是"我问了我做医美的朋友"，说明信任需要一个**人**来背书，纯 AI 方案会遇到转化墙。

**Q3（针对 gtm.help 类 B2B 工具）**
> "这周你为了找客户，手动做了哪些事？大概花了多少小时？最后发出了几封？其中有几封收到了回复？"

*追问点*：把"花了多少小时"和"回复数"两个数字记下来。如果对方算出来是"每天 2 小时，一周 10 封，0 回复"——这就是付费意愿最强的人，因为他的痛苦有明确的数字。这时候再问："如果有个东西每周给你 10 个已经筛过的人，收 $99/月，你会先试一周吗？"
