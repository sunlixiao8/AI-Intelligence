# 每日 AI 产品商业情报

**日期：2026-07-31**
**读者：刚开始学习 AI 产品开发的个人创业者**
**阅读时长：约 20 分钟**

本期候选池来自 TrustMRR、Toolify、There's An AI For That 等公开来源。我选择了 4 个产品，覆盖三种典型打法：**消费者订阅 + AI 生成（Rezi）、B2B 数据分析 + AI 对话（Cometly）、AI 原生产品（Articos）、垂直电商/SaaS 小生意（Hairdoo）**。所有收入数据都标注了来源，请勿把推测当作事实。

## 一、Rezi —— AI 简历生成器

### 产品

- **名称**：Rezi
- **URL**：https://rezi.ai （线索来自 TrustMRR Leaderboard：https://trustmrr.com/）
- **类别**：AI 内容生成 / 求职工具
- **目标用户**：全球求职者、应届生、职业转型者，以及需要批量处理简历的个人与企业客户

### 用户问题

求职者最痛苦的不是“写不出简历”，而是**面对每个职位都要重新调整简历**。很多人会投 50-100 家公司，但只准备 1 份简历，结果被 ATS（招聘者常用的简历筛选系统）和招聘官快速丢弃。

Rezi 解决的是：**把简历变成可批量定制、贴合职位描述的“投递机器”**。它的卖点是“AI 根据职位描述重写你的经历”，其企业版甚至可以直接投递给公司。这不是一次性好奇需求，而是每次找工作都会反复出现的痛苦。

### 商业信号

- **定价模式**：Freemium + 付费订阅。TrustMRR 页面显示 Rezi 不只做个人用户，还有 Enterprise 产品，服务超过 300 家组织。
- **月收入估算**：`约 $259,516 / 月（MRR）`
- **置信度**：`高`
- **证据**：TrustMRR Leaderboard 2026-07-31 数据，由创始人 Jacob Jacquet 报告。该数字是自我报告，但它是公开可信平台上最直接的收入信号。换算年化约 `$310 万 / 年`。
- **用户/热度线索**：官方声称每年约 100 万新用户，企业版进入 300+ 组织，包括 1 家世界 500 强和多所大学。这是很强的需求验证。

### 为什么可能赚钱

- **使用频率**：不找工作时不打开，但一但开始投简历，频率极高（每天多次修改）。
- **紧迫程度**：高。错过投递窗口就等于错过机会。
- **预算负责人**：个人求职者为自己的职业付费意愿强；企业 HR/职业学院有“批量优化简历”的预算。
- **切换成本**：用户一旦在工具里保存了多个版本的简历、投递记录和推荐信，就难以迁移。这类工具本质是“越用越了解你”的数据产品。

### 产品逻辑与技术路径

**MVP 范围（初学者版本）**：

- 输入：用户粘贴自己的简历文本 + 粘贴目标职位描述（JD）。
- 输出：一份重新生成、突出关键词的简历。
- 流程：拆解 JD → 提取用户简历中的匹配经历 → 按 JD 重写 bullets → 生成 PDF。

**推荐技术栈**：

- 前端：Next.js + Tailwind CSS
- 后端：Next.js API Routes
- 数据库/认证：Supabase
- 支付：Stripe / Lemon Squeezy
- AI：OpenAI API（GPT-4o 及以上）
- PDF 生成：react-pdf 或浏览器打印方案

**AI 模型用法**：

- 信息抽取：从旧简历中识别工作经历、技能、教育。
- 生成：根据 JD 重写经历描述，控制关键词出现频率。
- 分类：判断候选人经历与职位的匹配度分数。

**如果“我”来开发，会遇到的最大难点**：

1. **PDF/Word 输出质量**：AI 生成内容很容易，但简历格式错位会很廉价。真实用户对“导出格式是否完美”极其敏感，这也是很多简历工具的核心护城河。
2. **LLM 输出不稳定的时长控制**：生成的经历描述最容易出现“过度夸大”，用户一旦觉得“这不是我”，立刻流失。
3. **旧简历解析**：用户上传的文件可能是各种格式，且版式混乱。解析 PDF 时一行错位，后续内容全部错误。

**可以降低难度的捷径**：

- 第一版不要追求“上传 PDF 自动解析”。让用户填表单，或者先只支持“复制粘贴文本”。
- 第一版不做完整 PDF 渲染，只输出 HTML 简历，用户放在浏览器直接打印。
- 针对细分人群做模板：只做“技术岗位”“护士”或“教师”一个行业模板，减少通用性难度。

### 适合 OPC 初学者的机会

- **更小众的版本**：
  - 中文市场 / 日韩市场的“外语简历优化”工具（这些市场对语法和表达有真实付费意愿）。
  - 特定职业赛道，例如“护理 / 医疗简历生成器”。
- **第一批该访谈的客户群体**：应届毕业生、求职训练营学员、职业顾问。
- **1 周验证实验**：在 Product Hunt 或小红书/知乎发一篇“我做了个 AI 简历工具，免费帮 50 个人修改简历”。观察是否有陌生人主动使用、是否有人追问付费价格。

## 二、Cometly —— AI 营销归因与分析平台

### 产品

- **名称**：Cometly
- **URL**：https://cometly.com （线索来自 TrustMRR Leaderboard：【https://trustmrr.com】）
- **类别**：B2B SaaS / 营销分析
- **目标用户**：SaaS 公司的创始人、增长负责人、投放经理

### 用户问题

几乎所有投放广告的公司都有一个老大难问题：**不知道到底是哪条广告带来了成交**。Meta、Google、TikTok 等渠道各自报数，Shopify/Stripe 等收款又自成一套，老板问“我的 $100 广告费到底赚了多少”，没人能准确回答。

Cometly 的做法是：把点击、线索、成交这些事件串起来，形成归因数据，然后让用户**用自然语言直接问 AI**：“上个月 Google Ads 的 ROI 是多少？”“哪个 campaign 带来的 Demo 最多？”它的产品口号概括为“面向 SaaS 公司的营销归因，用 AI 聊天你的广告数据”。

### 商业信号

- **定价模式**：订阅制，通常按月收入或事件量收费（具体定价未知，SEO 首页未报告）。
- **月收入估算**：`约 $208,992 / 月（MRR）`
- **置信度**：`高（创始人自我报告）`
- **证据**：TrustMRR Leaderboard 2026-07-31 数据，创始人 Grant Cooper 报告。年化约 `$250 万 / 年`。这个收入在 B2B 数据工具中很典型——它不是靠炒作赚钱，而是靠解决“算账”问题。

### 为什么可能赚钱

- **使用频率**：投放团队每天都要看数据，属于高频使用。
- **紧迫程度**：极高。广告费烧掉但不知道回报，是老板每天都会焦虑的问题。
- **预算负责人**：公司有明确预算；归因工具属于直接算 ROI 的“成本中心”。
- **切换成本**：归因工具一旦接入广告账户、CRM 和支付数据，数据管道会很深，更换极麻烦。这是护城河。

### 产品逻辑与技术路径

**核心工作流**：

1. 用户连接广告平台（Meta/Google/TikTok）和转化数据（Stripe/Shopify/CRM）。
2. Cometly 把点击与成交进行“归因匹配”。
3. AI 生成洞察：总结花费、收入、ROI、最佳 Channel。

**MVP 范围（初学者版本）**：

- 不需要做“全自动归因”。只做一个**简化版落地页 + 一个追踪链接 + 一个收入数据表**。
- 用户把 Cometly 生成的追踪链接放在广告里，成交时回传一个金额，报表显示每一笔成交来自哪个渠道。
- 再加入一个“AI 总结”：把数据表丢给 LLM，自动生成“这个月 Google Ads 支出 $2k，带来 $5k，ROI 2.5x”的文本报告。

**推荐技术栈**：

- 前端：Next.js + React
- 后端：FastAPI
- 数据库：Supabase / PostgreSQL
- 定时任务：GitHub Actions 或 Vercel Cron
- AI：OpenAI API，关键是做好的 prompt 抽象

**AI 模型用法**：

- 结构化分析：LLM 读取 CSV/JSON 数据，生成结论。
- 建议生成：告诉用户“你应该砍掉哪个 Ad set”。
- 注意：**此处 AI 不需要太聪明，甚至可以用预设 SQL 规则完成大部分工作**。AI 只是把结果翻译成人话。

**如果“我”来开发，会遇到的最大难点**：

1. **数据接入**：接入 Meta/Google 广告 API 有权限审核、token 过期、字段变化等问题，非常坑。
2. **归因准确性**：很多用户没有 enable cookie，或者用户跨设备点击；归因模型需要大量经验。
3. **B2B 销售**：这类产品买家很少，开发者往往做出来之后找不到客户，获客难度远大于产品难度。

**可以降低难度的捷径**：

- 第一版**不要接广告平台 API**，只接 Webhook + UTMA 参数。
- 第一版只服务 Shopify 卖家：Shopify 订单数据是现成的，广告点击用短链接标记，做一个 Shopify App 就能上架。
- 第一版把“AI 报告”做成每周自动发送的邮件，避开复杂 dashboard 开发。

### 适合 OPC 初学者的机会

- **更小众的版本**：
  - 面向自由职业者的“单页归因报表”工具。
  - 面向小红书/TikTok 博主达人的“品牌合作报价分析助手”。
  - 给做 App 的小团队用的“买量 ROI 计算器”。
- **第一批该访谈的客户群体**：独立开发者 / 小电商主，问他们“我看不到哪条广告赚钱，现在是怎么应对的”。
- **1 周验证实验**：用 Airtable 做一个表单，手动收集 10-20 个广告账户的花费和收入，然后生成 PDF 报告发给他们，问“你愿意为每月自动生成这个报告付多少钱”。

## 三、Articos —— 用 AI 模拟用户访谈的研究平台

### 产品

- **名称**：Articos
- **URL**：来源为 Toolify 收录页：https://www.toolify.ai/zh/（搜索 “Articos”）
- **类别**：AI 原生 SaaS / 用户研究 / 产品验证
- **目标用户**：创始人、产品经理、设计师、代理公司

### 用户问题

独立开发者和创业公司最常见的失败原因是：**在投入几周甚至几个月写代码之前，没有验证用户是否愿意付费**。传统用户研究太慢：招募用户要一周，安排访谈要三天，整理录音要两天。最后发现方向错了，时间全浪费了。

Articos 的方案是：用 AI 模拟目标用户，由 AI 主持人进行访谈。你设定一个用户画像，它扮演真实的用户回答你的问题。它能告诉你“用户理解了什么、困惑什么、愿意为什么付费、阻碍使用的原因”。

**注意**：本产品的收入数据我无法确认。它来自 Toolify 的最新介绍页，看起来更接近“新发布产品”，尚未有公开 MRR 数据。下面我会明确区分已知与未知。

### 商业信号

- **定价模式**：未知。官网未公开（以 Toolify 页面信息为准）。
- **月收入估算**：`未知`
- **置信度**：`N/A（没有证据）`
- **增长线索**：被 Toolify 收录并给了详细描述，说明产品完成度较高、有面向早期用户的推广预算。但没有用户数量、评论数或公开收入。
- **为什么仍值得研究**：它的产品假设非常值得学习——**AI 模拟用户能在产品开发早期代替真实访谈**。这个假设是否成立是另一回事，但它是 AI 原生工作流的典型案例。

### 为什么可能赚钱

- **使用频率**：在项目早期每周几次，属于“项目制”工具，不是每天高频使用。
- **紧迫程度**：中高。创始人想避免“白干三个月”，愿意花小钱验证。
- **预算负责人**：初期是创始人自己；后期可以卖给设计机构和创新咨询公司。
- **切换成本**：低。用户用完即走，如果它不能替代真实访谈，留存会很差。这是它最大的风险。

### 产品逻辑与技术路径

**MVP 范围（初学者版本）**：

- 一个表单：用户输入“我想访谈谁、背景是什么、我想问什么问题”。
- 一个后端：调用 LLM，让它扮演该用户画像，并对每个问题给出可能的一线回答。
- 输出：一个“模拟访谈记录” + AI 生成的关键结论。

**推荐技术栈**：

- 前端：Next.js + Tailwind
- 后端：Next.js API Routes
- 数据库：Supabase
- AI：OpenAI API 或 Claude API
- 额外：用 WebSocket 做流式输出，提升访谈沉浸感

**AI 模型用法**：

- 角色扮演（System Prompt）：设定用户画像、行业、预算、痛点。
- 对话管理：让模型记住之前的回答，并生成追问问题。
- 文本总结：访谈结束后生成一份“用户反馈摘要”。

**如果“我”来开发，会遇到的最大难点**：

1. **防止 AI 说“假话”**：AI 扮演用户时会莫名其妙地变得礼貌和“合理”，它不会像真实用户那样表达混乱、矛盾或强烈的情绪。这导致访谈结果失真。
2. **用户画像建模能力**：没有任何前置数据库时，模型只能凭想象回答。更有效的做法是让它基于一个真实用户调研报告来扮演，但这需要大量输入数据。
3. **销售非常难**：客户会怀疑“AI 访谈真的有用吗？” 如果你无法提供令人信服的数据，它可能变成一次性工具。

**可以降低难度的捷径**：

- 第一个版本不做“模拟访谈”，先做“**访谈记录 + AI 分析**”：用户上传真实访谈录音转文字稿，AI 提取模式。这比模拟访谈更真实、更容易建立信任。
- 模拟访谈只聚焦特定场景，比如：只做“Shopify 店主对 AI 客服的购买意愿”这类窄场景，在细分领域内获得可信度。

### 适合 OPC 初学者的机会

- **更小众的版本**：
  - “价格测试模拟器”：让 AI 扮演用户，测试不同价格对购买意愿的影响。
  - “落地页反馈机器人”：用户粘贴自己的落地页文字，AI 扮演目标用户，指出没有看懂的地方。
- **第一批该访谈的客户群体**：正在做新项目调研的独立开发者、产品经理。
- **1 周验证实验**：手动调用 ChatGPT 模拟 10 个目标用户访谈，然后把它做成一份 PDF 报告给别人看，问“你觉得这个结果能用来做决策吗？”如果他们说“可以”，再开发工具。

## 四、Hairdoo —— 垂直电商/订阅小生意（非 AI，但值得学）

### 产品

- **名称**：Hairdoo
- **URL**：https://trustmrr.com/startup/hairdoo
- **类别**：电商 / 垂直消费品
- **目标用户**：美发相关消费者（具体是假发、美发工具还是订阅盒，TrustMRR 页面未详细说明，需进一步确认）

### 用户问题

美发/假发/护理品类是一个高复购、高毛利、用户决策极度依赖“信任”的市场。如果 Hairdoo 是一个“美发订阅 + 导购”模式，那它解决的问题就是：**用户不知道什么样的美发产品适合自己，需要持续的推荐和补货提醒**。

由于公开资料不足，我无法完全确认它的具体业务内容。这里我只把它当作“值得学习的垂直电商 SaaS 小生意”来分析。

### 商业信号

- **定价模式**：未知，应该是电商零售价或订阅盒。
- **月收入估算**：TrustMRR 售出列表显示 `$8k / 月收入`，售价 `$200k`，倍数 2.1x。
- **置信度**：`低` —— TrustMRR 是可靠平台，但我们不清楚这里的 “$8k” 是“最近 30 天收入”还是“标准月收入”，也未看到具体的订单量和利润。
- **证据**：https://trustmrr.com/startup/hairdoo
- **增长线索**：它被挂到 TrustMRR 上出售，本身就是一种信号：这门生意已经有了稳定现金流，否则没人愿意花 $200k 购买。同时 2.1x 的倍率在电商里不算高，说明买家更看重利润，而不是增长率。

### 为什么可能赚钱

- **使用频率**：美发/假发这类产品，用户会定期补货或换新；叠加订阅模式后留存率高。
- **紧迫程度**：中等。不是救命刚需，但涉及“外貌焦虑”，用户在决策上愿意付费。
- **预算负责人**：个人消费者，复购由习惯驱动。
- **切换成本**：订阅型产品一旦形成习惯，切换很难；但对新品牌来说，冷启动很难是最大问题。

### 产品逻辑与技术路径

**如果做类似产品，并且加入 AI 能力**，MVP 可以这样设计：

- 目标：做一个“AI 发型/产品推荐助手”，挂在 Shopify 店铺上。
- 用户拍一张照片或选择 3-5 个偏好标签（发质、脸型、想要的感觉）。
- AI 推荐产品组合。
- 用户下单订阅，每月自动补货。

**推荐技术栈**：

- Shopify App（Node.js）
- Next.js 做配置页
- OpenAI Vision（图像识别 + 分类）
- Stripe / Shopify Subscription API 做订阅

**AI 模型用法**：

- 视觉分类：识别用户发型、发色、发质。
- 推荐生成：根据规则和偏好做组合推荐。
- 对话式导购：用户咨询“我适合染什么颜色”时自动回复。

**如果“我”来开发，会遇到的最大难点**：

1. **供应链和履约**：电商最难的不是建站，而是“有货、能发、亏不亏”。个人开发者一个人做技术毫无问题，但供应链会让你死得很快。
2. **信任冷启动**：谁来买一个没有评价的新美发品牌？通常需要网红/KOC 分销或内容营销。
3. **退货与售后**：美发类产品一旦拆封，很难二次销售，退货率对利润影响极大。

**可以降低难度的捷径**：

- 不要自己做品牌和库存，直接做 **“AI 导购 + 联盟电商”**：你负责推荐，用户去 Amazon 购买，你拿佣金。这样没有任何库存压力。
- 先把一个素材做成 TikTok/Instagram 爆款，测试需求，再上架。

### 适合 OPC 初学者的机会

- **更小众的版本**：做“针对女性脱发人群的护理产品推荐引擎”，或者“帮美发师做 AI 个人名片/预约工具”。
- **第一批该访谈的客户群体**：美发店主、假发经销商、经常购买美发产品的消费者。
- **1 周验证实验**：在 Reddit/小红书发帖：“我开发了一个 AI 发型推荐工具，免费帮你分析适合发型”，看有多少人私信你。如果有 20 人以上来找你，再继续做。

## 今日模式

> **“AI 不是产品，而是转化增强器。”**

注意观察今日四个例子：Rezi 卖的是“更快获得面试”，Cometly 卖的是“广告钱没有白花”，Articos 卖的是“早点发现会失败”，Hairdoo 卖的是“我对自己的外貌更自信”。它们都不是“因为用了 AI 所以付费”，而是“因为解决了实际问题所以付费”。

AI 真正改变的是**交付成本**和**可定制能力**：一个人现在可以做过去需要一个团队才能做出来的服务。对个人创业者来说，最大的机会不是做通用 AI 平台，而是：

1. 找到一个固定的小群用户。
2. 观察到他们反复做某件痛苦的事。
3. 用 AI 把那个流程自动化。
4. 收他们原本就愿意付的钱。

## 建造雷达

受到今日产品启发，3 个适合独立开发者的最小产品想法：

1. **面试模拟器**：面向非英语母语的程序员，AI 模拟英文面试官，根据用户的简历提问，然后生成表现报告。对标 Rezi，但更聚焦。
2. **广告自动周报**：输入广告平台导出的 CSV，用 LLM 自动生成“哪条广告该停、哪条该加预算”的周报邮件。对标 Cometly，但更轻。
3. **AI 用户访谈记录整理器**：用户上传访谈录音，AI 自动分段、提取用户原话、总结痛点和付费意愿。对标 Articos，但做“辅助”而不是“模拟”。

## 用户访谈问题

如果你今天准备去验证上面某一个想法，可以直接问这些访谈对象：

1. **“上次你做这件事，是让谁帮的忙？你当时有没有考虑付费找人解决？”**
   —— 用来判断：用户现在是自己硬扛，还是有购买替代服务的先例。

2. **“如果现在有一个工具能帮你自动完成 80% 的工作，但每个月收费 $20，你会继续用吗？为什么？”**
   —— 用来估算意愿和价格锚点。

3. **“你之前试过哪些同类工具？为什么离开？”**
   —— 用来避开别人已经踩过的坑，找到你产品的差异化突破口。
