## 1. LinkPost：AI 内容分发/链接发布工具（功能详情未证实）

**来源：** [产品页](https://trustmrr.com/startup/linkpost)｜[TrustMRR 列表页](https://trustmrr.com/)（2026-10-31 摘要）

### 1.1 产品与用户问题

- **名称/类别：** LinkPost，TrustMRR 分类为 Artificial Intelligence。
- **功能推测：** 从名称看，可能是把链接、产品更新或内容发布到多个渠道的工具；也可能是链接转帖子、链接聚合或社交发布辅助。**功能未证实，置信度低。**
- **目标用户推测：** 独立开发者、内容创作者、增长/营销人员、需要把同一内容分发到多个平台的小团队。
- **用户问题：** 同一篇产品更新/链接，要手动改写成 X、LinkedIn、邮件、小红书、论坛等版本；重复劳动多、容易忘、平台语气不同。付费理由不是“好奇 AI”，而是**节省重复发布时间、保持发布频率**。

### 1.2 商业信号

- **官方收入：** 未知。未找到公司/创始人公开 MRR/ARR。
- **第三方平台列示收入：** $4,000（TrustMRR 摘要，周期未注明；按 Price/Revenue 反推很可能为月收入）。
- **推测月收入：** **$3,500-$4,500/月**；置信度：**中低**。
- **售价/倍数：** $79k / 1.6x。若 Revenue 为月收入，则售价约为年化收入的 1.6 倍，属于小体量可转让资产。
- **定价模式：** 未知。摘要未给定价页；推测可能为订阅制，置信度低。
- **牵引力证据：** 仅见其在 TrustMRR “Best deals this week”摘要中出现，可视为市场曝光线索，**不能证明用户增长**。
- **未知：** 定价、付费用户数、流量、评价、退款率、毛利率。

### 1.3 为什么可能赚钱

- **使用频率：** 中高。每次产品更新、内容发布都可能用一次。
- **紧迫程度：** 中。不是救命需求，但直接影响发布效率和内容产能。
- **预算负责人：** 个人创作者、独立开发者、小团队增长负责人。
- **切换成本：** 低。用户很容易改用 ChatGPT+复制粘贴，这是最大风险。
- **赚钱关键：** 把“多平台改写+发布检查+历史复用”打包成工作流，而不是只提供一个生成框。

### 1.4 产品逻辑与技术路径（建议，不是其真实架构）

**适合初学者的 MVP：**

1. 输入一个链接或产品更新文本。
2. 抓取标题、摘要、关键点。
3. 选择平台模板：X/LinkedIn/小红书/邮件/论坛。
4. AI 生成多平台版本，保留品牌语气。
5. 用户预览、编辑、复制；第一版不做自动发布。
6. 保存历史，支持复用和定时提醒。
7. Stripe/Lemon Squeezy 收费。

**核心工作流：** 链接 → 内容抽取 → 平台模板 → AI 改写 → 预览编辑 → 复制/半自动发布 → 历史记录。

**需要的数据/输入：** 链接正文、产品卖点、品牌语气、平台字数/格式限制、历史高表现帖子。

**推荐技术栈：** Next.js + Tailwind；Supabase Auth/DB；OpenAI API；Cheerio/Readability 做网页抽取；定时任务；Stripe/Lemon Squeezy。自动发布再考虑各平台 API。

**AI 用法：** 抽取、摘要、改写、平台风格分类、标题生成。不要一开始做“全自动智能体发布”。

**如果我来开发，最大问题：**  
**不是调用模型，而是“发布”这一环。** 真正自动发布要接入多个平台 API、OAuth 审核、反垃圾规则、账号权限和失败重试；平台限制一变，产品就坏。若只做复制粘贴，用户会问“为什么不直接用 ChatGPT”。所以第一版必须把“多平台模板+历史复用+检查清单”做得比聊天框省步骤。

**更简单的第一版：** 只做“链接/更新 → 3 个平台文案包”，不自动发布；用人工审核和手动复制降低平台风险。

### 1.5 适合 OPC 初学者的机会

- **更小众版本：** 面向独立开发者的“Changelog 转社交帖”：输入产品更新页，输出 X、LinkedIn、邮件、Product Hunt 评论草稿。
- **第一批访谈客户：** 独立开发者、播客主、内容运营、一人公司创始人。
- **1 周验证实验：** 找 10 个有产品更新页的独立开发者，人工帮他们生成多平台文案，收 $10/次或免费换反馈；记录他们是否愿意每周重复使用，而不是只说“不错”。

## 2. FlipScan：AI 二手转售扫描器

**来源：** [产品页](https://trustmrr.com/startup/flipscan)｜[TrustMRR 列表页](https://trustmrr.com/)（2026-10-31 摘要）

### 2.1 产品与用户问题

- **名称/类别：** FlipScan: AI Reselling Scanner，Artificial Intelligence。
- **功能推测：** 面向二手转售者的扫描工具，可能通过拍照/条码识别商品，查询转售价格、利润空间或建议买入价。**具体功能未展开，置信度中低。**
- **目标用户：** 跳蚤市场卖家、二手平台卖家、清库存小商家、业余转售者。
- **用户问题：** 在扫货现场，用户需要在很短时间内判断“这件东西能不能买、能卖多少钱、扣掉手续费和运费还剩多少”。这是高频、直接影响利润的决策问题。付费理由：**一次正确估价就可能覆盖订阅费**。

### 2.2 商业信号

- **官方收入：** 未知。未找到公开官方 MRR/ARR。
- **第三方平台列示收入：** $860（TrustMRR 摘要，周期未注明；反推很可能为月收入）。
- **推测月收入：** **$700-$1,000/月**；置信度：**中低**。
- **售价/倍数：** $8k / 0.8x。售价低于年化收入，**推测**可能存在增长/留存风险、收入不可持续、或卖家急售；也可能只是市场定价差异。不能据此断定产品差。
- **定价模式：** 未知。推测可能为订阅/积分/移动应用内购，置信度低。
- **牵引力证据：** 仅见 TrustMRR “Recently listed”，无评论、安装量、流量数据。
- **未知：** 定价、识别准确率、数据来源、用户数、平台覆盖、退款率。

### 2.3 为什么可能赚钱

- **使用频率：** 高。扫货时可能一次查几十件商品。
- **紧迫程度：** 高。现场决策有时限，估价慢就错过交易。
- **预算负责人：** 转售者自己；小商家老板。
- **切换成本：** 中。若历史扫货记录、利润规则和准确率建立起来，用户不愿换。
- **赚钱关键：** 估价准确率和数据覆盖。AI 识别只是入口，真正的价值是“可信的已售价格+费用计算”。

### 2.4 产品逻辑与技术路径（建议）

**适合初学者的 MVP：**

1. 拍照或扫码识别商品。
2. 用户确认品类/型号（第一版必须允许手动纠正）。
3. 查询已售价格或参考价格。
4. 输入买入价，自动计算平台费、运费、税、利润。
5. 给出“建议买入价/预计利润/风险提示”。
6. 保存扫货历史。
7. 订阅收费。

**核心工作流：** 拍照/条码 → 识别 → 型号匹配 → 价格查询 → 费用计算 → 利润建议 → 历史记录。

**需要的数据/输入：** 商品数据库、已售成交价、平台费用规则、运费、汇率、品类知识。

**推荐技术栈：** React Native/Flutter 或移动端 PWA；Supabase；视觉模型/条码库；价格数据 API；缓存与队列；Stripe/应用内购。

**AI 用法：** 视觉识别、标题匹配、品类分类、异常价格检测。AI 不能替代价格数据源。

**如果我来开发，最大问题：**  
**数据源，而不是模型。** 已售价格数据往往受平台 API 条款、成本和覆盖限制；如果数据不稳定，AI 估价再漂亮也不可信。第二问题是识别错误：扫错型号会给出错误利润建议，用户一次被骗就不会再用。移动端离线、拍照质量、费用规则也会拖慢体验。

**更简单的第一版：** 只做一个品类，例如二手相机、乐高、书籍或复古服装；用户手动选型号，工具只做“利润计算+参考价”，不做全自动识别。用公开成交记录和人工核价起步。

### 2.5 适合 OPC 初学者的机会

- **更小众版本：** “二手相机扫价助手”：拍照/选型号，查已售价格，扣手续费和运费，给出最高买入价。
- **第一批访谈客户：** 本地跳蚤市场卖家、二手相机店、乐高转售者、闲鱼/eBay 小卖家。
- **1 周验证实验：** 陪 3 个转售者扫 20 件商品，人工用表格+公开成交价帮他们算利润；观察他们是否愿意为“准确+快”付 $9-$19/月，以及最常查什么品类。

### 3.2 商业信号

- **官方收入：** 未知。
- **第三方平台列示收入：** $379（TrustMRR 摘要，周期未注明；反推很可能为月收入）。
- **推测月收入：** **$300-$450/月**；置信度：**中低**。
- **售价/倍数：** $6k / 1.3x。小体量工具资产。
- **定价模式：** 未知。推测可能为订阅或买断，置信度低。
- **牵引力证据：** 仅见 “Recently listed”，无评价/流量/安装量。

### 3.3 为什么可能赚钱

- **使用频率：** 中。创作者每周可能多次处理素材，但不是每日必用。

- **预算负责人：** 创作者个人、剪辑师、小团队运营。
- **切换成本：** 低。容易被剪映、CapCut、Descript、ChatGPT 等替代。
- **赚钱关键：** 找到一个“高频、具体、比通用编辑器少 5 步”的窄工作流，而不是做完整编辑器。

### 3.4 产品逻辑与技术路径（建议）

以下假设做“长内容转短视频/社媒文案包”，不是对其真实功能的确认。

**适合初学者的 MVP：**

1. 上传音频或视频。
2. 转录为文本。
3. AI 找钩子、分段、提取金句。
4. 生成 5-10 条短视频标题/脚本/字幕。
5. 用户编辑并导出文案包。
6. 订阅收费。

**核心工作流：** 上传媒体 → 转录 → 分段/找钩子 → 生成多平台文案 → 编辑导出。

**需要的数据/输入：** 媒体文件、转录文本、品牌语气、目标平台格式。

**推荐技术栈：** Next.js + Supabase；对象存储；Whisper/同类转录 API；OpenAI API；FFmpeg worker；队列；Stripe。

**AI 用法：** 转录、摘要、分段、钩子提取、文案生成。第一版不要做完整视频时间轴编辑器。

**如果我来开发，最大问题：**  
**媒体处理是深坑。** 大文件上传、转码、异步任务、失败重试、存储成本、导出质量都会拖垮初学者；完整视频编辑器前端时间轴非常复杂。另一个问题是版权和平台适配。AI 文案不是壁垒，稳定处理媒体才是。

**更简单的第一版：** 只做音频/播客，不做视频渲染；输出“7 天短视频文案包+字幕文本”，让用户自己去剪。先手动交付，验证付费后再自动化。

### 3.5 适合 OPC 初学者的机会

- **更小众版本：** “播客单集转 7 条短视频脚本+标题+字幕包”，面向知识博主和课程创作者。
- **第一批访谈客户：** 播客主、知识类 UP 主、课程讲师、一人内容团队。
- **1 周验证实验：** 找 3 个播客主，人工把 1 期节目切成 7 条短视频文案，收 $50 实验费；观察修改率和是否愿意按月订阅。

- **使用频率：** 每日。闹钟/晨间提醒是天然高频场景。
- **紧迫程度：** 中低。不解决会“不方便”，但不会立刻造成损失。
- **预算负责人：** 个人用户；教会小组可能团购。
- **切换成本：** 中。一旦形成晨间习惯、收藏经文和读经计划，迁移意愿下降。
- **赚钱关键：** 通知可靠性+内容更新+细分人群。非 AI 产品，靠习惯和内容留存。

### 4.4 产品逻辑与技术路径（建议）

**适合初学者的 MVP：**

1. 用户设置晨间提醒时间。
2. 每天推送一节经文/短读经计划。
3. 支持收藏、分享、连续打卡。
4. 免费基础版+订阅高级内容/主题计划。
5. 先做通知提醒，不承诺“系统级闹钟”。

**核心工作流：** 设置提醒 → 每日推送 → 打开阅读 → 收藏/分享 → 订阅。

**需要的数据/输入：** 公版圣经译本、读经计划、用户偏好、通知时间。

**推荐技术栈：** Flutter/React Native；本地通知；Supabase；OneSignal；移动端应用内购。AI 可选，用于个性化解释/推荐，但不是核心。

**如果我来开发，最大问题：**  
**闹钟可靠性。** iOS 通知权限、后台限制、Android 厂商省电策略都会导致“闹钟不响”；用户对这个零容忍。第二是圣经译本版权，不能随意使用受版权保护的译本。第三是留存：用户下载后如果连续几天不打开，就会卸载。

**更简单的第一版：** 先做“每日经文通知+收藏”，不做复杂闹钟；使用公版译本；先 Android 或先做 PWA 验证内容偏好；用人工推送验证 7 天留存。

### 4.5 适合 OPC 初学者的机会

- **更小众版本：** 面向“考生/母亲/教会小组”的晨间经文+代祷清单提醒；或“通勤 5 分钟读经”音频提醒。
- **第一批访谈客户：** 教会小组成员、基督徒学生、每日灵修用户。
- **1 周验证实验：** 做落地页，招募 10 个目标用户，连续 7 天人工发送晨间经文提醒；测打开率、回复率和付费意愿，不先开发完整 App。

## 今日模式

**小工具生意的核心不是“AI 含量”，而是“数据源+工作流+可靠性”。**  
LinkPost 的难点在平台发布，FlipScan 的难点在价格数据，ClipUtils 的难点在媒体处理，Bible Verse Alarm 的难点在通知可靠性。模型只是其中一环。对个人创业者更可复用的模式是：

> 先用人工交付结果验证付费，再把重复步骤产品化；先卖“省时间/多赚钱”的结果，再卖软件。

另一个值得记住的信号：TrustMRR 上这些小产品的售价/倍数并不高，说明市场会给“平台依赖、留存不确定、收入规模小”打折。初学者不要一上来追求大平台，而应做**可转让、可验证、能手动交付**的小资产。

## 建造雷达：3 个受今日产品启发的小产品想法

### 想法 1：二手相机扫价助手
- **灵感：** FlipScan。
- **用户：** 本地二手相机卖家、跳蚤市场转售者。
- **MVP：** 选品牌/型号 → 查公开成交价 → 扣平台费和运费 → 给出最高买入价。
- **定价假设：** $9-$19/月，或按查询次数卖积分。
- **验证：** 陪 3 个卖家扫 20 件商品，人工出利润表，观察是否愿意付费。

### 想法 2：Changelog 转多平台社交帖
- **灵感：** LinkPost。
- **用户：** 独立开发者、一人公司。
- **MVP：** 输入产品更新链接 → 生成 X/LinkedIn/小红书/邮件草稿 → 复制发布。
- **定价假设：** $12/月，或 $5/次文案包。
- **验证：** 手动服务 10 个产品更新，测重复使用率。

### 想法 3：播客单集转 7 天短视频文案包
- **灵感：** ClipUtils。
- **用户：** 播客主、知识博主、课程创作者。
- **MVP：** 上传音频 → 转录 → 找钩子 → 输出 7 条脚本/标题/字幕文本。
- **定价假设：** $19/月，或 $49/期。
- **验证：** 人工切 3 期节目，收实验费，测修改率和复购意愿。

## 用户访谈问题：可直接问潜在用户

把 `X` 替换成你的产品场景，例如“扫货时查价”“产品更新转多平台”“播客转短视频”“晨间灵修提醒”。

1. **“你上一次做 X 是什么时候？当时具体步骤是什么？哪一步最耗时、最容易出错？”**  
   目的：确认问题真实发生，而不是你觉得有需求。

2. **“你现在用什么替代方案——人、Excel、其他软件、还是干脆不做？每月为此花多少时间或多少钱？”**  
   目的：找到真实替代方案和预算，而不是问“你会用吗”。

3. **“如果有一个工具只解决 X 里最关键的一步，你愿意先试用 3 次吗？试用后你愿意付 $0/$9/$19/$49 中的哪一档？为什么？”**  
   目的：把“感兴趣”推进到“具体付费档位”。
