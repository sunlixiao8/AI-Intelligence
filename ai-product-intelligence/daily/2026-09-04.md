## 产品 1：MagicSlides.app

- **链接**：https://www.magicslides.app
- **TrustMRR 挂牌页**：https://trustmrr.com/startup/magicslides-app
- **类别**：AI 演示文稿生成 / Google Slides 插件
- **目标用户**：经常要做 PPT 的顾问、教师、培训师、学生、中小企业销售

### 1.1 用户问题

“从空白页开始做 PPT”不是高频刚需，但它是**一个永远会出现、每次出现都很痛苦**的任务。

普通职场人做完一份 20 页的周报/方案，真正花时间的不是打字，而是：想结构、找措辞、调版式、把想法转成别人能看懂的页面。MagicSlides 把“给我一个主题”变成“给你一整套可编辑的幻灯片草稿”，用户再做修改和裁剪。

它解决的痛苦很具体：**把 0 到 60 分的部分交给 AI，把 60 到 80 分留给用户自己改。**

### 1.2 商业信号

TrustMRR 挂牌信息显示：

- Revenue：$9,200 / 月
- Price：$500,000
- Multiple：4.5x

这块数据需要特别说明：

| 项目 | 内容 |
|---|---|
| 月收入判断 | 约 `$9.2k/月` |
| 置信度 | `中`（来源是 TrustMRR 挂牌页，卖方自报，非官方审计） |
| 证据 | TrustMRR 页面显眼位置出现 MagicSlides.app 的在售信息（抓取日期 2026-09-04） |
| 定价模式 | **未知**。我没有抓到它的价目表，常见模式是免费基础版 + 包月订阅或点数制，但不能确认 |

另一个信号是 500k 美元的挂牌价。它不代表公司值 500k，只说明**卖家认为自己能卖出这个价**。4.5x 倍数意味着买家对增长有一定预期。对于个人开发者，这个估值信号比“收入信号”更弱，建议只看成一个故事背景。

### 1.3 为什么可能赚钱

- **使用频率**：不是每日，而是“每周一次 + 赶工场景”。这个频率足够支撑订阅吗？有点勉强，所以最好做成按次/按点数付费，或者是团队共享订阅。
- **付费动机**：一场重要路演的时间成本远高于 $10~$20 的工具费。
- **切换成本**：如果是 Google Slides 插件，用户安装后，下次做 PPT 会自然再打开，习惯优势明显。
- **预算来源**：C 端用户自掏腰包；B 端可以由部门采购，但需要演示给团队多人使用。

### 1.4 产品逻辑与技术路径（重点）

如果“我”来做，我会拆成四个阶段：

1. **用户输入主题**：例如“面向天使投资人的 AI 招聘工具路演”。
2. **AI 产出大纲和逐页内容**。
3. **选择一套固定版式模板。**
4. **生成可编辑的 PPT/Google Slides 文件。**

技术栈可以是：

- Next.js + Tailwind 做前端
- OpenAI API，使用 **Structured Output/JSON Schema**，让模型稳定返回每一页的结构化数据
- 后端用 Next.js API Routes
- 文件生成：python-pptx 或 Google Slides API
- 用户上传 Logo/品牌色，替换主题变量

**最大的难点不在 AI，而在“文件生成质量”。**

用 API 生成真正的 `.pptx` 时，标题太长了怎么办？要点很多时要不要换页？图片比例对不对？用户拿到的 PPT 如果像“翻车现场”，不管你前端页面多好看，用户都会觉得是垃圾。

所以要限制 AI 自由度，不要让它“自由创作”一堆花哨版式。更聪明的做法是：

> 只做 4 种固定卡片模板：封面页、要点页、两栏对比页、数据页。AI 只负责往模板里填字段，不允许创造新布局。

这样一来，MVP 难度会下降很多。用户拿到的是“内容结构完整、版式可预测”的草稿，而不是一个充满随机艺术的 demo。

### 1.5 适合 OPC 的切入机会

更细分的方向：

- **行业专用 PPT 生成器**：只做“卖课大纲 PPT”“咨询交付报告”“毕业论文开题 PPT”，比大而全的 MagicSlides 更容易做出质量。
- **中文 PPT 模板 + AI 填充**：国内用户对豆包/Kimi/讯飞的习惯已经很强，但中文 PPT 的高质量文件输出仍然是个痛点。

**1 周验证实验**：
不写代码，先用 ChatGPT + Canva/PPT 模板手动帮 5 个人做 PPT。免费做，但记录他们拿到成品后第一反应改了什么。如果 5 个人全部说“结构比我快太多了”，那说明值得做；如果他们开始逐字改内容，说明 AI 内容质量不行，而不是文件生成技术不行。

## 产品 2：Rezi

- **产品页**：https://www.rezi.ai （有待进一步核实官方口径）
- **来源**：TrustMRR Leaderboard 摘要（https://trustmrr.com/）
- **类别**：AI 简历生成器 / ATS 求职工具
- **目标用户**：求职者、应届生、猎头、企业招聘团队

### 2.1 用户问题

写简历是一个“低频率、高焦虑、高后果”的任务。

普通求职者不知道自己简历会被 ATS（自动简历筛选系统）怎么解析，也不知道该匹配哪些关键词。Rezi 的价值不是“帮你写一段漂亮自我介绍”，而是：

> 告诉你：你的简历能不能通过机器阅读？和工作描述比差在哪？怎么改？

它把简历从“写作问题”变成了一个“撮合问题”。这个角度很聪明，因为用户愿意为了结果付费，而不只是为了文字付费。

### 2.2 商业信号

TrustMRR 排行榜显示：

- MRR：约 `$256,830/月`
- 置信度：`中`。来源为 TrustMRR 抓取页，创始人在数据库中的自报说明是一种“公开声明”，但没有审计
- 官方描述提到：约 **1M 新用户/年**；企业版支持 300+ 组织，包括财富 500 强企业和多所大学

这个用户量的信号比 MRR 更值得关注。说明 Rezi 已经有稳定增长引擎，可能是 SEO 或学校/职业中心的推荐渠道。

| 项目 | 内容 |
|---|---|
| 月收入判断 | 约 `$250k~$260k/月` |
| 置信度 | `中` |
| 证据 | TrustMRR Leaderboard 的 Rezi 条目显示 MRR 约 25.7 万美元；官方文本称有“1M new users per year”（2026-09-04 抓取） |
| 收入类型 | 看起来是 MRR 口径，但仍以创始人自述为准 |

### 2.3 为什么可能赚钱

- **付费意愿**：找工作时，用户愿意花 $20~$50 改善简历，因为回报是 offer 带来的收入。
- **使用频率**：单人频率低，但群体覆盖大：学生、转行者、被裁员工、跳槽者每天都有。
- **最好赚的不是 C 端**：Rezi Enterprise 才是高价值。如果企业把 Rezi 作为招聘团队的筛人辅助工具，猎头和企业付的就不是“个人工具费”，而是“招聘成本”，这才是几万美元/年的生意。
- **壁垒**：用户上传的简历越多，它对不同行业关键词和 ATS 解析的经验就越强，后来者有数据冷启动问题。

### 2.4 产品逻辑与技术路径

MVP 可以只做两件事，不要一上来就做完整的“简历生成器”：

1. **简历解析**：上传 PDF，提取出工作经历、教育、技能。
2. **匹配评分**：粘贴一个 JD，把简历里的技能点和 JD 要求做对比，输出“缺什么关键词”“哪些经历应该往前放”。

技术栈建议：

- Next.js + Tailwind
- Supabase 做用户数据和文件存储
- PDF 解析用成熟库或 API
- OpenAI API 做技能抽取和关键词比对
- 最终导出 PDF 用排版可控的方式，不建议用浏览器直接打印，因为中文和英文的字体、分页都会出问题

**最大的技术难点是 PDF 到结构化数据的还原。**

很多简历的版式是两栏的、带表格的、用图形图标表示技能的。AI 模型看 PDF 提取后的文本时，容易丢失阅读顺序：左边读完跳到右边，逻辑就乱了。

对初学者来说，先不要追求“任意简历都能解析”。可以把处理范围限定为：**单栏、标准时间倒序、文字型简历**。把这种简历的解析做到 90 分以上，再慢慢扩展。

### 2.5 适合 OPC 的机会

中文世界的机会可能不是“简历生成”，而是：

- **针对特定岗位的匹配度体检**：例如“投产品经理岗”的简历体检。
- **转行简历改写**：传统行业转 AI/互联网时，怎么写项目经历才不显得业余。
- **高校就业中心的小工具**：按学校模板一键格式化成统一版本，这个场景在中国高校里很常见。

**访谈对象建议**：学校就业办老师、猎头顾问、最近一个月投过 20 份以上简历还没回音的人。不要去问“你觉得简历生成器怎么样”，而是问：“你最近一次投简历，有没有一个公司问了你简历里写的东西？”

## 产品 3：TableAI

- **来源**：Indie Hackers 产品数据库摘要（https://www.indiehackers.com/products）
- **类型**：AI + WhatsApp 的餐厅运营工具
- **目标用户**：中小餐厅、咖啡馆、外卖店铺

*说明：这个产品不在原始候选池里，属于补充来源。它的收入数据只有 Indie Hackers 的产品摘要一句话，没有产品官网细节，因此我把这个产品当成“模式学习案例”，而不是当成一个证明有效的赚钱产品。*

### 3.1 用户问题

对很多小餐厅来说，客户真的会通过 WhatsApp 或微信订餐：“老板，今天还有位置吗？”“来两份招牌饭，不要辣，二十分钟后到。”

这些散客贡献了不少营业额，但餐厅只能用人工回复。遇到忙的时候漏回消息，客户就走了。

TableAI 做的事情很可能是：让顾客用聊天对话自然下单，AI 识别菜品、口味、取餐时间，然后餐厅后台和店员确认。**核心不是“AI 聊天”，而是把聊天变成一张可执行的订单。**

如果你把它当成一个 AI 聊天机器人，会觉得没什么了不起；如果把它当成“餐厅第二条收银入口”，它值 $20k/月。这正是它的商业模式值得学习的地方：**把 AI 嵌入已有的高频对话流，而不是再造一个新 App。**

### 3.2 商业信号

Indie Hackers 摘要显示：

- 月收入：`$20,000/月`（**自报，未验证**）
- 置信度：`低`
- 证据：Indie Hackers 产品列表里的 “TableAI Restaurant operations on WhatsApp. No app to install. $20,000 month self-reported”（2026-09-04 抓取）

我需要特别提醒：Indie Hackers 的“self-reported”只是创始人自己填的数字。对一个餐厅 SaaS，它的验证难点在于：它到底是有 100 家店每家付 $200，还是有 10 家店每家付 $2000？这个信息看不到。

### 3.3 为什么这个模式可能赚钱

- **频率极高**：餐厅每天都有人订餐，这是高频、实时、不能出错的需求。
- **紧急程度极高**：漏单等于直接损失收入。
- **预算很小但算得清**：老板愿意为一单不丢付费。如果一个月被漏掉 30 单，每单 100 元，就是 3000 元损失。一个 AI 接单助手月费 $99~$200，对老板来说 ROI 是明确的。
- **切换成本**：顾客一旦习惯通过 WhatsApp 下单，餐厅就不会轻易换工具；这个渠道沉淀下来的客户不是你的，但也算餐厅的资产。
- **团队很小，甚至一个人就能跑通**：完全适合 OPC 先做最小客户群。

### 3.4 产品逻辑与技术路径

如果把“为餐厅做一个聊天助手”想成纯 NLP 问题，你会死得很惨。

因为真正的复杂度在流程，不在对话：

- 菜单怎么更新？
- 某个菜卖完了 AI 怎么会知道？
- 顾客说“和上次一样”怎么办？
- 重复下单怎么处理？
- 支付/到店付款到底算不算下单？

**MVP 不要做成完整点餐系统。**

可以先只做一件事：**把 WhatsApp 里来的自由文本订单，结构化地推送到餐厅的一个 iPad/微信群/Google Sheet 里，然后店员一键确认。**

流程是：

1. 顾客发 WhatsApp 语音/文字：“两份鸡饭，少辣，12 点来自取。”
2. AI 自动抽取成结构化内容：`{菜品：鸡饭 x2，口味：少辣，时间：12:00，类型：自取}`
3. 推送通知给店员：请确认。
4. 店员回复“OK”，AI 再把确认消息发给顾客。

技术栈：

- Twilio WhatsApp API 或 Meta WhatsApp Business API
- OpenAI API 做意图识别和信息抽取
- Supabase 存订单
- Google Sheets 同步给店家做每日对账
- 后台用一个极其简单的列表页给店员看：新订单、待确认、已完成

**最大的难点：店家操作意愿和容错。**

服务员和厨师不会像互联网产品用户那样愿意多点几下按钮。如果你的 AI 识别错了菜品，店员需要能一键修正，且修正过程不能超过 2 秒。否则他们会放弃这个工具。

**降难度捷径**：不要做全自动接单。第一版做“AI 自动识别 + 人工点击确认”的半自动模式。把 AI 当成人肉接线员的助手，而不是替代者。

### 3.5 适合 OPC 的机会

中国个人开发者可以直接抄作业的版本：

- **企业微信/微信私聊版“点单助手”**，专门给社区咖啡店、烘焙私房、外卖店用。
- 不要碰 POS 收银和库存，只做“让老板少漏单”这一个非常小的点。
- 定价可以从每单 0.3~0.5 元或每月 199~399 元试起。

**第一批访谈对象**：
找一个开餐饮店的朋友，或者去附近小店观察。不要问“你要不要 AI”，问：“你现在用什么方式记住微信里来的订单？有没有漏过单？漏单那天你损失了多少钱？”

## 为什么我没有选候选池里其他“高收入”项目

本次候选池里有几个看起来很惊人的数字：

- Private Venture 60：Revenue $33k，Price $1M
- Private Venture 59：Revenue $3.6k，Price $50k
- UpLinked B.V.：Revenue $2.4k，Price $28k
- AutoReels.AI：Revenue $1.2k，Price $50k

这些我没有做进正篇，原因是它们全部是匿名或极度残缺的信息。我只知道收入数字和挂牌价，不知道产品是什么、用户是谁、为什么可能赚钱。如果强行分析，只能靠猜。**猜出来的内容不是情报，是故事。**

但其中有一个反向信号对初学者很有价值：

> AutoReels.AI 月收入约 $1.2k，却挂牌 $50k，要倍数 3.5x。MagicSlides 月收入 $9.2k，挂牌 $500k，要 4.5x。这些数字可以在 TrustMRR 上对比出来。

这说明“AI 套壳小产品”确实存在一个交易市场，但价格更多反映的是“未来增长的故事”，而不是当前利润。如果你做产品的目标只是未来卖给其他创业者，那么你的增长要讲得漂亮；如果你的目标是做一个小而稳的生意，参考价应该在 1.5x~2.5x，而不是 4.5x。

## 今日模式

**这三个产品，表面上完全不一样：做 PPT、写简历、餐厅接单。但它们的共同点是：都不卖“聊天”。**

仔细观察：

- MagicSlides 卖的是“一份能直接修改的 PPT 草稿”
- Rezi 卖的是“简历和目标岗位之间的差距诊断”
- TableAI 卖的是“一张餐厅不会漏掉的订单”

区别普通 AI 产品和赚钱 AI 产品，往往就在这个时候出现：**你能不能让用户从你的产品里带走一个“交付物”或者一个“结果”？**

如果用户用完之后只能说“这个机器人好聪明”，他不会付钱。如果用户拿到的是一个更好看的文件、一份得分报告、一张没有漏掉的订单，他会自己算出这笔钱值不值。

## 建造雷达

三个由今天产品启发、且 CTO 强度适合 OPC 的小想法：

1. **会议纪要转工作周报再转外部演示 PPT**  
   大多数人开会完要写周报，周报要写月度汇报。这中间有很多重复劳动。做一个只针对“从会议记录到周报模板”的极简工具，比做一个完整 PPT 生成器更快验证。

2. **简历盲区体检器**  
   不做简历生成，只做“投递前检查”。用户可以上传简历和职位 JD，系统给出 3 个具体问题：缺哪些关键词、最近一段经历描述是否太弱、有没有不通顺的表达。定价不用订阅，按次付费 ￥9.9 或 $3。

3. **微信群/WhatsApp 的半自动客服转发器**  
   针对任何一个每天在私人号/微信里收到大量订单和咨询的小商家（花店、私房菜、宠物寄养），把客户消息里的“需求”抽出来，变成店长一眼能看懂的工作卡。不需要复杂的聊天机器人体验，只要信息提取够准。

## 用户访谈问题

你可以直接拿去问潜在用户（无论是简历人群还是餐厅老板），关键是不要问“你需不需要 AI”，而是问场景：

1. **“请你说一下上次做 XX 的完整过程。你从开始到结束，中间卡在哪一步最久？”**  
   这里 XX 可以是“做一份路演 PPT”“改简历”“记一个微信订单”。问细节，别问感受。

2. **“如果有一个工具能帮你完成 80%，剩下 20% 需要你自己改，你敢不敢用？”**  
   这能测出用户对 AI 输出的信任底线。如果他连 80% 都不敢信，说明你的交付必须做得更可编辑、更可回退，而不是模型更强。

3. **“你现在为这件事花了多少钱？包括钱和人工时间？”**  
   如果用户答不上来，说明痛点不够迫切。如果他说“每周至少花两小时”，你就知道有一个可以计算价值的口径。

## 置信度与风险声明

本期所有收入数据来自 TrustMRR 与 Indie Hackers 的页面快照，不是财务审计，也不代表真实银行流水。以下为本期关键结论的置信度汇总：

| 产品 | 收入估算 | 置信度 |
|---|---|---|
| MagicSlides.app | 约 `$9.2k/月` | 中 |
| Rezi | 约 `$250k~$260k/月` | 中 |
| TableAI | 约 `$20k/月`（自报） | 低 |
| Private Venture / UpLinked / AutoReels | 只有挂牌线索 | 未知 |

对刚开始做 AI 产品的你来说，最重要的一句话是：

**不要把任何带链接的收入数据直接当“可复制的事实”，而要问：如果这个产品今天从零开始，我能不能用更小的切口做一次 1 周验证？**
