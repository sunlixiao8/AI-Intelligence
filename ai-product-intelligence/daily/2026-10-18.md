**来源链接：** [TrustMRR: ShowcaseKu](https://trustmrr.com/startup/showcaseku)｜[TrustMRR 来源页](https://trustmrr.com/)

**降低难度的捷径：**  
第一版先不接 AI，做 3 个高质量人工模板 + 表单 + 访问统计；用人工帮 5 个用户生成案例页，验证他们是否愿意为“转化”付费，而不是为“生成”付费。

## 2. Carry

**来源链接：** [TrustMRR: Carry](https://trustmrr.com/startup/carry)｜[TrustMRR 来源页](https://trustmrr.com/)  
**类别：** Utilities / AI 工具周边  
**产品描述：** “Save ChatGPT, Claude & Grok to Markdown Automatically”  
**目标用户：** 重度使用多个 AI 聊天工具、需要归档和复用对话的人：研究者、顾问、内容创作者、开发者、知识管理爱好者。

### 2.1 用户问题
AI 对话散落在 ChatGPT、Claude、Grok 等平台里，复制粘贴麻烦，格式混乱，难以沉淀为可搜索、可引用的 Markdown 笔记。  
用户付费点：**节省整理时间 + 防止重要对话丢失 + 把对话变成知识资产**。这是高频且具体的痛点。

### 2.2 商业信号

| 项目 | 内容 |
|---|---|
| 定价模式 | 未知。可能是订阅或一次性买断，摘要未显示 |
| 官方收入 | 未找到官方披露 |
| 平台披露收入 | TrustMRR 显示 `Revenue $354`，推断约 `$354/月` |
| 推测收入 | 年化约 `$4,248/年`；无额外推测 |
| 置信度 | **中低**。字段与 `2.4x` 倍数吻合，但客户数、退款、平台依赖风险未知 |
| 交易信号 | 售价 `$10k`，Multiple `2.4x` |

### 2.3 为什么可能赚钱
- **使用频率：** 高。重度 AI 用户每天产生对话。
- **紧迫程度：** 中高。重要对话丢失或难找时很痛。
- **预算负责人：** 个人专业用户；团队版可由团队负责人付费。
- **切换成本：** 中。一旦形成归档习惯和目录结构，迁移成本会上升。

### 2.4 产品逻辑与技术路径
**适合初学者的 MVP：** Chrome 扩展，一键把当前 ChatGPT/Claude 对话导出为 `.md`，保留角色、时间、代码块，本地下载，不做云同步。

**核心工作流：** 打开对话 → 点击扩展 → 解析页面 DOM → 转 Markdown → 下载或复制。第二版再加标签、搜索、同步到 Obsidian/Notion。

**推荐技术栈：** Chrome Extension Manifest V3 + TypeScript；可选 Next.js 做官网和付费；Supabase 做账号和同步；OpenAI API 仅用于自动标题、摘要、标签，不是核心。

**AI 用法：** 可选：自动生成对话摘要、提取待办、按项目分类。核心其实是解析和格式转换，不是大模型。

**如果我来开发，最大难点：**  
**平台 DOM 变化和权限/隐私**。ChatGPT、Claude、Grok 页面结构会变，扩展容易失效；用户对话可能含敏感信息，必须明确“本地处理、不上传”。另外要遵守平台条款，避免做成灰色抓取工具。

**降低难度的捷径：**  
第一版只支持一个平台、只导出当前对话、只本地下载。不要一上来做三平台同步。先验证用户是否愿意为“省 10 分钟整理时间”付费。

### 2.5 适合 OPC 初学者的机会
- **更小众版本：** 面向咨询顾问的“AI 访谈对话归档”，自动生成客户纪要、引用和待办。
- **第一批访谈客户：** AI 重度用户、独立顾问、研究员、内容创作者、用 Claude 写代码的开发者。
- **1 周验证实验：** 做 20 次人工导出服务，收 $5–$10/次；同时记录用户最想导出的是“代码块、引用、附件还是整个项目”。

## 3. Static Forms

**来源链接：** [TrustMRR: Static Forms](https://trustmrr.com/startup/static-forms)｜[TrustMRR 来源页](https://trustmrr.com/)  
**类别：** Developer Tools  
**目标用户：** 静态站点开发者、独立开发者、建站代理公司、使用 Next.js/Astro/Hugo 的团队。  
**为什么纳入非 AI 产品：** 它是典型的“单一工作流 + 托管订阅 + 开发者分发”小 SaaS，商业模式清楚，且可用 AI 做回复摘要/垃圾过滤增强。

### 3.1 用户问题
静态网站没有后端，但联系表单、反馈表单、报名表单仍然需要接收数据。用户不想为了一个表单搭服务器、数据库和邮件系统。  
付费点：**可靠接收表单 + 防垃圾 + 邮件通知 + 简单后台**。这是反复出现、低好奇心、强工具型需求。

### 3.2 商业信号

| 项目 | 内容 |
|---|---|
| 定价模式 | 未知。可能是按表单/提交量订阅 |
| 官方收入 | 未找到官方披露 |
| 平台披露收入 | TrustMRR 显示 `Revenue $965`，推断约 `$965/月` |
| 推测收入 | 年化约 `$11,580/年`；无额外推测 |
| 置信度 | **中**。收入字段与 `3.5x` 倍数吻合，产品场景清楚，但定价和客户数未知 |
| 交易信号 | 售价 `$40k`，Multiple `3.5x` |

### 3.3 为什么可能赚钱
- **使用频率：** 中高。表单持续接收提交。
- **紧迫程度：** 高。表单坏了会直接丢线索。
- **预算负责人：** 开发者、建站代理、企业站点负责人。
- **切换成本：** 中。表单端点嵌入后，迁移需要改代码和验证邮件，不如作品集工具那么容易换。

### 3.4 产品逻辑与技术路径
**适合初学者的 MVP：** 提供一个表单 POST 端点，提交后转发到邮箱，后台可查看提交记录，带基础垃圾过滤和 Webhook。

**核心工作流：** 用户创建表单 → 获得 endpoint/嵌入代码 → 静态站点提交 → 服务端校验 → 存库 → 邮件通知 → 后台查看/导出。

**推荐技术栈：** Next.js API Routes 或 FastAPI + Supabase/Postgres + Resend/Postmark 邮件 + Stripe。垃圾过滤先用规则，再加 AI 分类。

**AI 用法：** 可选增强：垃圾提交分类、长回复自动摘要、按字段生成跟进邮件草稿。不要让 AI 挡住表单主流程。

**如果我来开发，最大难点：**  
**邮件送达率、垃圾提交和可靠性**。表单产品最怕“提交成功但邮件没收到”。还要处理滥用、限流、隐私合规和客户域名配置。AI 不是最大难点，基础设施才是。

**降低难度的捷径：**  
第一版只做“一个表单 + 邮件转发 + 后台记录”，不做复杂 builder。先服务 5 个使用 Astro/Next.js 的开发者，手动配置端点，验证他们最怕的是垃圾邮件、丢件还是导出麻烦。

### 3.5 适合 OPC 初学者的机会
- **更小众版本：** “AI 表单回复摘要器”——面向建站代理，客户提交 50 条反馈后自动生成周报和待办。
- **第一批访谈客户：** 独立建站开发者、Astro/Next.js  freelancer、小型代理商、本地服务商网站维护者。
- **1 周验证实验：** 做落地页 + 手动帮 5 个站点接入表单，收 $19/月；观察他们是否愿意为“防垃圾 + 摘要”多付钱。

## 6. 今日模式

**可复用洞察：**  
在交易市场里，能卖出倍数的小产品，往往不是“模型很先进”，而是把高频、杂乱、容易丢失的输入，变成**可导出、可复用、可审计的资产**。Carry 把 AI 对话变成 Markdown；Static Forms 把表单提交变成可靠记录；ShowcaseKu 把项目变成案例页。  
对个人创业者：**先找一个“用户已经在手动复制粘贴/手动整理”的窄工作流，再做自动化。** 收入绝对值小并不可怕，可怕的是工作流不具体、用户不愿重复使用。

   验证点：用户付费是为了“好看”还是“带来预约”。
