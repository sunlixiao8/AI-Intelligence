## 产品一：SiteJourney

**1. 产品**

- **名称：** SiteJourney（AI 类别，推断为网站用户旅程分析工具）
- **URL：** https://trustmrr.com/startup/sitejourney
- **类别：** AI / 网站分析
- **目标用户：** 需要理解访客行为和网站转化漏斗的中小企业站长、独立开发者、营销人员
- **备注：** 产品具体功能细节未在本次抓取的摘要中展示，以下分析基于 TrustMRR 的数据和产品名称推断，已尽量保守。

**2. 用户问题**

网站运营者最常问的问题是：用户从哪来？在哪个页面停留？为什么离开？哪里卡住？传统工具（Google Analytics 等）能告诉你有多少访客，但不会告诉你**"为什么"**。SiteJourney 这类 AI 分析工具的价值在于：把点击流数据自动总结成人类可读的结论——"来自 Pinterest 的用户抵达定价页后，在 FAQ 区停留后离开，可能对价格有疑问"。

这是一个反复出现、明确归因于业务收入的痛点。数据不会消失，需求是长期的。

**3. 商业信号**

- **定价模式：** 订阅制 SaaS（具体价格未知，TrustMRR 未给出）
- **月收入估算：** **约 $12,000 / 月（挂牌 MRR）**
- **置信度：** `高（挂牌）` —— 来自 TrustMRR 平台数据；但未经独立审计
- **证据：**
  - TrustMRR 挂售页显示：Revenue $12k，Price $400k，Multiple 2.8x
  - 链接：[https://trustmrr.com/startup/sitejourney](https://trustmrr.com/startup/sitejourney)
  - 按 2.8x 年收入倍数计算：$400k ÷（$12k × 12）≈ 2.78x，与页面一致，说明 Revenue 字段确实是月收入
- **增长/热度证据：** 该产品出现在 TrustMRR 首页 "Best deals this week" 区域，说明有活跃的买方关注

**4. 为什么可能赚钱**

- **使用频率：** 网站运营者每周甚至每天查看流量和转化数据，这是工作流的一部分，不是一次性需求。
- **紧迫程度：** 网站获客成本高，用户流失意味着真金白银损失。
- **预算负责人：** 市场负责人或创始人自己有预算，无需说服大型组织。
- **切换成本：** 一旦接入埋点并习惯 AI 日报/周报，更换工具需要重新部署代码，切换成本较高。

**5. 产品逻辑与技术路径**

- **MVP 范围：** 只做一个功能——"AI 每周网站旅程报告"，而不是完整分析平台。
- **核心工作流：**
  1. 用户在网站嵌入一段 JS 埋点脚本（或接入现有 GA4/Plausible 数据）；
  2. 后端接收事件（page_view、click、scroll_depth）；
  3. 数据库按 session 聚合用户路径；
  4. 定时任务（如每周一 9:00）提取关键事件，调用 LLM 生成自然语言总结；
  5. 通过邮件或仪表盘发送给用户。
- **推荐技术栈：** Next.js + Supabase（数据库）+ 一行 JS 埋点脚本 + OpenAI API + 定时任务（如 Vercel Cron 或 Trigger.dev）。
- **AI 模型用法：** 用 LLM 做**摘要生成**和**异常模式识别**（如某页面跳出率暴涨）。不应让 LLM 直接算数据，数据用 SQL 算好，LLM 只负责"解读"。
- **如果我来开发，会遇到的最大难点：**
  - **埋点数据准确性**：用户可能重复加载、机器人流量、隐私拦截；数据脏会导致 AI 结论错误，用户失去信任。
  - **事件流量的存储成本**：如果用户站点流量大，事件表会快速增长，Supabase 免费额度很快用完。
  - **LLM 输出可靠性**：模型很容易把噪声当成趋势，产生"幻觉洞察"。
- **降低难度的捷径：**
  - 第一版不做埋点 SDK，而是对接现有平台（GA4 导出、Plausible API），获取数据后只做"AI 解读报告"。
  - 不做实时分析，所有处理在夜间批量完成，降低成本与复杂度。
  - 人工给数据加上规则：只有超过设定阈值才允许 LLM 生成结论，否则不输出。

**6. 适合 OPC 初学者的机会**

- **可以切入的更小众版本：** "AI 网站异常周报"——只监控一个核心指标（注册转化率/付费转化率），当它环比变化超 15% 时自动生成一份分析报告。
- **第一批应该访谈的客户群体：** 月访问量超过 1 万但不到 100 万的中小网站主，尤其是独立电商、SaaS 落地页运营者。他们用不起昂贵的全渠道分析平台，但需要有人帮他们解读数据。
- **1 周验证实验：** 手动收集 10 个公开网站的流量数据（如公开发布的电商网站来源报告），用 GPT-4 生成"诊断报告"，发给 10 位潜在用户，问：这份报告洞察是否准确？愿意为每月的订阅花多少钱？（Telegram/微信里问即可，不需要做产品。）

- **可降低难度的捷径：** 不要一开始就做平台。从一个行业里的一个具体岗位切入，比如"帮助独立站电商客服自动处理退货申请"。

## 产品三：Wasabi: Multiplayer AI Party Games

**1. 产品**

- **名称：** Wasabi: Multiplayer AI Party Games
- **URL：** 产品详情页 URL 未在摘要中获取到，链接仅指向 TrustMRR 总站：[https://trustmrr.com/](https://trustmrr.com/)
- **类别：** Artificial Intelligence / 游戏 / 娱乐
- **目标用户：** 聚会场景的年轻用户（朋友聚会、家庭活动、线上派对）

**2. 用户问题**

聚会中常见的尴尬是"玩什么"。传统派对游戏需要道具、主持人，玩几次就腻了。Wasabi 这类产品用 AI 实时生成游戏内容（题目、猜词、情境、搞笑挑战），让每一局都不同，不需要准备任何物料。它解决的不是生存问题，而是**高频的社交娱乐需求**——周末聚会的人总需要点新东西。

**3. 商业信号**

- **定价模式：** 未知（推测为免费增值 + 房间解锁/点数购买，或一次性买断；仅为推测）
- **月收入估算：** **约 $4,300 / 月（挂牌 MRR）**
- **置信度：** `高（挂牌收入）`；定价模式与用户数为 `未知`
- **证据：**
  - TrustMRR 首页摘要：Wasabi: Multiplayer AI Party Games，Artificial Intelligence，Revenue $4.3k，Price $100k，Multiple 1.9x
  - 链接：[https://trustmrr.com/](https://trustmrr.com/)（产品页具体 URL 未在摘要中提供）
  - 按 1.9x 倍数计算：$100k ÷（$4.3k × 12）≈ 1.94x，与页面一致
- **增长/热度证据：** 该产品被挂售本身代表有真实收入；但 1.9x 倍数表明买方认为其增长潜力有限（可能依赖单个获客渠道或缺乏留存）。

**4. 为什么可能赚钱**

- **使用频率：** 低频，但社交裂变强——一次聚会可能有 5-10 人参与，其中可能有新用户被带入。
- **紧迫程度：** 低，但它属于"冲动型付费"产品：用户想玩的那一瞬间，愿意花几块钱解锁。
- **预算负责人：** 无预算审批，消费者个人决策，付费路径很短。
- **切换成本：** 低，但 AI 生成内容的丰富度是护城河——如果你的题库/玩法更新快，用户会复购。

**5. 产品逻辑与技术路径**

- **MVP 范围：** 一个 Web 版"AI 猜词"游戏——房主创建房间，其他玩家通过链接加入，AI 担任出题人和裁判。
- **核心工作流：**
  1. 房主建房，生成 6 位邀请码；
  2. 玩家扫码/输入邀请码加入；
  3. 游戏开始：AI 生成当前回合的题目（如"你是一位外星人，向地球人解释人类最奇怪的习惯"）；
  4. 玩家提交答案 → AI 根据规则评分（或全场投票）；
  5. 积分榜，下一轮。
- **推荐技术栈：** Next.js + Tailwind CSS + Supabase（聊天/状态同步用 Realtime 或直接轮询）+ OpenAI API。实时通信第一版用简单的轮询或 Supabase Realtime 就够，不上 WebSocket。
- **AI 模型用法：**
  - **生成**：题目生成、答案评判；
  - **分类**：玩家答案是否属于敏感内容（简单关键词过滤即可，不必用模型）；
  - 不要试图让 AI 理解幽默，AI 生成题目后，评判交给玩家投票。
- **如果我来开发，会遇到的最大难点：**
  - **AI 延迟**：如果等待 AI 生成题目要 5 秒，游戏质感就毁了。解决：在每轮进行时，预生成下一轮的 3 道题；或先调用 LLM 批量生成 20 道题，游戏从题库中取。
  - **多人实时状态同步**：房主加入/离开、断线重连、回合状态一致性，这些是传统前端开发不会遇到的问题。
  - **内容合规**：AI 可能生成不合适的内容，尤其是面向未成年人的场景，需要前置过滤。
- **可降低难度的捷径：**
  - 第一版不做实时多人，做"单人挑战模式"——AI 连续出 10 题，用户看自己能得多少分，做完后可分享成绩到社交媒体。验证 AI 题目质量和趣味性，然后再加多人房间。
  - 使用现成游戏框架（如 PartyKit、Liveblocks）处理房间状态，而不是自己从零搭。

**6. 适合 OPC 初学者的机会**

- **可以切入的更小众版本：** "AI 跑团主持人"（AI Dungeon Master）——为桌面角色扮演游戏玩家生成剧情、NPC 对话、战斗奖励；或"AI 酒桌游戏"——面向 25-35 岁聚会人群的真心话问题生成器。
- **第一批应该访谈的客户群体：** 20-30 岁、每两周至少组织一次朋友聚会的人；剧本杀/密室逃脱店内等待区的顾客；线上游戏 Discord 社群管理员。问他们：最近一次聚会玩什么游戏？谁负责想游戏？好玩的标准是什么？
- **1 周验证实验：** 用 Typeform 或微信问卷做一个小测试——生成 10 道 AI 派对立题，发到 3 个微信群，是否有人愿意转发？转发率超过 30% 再做产品。

**4. 为什么可能赚钱**

- **使用频率：** 每次 API 调用都在发生，是持续性的成本。
- **紧迫程度：** 高——对 AI 重度用户（每日调用量百万级），API 费用是最大成本项，省 30-70% 直接改善毛利。
- **预算负责人：** CTO 或技术负责人有明确的预算决策权，KPI 明确（降本增效）。
- **切换成本：** 高——一旦接入了 Finest 的路由层，替换它需要改所有代码里的 base URL，这是它的护城河。
- **风险：** "模型路由"会让请求质量不稳定（用便宜模型处理复杂任务可能输出变差），这类产品的最大阻力是客户担心质量下降。广告语 "No drop in quality" 正是针对这一恐惧。

**5. 产品逻辑与技术路径**

- **MVP 范围：** 一个"LLM API 代理网关"——接受 OpenAI 格式请求，按规则转发到不同的模型，并记录节省金额。
- **核心工作流：**
  1. 客户把 base URL 改为 Finest 提供的地址（不需要改代码）；
  2. Finest 收到请求，解析参数（模型名、任务类型、优先级）；
  3. 路由决策：简单任务 → 便宜模型；复杂任务 → 贵模型；相同或相似请求 → 直接走缓存；
  4. 记录每个请求的模型、token 数、延迟、成本，生成仪表盘和每周成本报告。
- **推荐技术栈：** FastAPI（或 Node.js）+ Redis（缓存/限流）+ Supabase（用量记录）+ OpenAI/Anthropic Python SDK。部署用 Railway/Render 都可以，第一版不需要 K8s。
- **AI 模型用法：**
  - **路由决策**：可以用一个小的分类模型（如 GPT-4o-mini）判断请求是"简单摘要"还是"复杂推理"，然后路由到不同模型；
  - **缓存**：用 embedding 计算请求相似度，命中阈值以上直接返回缓存结果。但这会增加延迟和成本，第一版建议只做**精确缓存**（完全相同的请求）。
- **如果我来开发，会遇到的最大难点：**
  - **质量问题**：如果用户发现某个请求被路由到便宜模型导致输出变差，流失是瞬间的。需要建立完善的监控和回退机制（检测到失败/低置信度，自动重试贵模型）。
  - **缓存安全性**：LLM 输出不能盲目缓存（比如包含用户私有数据），如何设计缓存 Key 和数据隔离是一个隐藏难点。
  - **成本优化效果验证**：你自己先得有足够的调用量来测试路由策略，否则客户不信你。鸡生蛋问题：产品需要大量流量才能证明价值，但没有客户就没有流量。
- **可降低难度的捷径：**
  - 第一版不做路由，只做**AI 账单监控 + 预算告警**。帮客户看清楚：钱花在哪个模型、哪个功能、哪个部门。这个产品本身有付费意愿，且不需要承担质量风险。
  - 缓存先做"相同请求"（如日报模板、Prompt 固定的摘要任务），不做语义缓存。

**6. 适合 OPC 初学者的机会**

- **可以切入的更小众版本：**
  - "AI 账单体检"服务：手动（或半自动）分析用户的 OpenAI/Anthropic 账单，生成一份节约建议报告，付费按次或按年。一份报告收费 $199。
  - 针对特定任务的 API 网关插件：比如"翻译专用 API 网关"——自动选择最便宜的翻译模型（DeepL、GPT、Claude 之间切换），以翻译行业为目标客户。
- **第一批应该访谈的客户群体：** 公司里亲自管理 AI 成本的开发负责人（每日调用量超过 10 万次的团队）；AI 创业公司的 Co-founder/CTO；在 Indie Hackers 上讨论 API 成本的独立开发者。
- **1 周验证实验：** 写一篇 Twitter/X 帖子："我接入了 3 个 LLM 模型，把我们的 API 账单降低了 60%，下面是方法。" 给前 20 位私信的人免费出一份「账单优化报告」，看多少人回。如果有 10 人回复，说明需求真实存在。

## 今日模式

### 模式 1：AI 产品存在真实的"退出通道"，但倍数差异巨大

TrustMRR 今天挂售的 AI 产品中，倍数从 1.9x（Wasabi）到 5.0x（Laper）不等。差别不在 AI 技术本身，而在**收入质量**：客户是否集中、增长是否可持续、团队是否可替代。对 OPC 来说，这意味着从第一天就不要做"一个聪明的 AI 玩具"，而是做"一门有客户、有收入、可交接的生意"。

### 模式 2："省钱"比"赚钱"更容易卖

Finest 告诉你"我能帮你省 70% 的 API 费用，省不到不收费"。这种卖点不需要解释 ROI，因为 ROI 是计算出来的，不是讲出来的。凡是能**直接量化节省金额**的产品，销售阻力最低。对个人开发者，最容易切入的也是"成本优化"类工具——因为你不需要海量数据，只需要聪明的对比和路由逻辑。

### 模式 3：消费者 AI 产品可以小而美，但天花板清晰

Wasabi 以 $4.3k MRR 卖 $100k。对 OPC 来说，这是很现实的一笔钱。消费者 AI 产品（游戏、娱乐、图片工具）通常开发周期短、获得第一批用户容易，但留存和瓶颈也明显。如果你是初学者，建立一个这样的项目，既练技术又可能带来额外收入（哪怕是 $500/月），是一个比"做出下一个大平台"更务实的目标。

## 建造雷达

受今天产品启发的 2-3 个可以立刻着手的小产品想法：

1. **AI 窗帘/家居可视化工具（灵感来自 TrustMRR 挂售的 "AI curtain visualizer" app：$581 MRR、69 订阅者）**
   - 用户上传房间照片 → AI 把不同窗帘/地毯/配色 P 上去 → 分享给家人/朋友决策。
   - 为什么适合 OPC：单一功能、AI 视觉 API 可以直接调用、目标用户群（装修的人和家居电商）付费意愿存在。
   - 第一版可以在 WhatsApp/微信里用机器人实现，用户发照片就返回带新家具的效果图，不做 App。

2. **"AI API 账单体检"微工具（灵感来自 Finest）**
   - 用户上传 Cloudflare/OpenAI 导出的账单 CSV → 工具分析出：哪个模型最贵、哪个功能调用最多、推荐切换哪个模型可省多少 → 生成一页 PDF 报告。
   - 定价：免费生成基础报告，$19 解锁完整优化建议。
   - 为什么适合 OPC：不需要接入任何系统，不用处理数据隔离，验证人们对"省钱"的付费意愿。

3. **"AI 出题机"网页版（灵感来自 Wasabi）**
   - 面向酒吧聚会、团建组织者的 AI 游戏题目生成器：输入主题（"90 后怀旧""程序员冷笑话"）→ 生成 20 个适合多人玩法的问题 → 一键打印或投屏。
   - 定价：免费 5 题，$1.99 买断一个主题包。
   - 为什么适合 OPC：模板化开发，一次做好 10 个模板，后续只做内容维护。

## 用户访谈问题

如果你是 OPC 初学者，今天就可以用这 3 个问题去验证一个新的产品想法。适合用来访谈你周围的潜在用户（网站站长、开发者、聚会组织者）：

**问题 1：**
> "在过去一周里，你花在【某件重复性任务】上的时间有多少小时？如果有一个工具能自动完成 80%，你觉得你是会立刻用，还是觉得风险太大不敢用？为什么？"

—— 这个问题区分"愿意付费的痛"和"随口说说的痛"。

**问题 2：**
> "你现在为了解决这个问题，用的是工具、外包、还是人工？你每个月为这个方案支付多少钱？"

—— 了解用户当前的替代方案和预算基线。如果答案是"没花钱"，后面需要更谨慎验证付费意愿。

**问题 3：**
> "如果这个工具让你每个月省下 X 个小时（或者省下 Y 元），你觉得多少钱你愿意付？如果你不愿意付，最可能的原因是效果不放心，还是价格贵？"

—— 最直接的需求和价格锚点测试。参考 Finest 的教训：人们不只是担心价格，而是担心**质量下降**。问出这个顾虑，你就知道产品最关键的设计目标是"质量确定性"而不是"便宜"。
