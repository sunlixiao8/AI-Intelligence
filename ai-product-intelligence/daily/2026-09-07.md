## 1. Agentency —— 挂在货架上最便宜的 AI SaaS

### 产品

- **名称**：Agentency
- **URL**：https://trustmrr.com/startup/agentency
- **类别**：SaaS（TrustMRR 分类），评分原因标注与「AI / 自动化」相关
- **目标用户**：推测是数字营销机构、自由职业者或小型增长团队；名称由 Agent + Agency 组成，像「AI 代理驱动的营销机构工具」
- **功能证据**：**低置信度**。本次只能看到 TrustMRR 列表本身，没有官网、截图或评论。

### 用户问题

如果产品定位与名称一致，它大概想解决的问题是：小型营销机构或独立接案者需要同时处理大量重复性事务——SEO 外链、内容发布、客户报告、社交运营。雇人太贵，自己做太花时间，于是希望有「AI 代理」来跑一部分工作流。

用户愿意付费的动机不是「AI 很酷」，而是「省掉一个兼职员工的工资」。

### 商业信号

- 定价/用户数：未知，未抓取到任何定价页面或用户评价。

### 为什么可能赚钱

如果做成「AI 自动完成本来要请人做的活儿」，这类工具的替换价值很强。一个助理月薪可能 $500–$2000，一个机构老板很容易算清这笔账。

但要注意：**$23/月收入说明这个版本还没有跑通销售和留存，或者说它只是一个早期未验证的产品**。$1k 的挂牌价主要价值不在利润，而在「代码 + 域名 + 已有一点点收入记录」的资产包。真正能学习的点在于：

- 一个几乎不赚钱的 AI 杂务工具，在二手 SaaS 市场上大概值多少钱。
- 愿意花 $1k 买的人，大概率不是为了 $23/月收入，而是想省开发时间。

### 产品逻辑与技术路径

由于产品细节不足，**在抄它之前你应当先做“线索验证”**：

1. 直接联系卖家，要一个演示视频或测试账号。
2. 问清楚：$23 是哪个月收入？有没有连续 3 个月记录？
3. 看它到底绑定了哪些外部工具 API——通常是 OpenAI、Google Search、社交媒体平台等。

**如果让我开发一个类似形态的 MVP：**

- 核心工作流：用户输入一个任务目标（例如「为某客户生成 10 篇 SEO 外链文章并发布」）→ AI 拆解成子任务 → 调用外部工具 API 执行 → 输出非常简单的任务看板。
- 推荐技术栈：Next.js + Supabase + Stripe/Lemon Squeezy；AI 部分用 OpenAI/Claude API，通过函数调用或带工具的 Agent 模式。
- 第一个版本不要做“通用的 agent”，只做一条固定工作流：比如「自动抓取客户网站新博客 → 生成 3 条 LinkedIn 帖子 → 存入数据库工审核」。

**我开发时会遇到的最大难点：**

AI Agent 在多步骤任务中很容易跑飞。实际执行涉及大量 API 鉴权、错误处理、重试、权限问题，比写一个生成文案的单页工具复杂得多。而且用户无法信任全自动执行，必须有「人类确认关卡」。

**降低难度的捷径：**

第一版不追求自动化率 100%，做「半自动队列」：AI 把活拆好，用户在页面里点“执行”“修改”“跳过”，确保每一步可控。这样既保留了自动化的价值，又不至于因为一个 API 挂了就整个流程崩溃。

### 适合 OPC 初学者的机会

- 更小的切口：不做全流程 AI 代理，而是专做「某一种客户的某一个具体任务」，比如「小红书/Instagram 竞品分析周报自动生成」。
- 第一批访谈对象：独立营销顾问、小型代运营工作室老板。
- 1 周验证实验：用手动流程模仿产品——手动替 5 个潜在用户做一次「竞品内容周报」，观察他们是否愿意每周付 $20–50。如果 5 个人里有 2 个愿意付钱，再开发。

## 2. MagicSlides.app —— AI 幻灯片工具里的“现金牛”样本

### 产品

- **名称**：MagicSlides.app（TrustMRR 分类为 Artificial Intelligence）
- **类别**：AI 文档 / 演示文稿生成工具
- **目标用户**：学生、老师、营销人员、咨询顾问
- **功能证据**：**中等偏低**。本次没有抓取到官网详情；从名称与同类产品逻辑推断，核心能力大概率是「根据文本、PDF、YouTube 视频链接等输入自动生成 Google Slides / PowerPoint」。
- **来源**：https://trustmrr.com/ 页面内搜索 `MagicSlides.app`（2026-09-07 快照中「Best deals this week」区域）

### 用户问题

做演示文稿是一线职场和个人创业者都高频遇到的“必要之恶”。一个 20 页的 PPT 手动做需要 2–4 小时，过程中最痛苦的并不是打字，而是「把大段文字整理成每页 3 条要点、找到合适的结构、选模板、排排版」。

用户愿意付费的核心原因：**时间省下一大片，且成果直接用于工作汇报或客户提案，价值可被看到。**

### 商业信号

- 月收入估算：`$9,000–$10,000/月`（TrustMRR 列表显示 $9.7k）
- 置信度：`中`
  - 证据：TrustMRR 是把这些数字用于交易定价，不是拍脑袋榜单。但卖方申报数据不排除美化可能，且没有提供退款/流失数据。
  - 标价 `$500k`，Multiple `4.3x`，倒推年收入约 $116k，与 $9.7k × 12 = $116.4k 基本一致。可以推断「$9.7k」是月收入口径。
- 定价模式：未知。推测是订阅 + 积分模式：免费额度很少，付费后按月获得若干次生成点数；可能有按导出幻灯片数量计费。
- 增长证据：TrustMRR 把它列为「本周好交易」，没有流量、评价、用户数等数据。所以它到底靠 SEO、YouTube 教程还是 Product Hunt 起量，**未知**。

### 为什么可能赚钱

- 使用频率：对于一类人（老师、咨询顾问、线上课程创作者）是每周或每月刚需。
- 紧迫程度：工作要交付时很急，用户愿意为时效付费。
- 预算负责人：个人自己能决定购买，不需要走复杂采购流程。
- 切换成本：如果产品允许用户保存自己的模板和品牌色，用户会更愿意留下。但大多数 AI PPT 工具的留存弱，因为用户「做完一次就走了」。

这就是它可能达到 $9.7k/月但在二手市场仍然只卖 $500k 的原因之一：**收入看起来不错，但不一定稳定、留存和利润未知。** 对学 AI 产品的人来说反而是好样本：不必做出一款「改变世界」的产品，只要抓住一个高频低难度场景，也能做出真实收入。

### 产品逻辑与技术路径

**核心工作流（推测，按同类产品逻辑）：**

1. 用户输入主题、粘贴文档、上传 PDF，或粘贴 YouTube 链接。
2. 后端先抽取文本（如果是视频，先用 Whisper 类模型转文字）。
3. LLM 把内容总结成 8–15 页幻灯片结构。
4. 每一页用模板渲染成适合展示的卡片或幻灯片页面。
5. 导出为 PPTX，或写入用户的 Google Slides。

**推荐技术栈：**

- 前端：Next.js + Tailwind CSS
- 数据库/支付：Supabase + Stripe 或 Lemon Squeezy
- 后端：Next.js API Routes 或 FastAPI
- LLM：OpenAI API 或 Claude API，核心是「结构化 JSON 输出」，让模型返回每页标题、要点、演讲备注。
- 导出：PPTX 用 `pptxgenjs`；如果要做 Google Slides，需要接入 Google Slides API。

**AI 模型用法：**

不是让 AI 写一大段文章，而是让 AI 做「结构化拆分」：

- 输入原始内容
- 输出 `pages: [{title, bullets[], imagePrompt?, speakerNotes}]`
- 再由代码把数据填充到 PPTX 模板中

**我开发时会遇到的最大难点：**

1. **“AI 生成的 PPT 很丑”**。模型只能生成文字结构，漂亮需要模板。自己做高质量模板很难，买商业模板又涉及授权。
2. **PPTX 导出兼容性问题**。不同 PPT 版本、字体、版式很容易乱。
3. **Google Slides API 的配置成本很高**。OAuth、权限、上传模板、批量创建页面，第一次跑通要花至少半天到一天。
4. **单次生成成本不低**。一次生成 12 页可能需要多次模型调用，如果不做缓存和限额，很容易被薅羊毛。

**降低难度的捷径：**

第一版尽量不要碰 Google Slides 的 OAuth。先做成网页内的「预览 + 导出 PPTX 文件」，用户下载后在本地打开。这会把开发时间缩短一半以上。

内容来源也可以收窄：先只做一个输入类型，比如「粘贴 YouTube URL → 生成幻灯片」。YouTube 转文字是一个具体且痛感明确的需求，比泛泛地「用 AI 做 PPT」更容易传播。

### 适合 OPC 初学者的机会

- 更小众的切入：给「在线课程讲师」做「课程视频一键变讲义 PPT」；或者给独立顾问做「客户会议记录 → 提案 PPT 初稿」。
- 第一批访谈对象：大学老师、企业培训师、经常要做月度汇报的运营。
- 1 周验证实验：手动用 ChatGPT + 模板帮 3 个目标用户做一份真实 PPT，看他们是否愿意付费，并记录完成一份需要多长时间。

## 3. AutoReels.AI —— 卖“短视频体力活”的自动化工具

### 产品

- **名称**：AutoReels.AI
- **类别**：Artificial Intelligence（TrustMRR 分类），推测是 AI 短视频生产/再创作工具
- **目标用户**：需要持续发布 Instagram Reels / TikTok / YouTube Shorts 的个人博主、小企业主、代运营团队
- **功能证据**：**低**。未能抓取到官网功能；从名称判断，核心价值是把一个长素材或主题自动变成多条竖屏短视频（Reels）。

### 用户问题

短视频运营的痛点不是“不知道拍什么”，而是**“持续产出 + 剪片 = 每天耗 2 个小时”**。小商家、顾问、教练往往是本人出镜或提供素材，但没有团队帮他们做选题、字幕、剪辑和文案。

如果工具能自动把 1 条长视频切成 5 条竖屏片段、配上字幕和标题，并给出发布文案，用户就很愿意付月费。

### 商业信号

- 月收入估算：`$1,000–$1,200/月`（TrustMRR 显示 $1.1k）
- 置信度：`低`
- 证据：TrustMRR 2026-09-07 快照显示 `AutoReels.AI / Artificial Intelligence / Revenue $1.1k / Price $55k / Multiple 4.3x`。按 4.3x 倒推年收入约 $56.7k，与 `$1.1k × 12 = $13.2k` 不一致，和 `$55k ÷ 4.3 = $12.8k` 接近。这里存在明显口径疑问，可能收入有波动；**收入细节只能确认到“约 $1k/月量级”，置信度低**。
- 增长证据：未知。

### 为什么可能赚钱

短视频代运营市场非常成熟：

- 一家本地餐厅或房产中介如果意识到需要持续发短视频，外包一条视频约 $30–100/条。
- AutoReels 类的工具如果能做到“输入素材，输出可发视频”，可以以 $29–79/月售卖。
- 对用户来说，AI 剪得可能不够精致，但便宜、快、量大。对“保持日更”和“测试不同内容方向”来说够用。

**为什么只赚到 $1.1k/月：**

这类工具供给已经很多，同质化严重；而且纯生成的视频往往缺少真实人格感，很难真正「代替人」。$1.1k/月大约对应 20–40 个付费用户，更像「还没突破临界点」的产品。

### 产品逻辑与技术路径

**核心工作流（推测）：**

1. 用户上传一段视频素材或一个 URL。
2. 系统转文字、识别高能片段、切分。
3. AI 重新组织脚本：例如 3 秒钩子 + 5 个信息点 + 1 个 CTA。
4. 加字幕、表情或简单转场。
5. 导出不同比例（9:16、1:1、16:9）和不同时长版本。

**推荐技术栈：**

- 前端：Next.js；上传用 Supabase Storage。
- 视频转文字：Whisper API 或本地的 faster-whisper。
- 脚本生成：GPT-4.1 mini / Claude Haiku，重点是把字幕时间轴对齐。
- 视频渲染：
  - 简单版：FFmpeg 烧录字幕。
  - 进阶版：Remotion（用 React 做视频），适合需要自定义动画的场景。
- TTS：若需要 AI 配音，可用 OpenAI TTS / ElevenLabs；但价格会更贵。

**AI 模型用法：**

不是用视频生成模型，这个产品“生成”的主力是**剪辑决策**——判断哪句话值得保留、哪里该切、字幕怎么断句。真正重要的技术其实是“字幕时间轴 + 断句”的处理。

**我开发时会遇到的最大难点：**

1. **视频处理耗 CPU/GPU 和钱**。即使只用 FFmpeg，长时间任务的队列、超时、失败重试都要处理。
2. **字幕断句不自然**。AI 生成的字幕如果每行太长，观感很差；需要按语义断句，这是打磨点。
3. **批量生成的产品容易“一眼 AI”**。模板感重，用户做完两条就不想用了。
4. **自动发布到平台 API 很受限**。Instagram/TikTok 官方 API 不允许完全自动发布，平台风控很严格。第一版最好只输出「草稿 + 一键复制文案」，不要做自动发布。

**降低难度的捷径：**

更简单的第一版：**不做视频剪切，只做「字幕版图文视频」**——用户提供一句观点或一段故事，系统自动生成一张动态背景图 + AI 语音朗读 + 字幕条。当年很多涨粉账号靠这种极低成本视频起量。

### 适合 OPC 初学者的机会

- 更垂直的场景：给「本地餐馆」做「每周一条菜品短视频」；给「保险/地产销售」做「个人观点口播短视频」。
- 第一批访谈对象：正在试着自己做短视频但没有团队的小企业主。
- 1 周验证实验：你自己手动用 CapCut 帮一个本地商家剪 3 条视频，问他们如果有一个按月付费的工具能自动完成 60% 的工作，他们付不付钱。

## 4. Search1API —— 给 AI 产品卖搜索能力

### 产品

- **名称**：Search1API
- **类别**：Developer Tools / API
- **目标用户**：正在开发 AI Agent、ChatGPT 外挂、研究类产品的开发者
- **功能证据**：**偏低**。本次没有 API 文档/官网摘要；从 TrustMRR 将它归类为 Developer Tools，以及名称中的 “Search1API” 推断：这是一个把「联网搜索能力」封装成 API 卖给 AI 应用开发者的服务。
- **来源**：https://trustmrr.com/ 页面内搜索 `Search1API`（2026-09-07 快照中「Best deals this week」区域）

### 用户问题

现在很多 AI 产品需要回答实时问题。例如：

- 「帮我查一下今天深圳有哪些展会」
- 「这家公司是不是刚拿到了融资？」

但 OpenAI、Claude 的模型训练数据不是实时的。开发者自己实现联网搜索很难：要么接 Google 搜索 API 但贵、配额复杂；要么写爬虫但容易被封、要维护网页解析逻辑。

这类 API 产品的价值是：**开发者调一个接口，就能拿到干净的搜索结果，省去自己处理搜索后端的时间。**

### 商业信号

- 月收入估算：`$1,200–$1,400/月`（TrustMRR 显示 $1.3k）
- 置信度：`低到中`
- 证据：TrustMRR 列表 `Search1API / Developer Tools / Revenue $1.3k / Price $50k / Multiple 3.2x`。`$50k ÷ (3.2 × 12) ≈ $1.3k`，与显示的 $1.3k 完全吻合。这说明列表里的收入口径与 MRR 一致的概率较高；但仍属于卖家申报，未独立审计。
- 定价模式：推测是预付费 + 按量计费，开发者先在账户充值，用一次扣一次。具体价格未知。

### 为什么可能赚钱

开发者工具的独特优势：

- 开发者一旦把 API 接入自己的产品，**只要他们的产品活着，就会持续调用**。
- 按量计费会随客户成长自动增长，不需要销售团队。
- API 如果足够稳定，用户切换成本高；但反过来，API 也是最容易被替换的——客户只需要改几行代码。所以必须有“稳定的质量 + 合理的价格 + 简单的接入体验”。

**为什么只做到 $1.3k/月：**

开发者工具需要写大量文档、处理各种崩溃错误、做故障报告，而且价格大战激烈。这个收入规模说明它可能刚起步，还没有进入显著增长期。

### 产品逻辑与技术路径

如果做同类产品，核心不是「调用模型」，而是：

1. **搜索部分**：对接到某个搜索服务商（Bing、Brave Search、自建爬虫）。
2. **提取正文部分**：抓取搜索结果页面，把 HTML 清洗成干净的 Markdown 或纯文本。
3. **缓存去重**：相同 query 短时间内不要重复抓取，控制成本。
4. **接口格式**：让 AI 开发者最容易接入——通常只需要一个 OpenAI 兼容格式或简单 REST API。

**推荐技术栈：**

- FastAPI（Python）做一个稳定的 API 网关，比 Next.js 更适合纯后端 API。
- 缓存用 Redis 或 Postgres。
- 异步爬取任务用队列（比如 BullMQ 或 Celery）。
- 计费系统用 Stripe，或更简单的 Postgres 余额表 + 定时扣费。

**AI 模型用法：**

在这类产品里，LLM 不是主角。最多用 LLM 做「查询改写」「结果摘要」「判断当前搜索结果是否相关」。更核心的能力是检索质量和速度。

**我开发时会遇到的最大难点：**

- **上游成本和稳定性**：如果你自己爬搜索引擎，很容易被封 IP；如果用官方搜索 API，成本又高，利润会非常薄。
- **解析质量**：网页 HTML 千奇百怪，转成干净的正文需要很强的清洗脚本。
- **可靠性 SLA**：API 服务要求 99.9% 可用，凌晨 2 点也得有人处理故障，对个人创业者压力大。

**降低难度的捷径：**

不要学它做通用搜索 API，更不要试图自己爬 Google。第一版可以：

- 申请 Bing Web Search API 的免费额度（每月限额内免费）。
- 只针对垂直领域，例如「科技公司新闻」或「招聘信息」。
- 封装成「给 ChatGPT 用的实时搜索 Plugin」。

如果想做商业化，更聪明的做法是**把搜索能力打包成垂直产品**，而不是卖通用 API。比如做「外贸开发信里自动查客户公司背景并给出个性化开场白」的小工具，而不是让用户自己接 API。

### 适合 OPC 初学者的机会

- 更小的产品切口：面向「独立开发者做 AI 简历助手」提供「招聘职位数据查询 API」；或面向「外贸 SaaS」提供「企业联系人 + 新闻动态 API」。
- 第一批访谈对象：正在做 AI Agent 产品的独立开发者、需要少量联网搜索能力但不希望自己接搜索服务的个人开发者。
- 1 周验证实验：去相关开发者社区发一帖：「我正在做一个中文搜索 API，免费送 1 万次调用，谁愿意当种子用户？」看有多少人注册，并从中访谈 3 个人。

## 🧭 今日模式

> **AI 产品的钱，不在“生成内容”这一下，而在“帮用户省掉一个固定岗位/外包动作”上。**

MagicSlides.app 卖的是节省 2–4 小时的 PPT 制作；AutoReels.AI 卖的是每天省掉 1 小时剪辑；Agentency 卖的是省掉一个营销助理；Search1API 卖的是省掉一位爬虫工程师。

同样是调用大模型，为什么有的只能免费引流、有的能收到订阅费？因为付费意愿来自**用户已经在自己花钱或花时间解决这件事**，而不是“AI 很新鲜”。

## 🔨 建造雷达（受本期启发的小产品想法）

1. **「AI 提案单页」工具**  
   面向独立开发者和自由设计师：输入客户需求 + 自己的服务与价格，一键生成一份可分享的网页版 Proposal，并附带「在线确认 + Stripe 收款链接」。  
   切的是「报价单和合同跟进」这个具体痛点，比通用提案工具更容易起步。

2. **「播客切片工厂」**  
   用户上传一期播客音频或一段直播回放，AI 自动选出 5 个最有话题性的 30–60 秒片段，生成字幕、标题、文案，输出可编辑的剪辑草稿。  
   第一版用最简单的方式：只给文字摘要和字幕结果，不做视频渲染，让用户去剪映或 CapCut 里一键成片。

3. **「本地商家 AI 内容月包」**  
   做一个小仪表盘：小商家提供几张照片与一句话业务介绍，系统每周自动生成 3 条小红书/Instagram 帖子 + 回复客户评论的草稿。  
   模式参考的是 AutoReels 的代运营替代逻辑，但只做「图文 + 文案」，不做视频，技术门槛更低。

## 🎤 用户访谈问题（可以直接用）

以下问题适合去访谈「正在自己运营内容的商家 / 正在做咨询和方案的自由职业者」：

1. **“过去一周里，你在做 XX（PPT / 短视频 / 客户跟进）这件事上，总共花了几个小时？如果 AI 能帮你省掉一半时间，你愿意每月付多少钱？”**  
   ——先问时间和金钱，不要先问“你需不需要 AI”。

2. **“你以前试过哪些 AI 工具？是哪一点让你最终没用下去？”**  
   ——大多数答案是「效果不行」「太麻烦」或「没有真的省时间」。只有找到真实放弃原因，才能做出差异点。

3. **“假设我做出一个工具，效果只有人工做的 70%，但速度快 10 倍、价格只要人工的 1/5。你会拿它来做什么？在什么情况下这个工具反而让你不敢用？”**  
   ——这个问题能逼问出「付费场景」和「信任障碍」两件事。
