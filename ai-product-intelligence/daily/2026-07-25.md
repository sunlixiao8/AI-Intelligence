- **类别：** AI / 开发工具
- **目标用户：** AI 工程师、数据科学家、学生和研究者，需要测试和比较不同大语言模型（LLM）性能的人群。

- **用户问题：**
    - **具体问题：** 在选择或替换 AI 模型时，开发者需要快速、标准化的基准测试来了解不同模型在推理、编码、逻辑、安全性等方面的具体表现。手动测试既费时又难以标准化。
    - **付费动机：** 用户需要节省评估模型的时间，确保项目选择的模型最优，避免部署成本或性能损失。这不是好奇心驱动，而是效率和工作质量驱动的需求。

- **商业信号：**
    - **定价模式：** 未知。TrustMRR 没有列出具体的定价细节，可能是按 API 调用付费或订阅制。
    - **月收入估算：**
        - **官方收入（高置信度）：** 根据 TrustMRR 交易页面，其 **月经常性收入 (MRR) 为 3,500 美元**。来源：TrustMRR 市场公开列表（日期：2026-07-25）。
    - **增长或牵引力证据：** 正在 TrustMRR 市场上以 **119,000 美元** 的价格出售，倍数约为 MRR 的 2.8 倍。这本身就是一个很强的商业信号——它通过了市场和买家的初步验证。有买家愿意以这个价格购买，意味着其用户和收入流是有价值的。

- **为什么可能赚钱：**
    - **使用频率：** 中低频，但每次使用价值高。开发者在选型或发布新功能时会高频率使用。
    - **紧迫程度：** 高。对于正在构建 AI 应用并需要做出模型选择的团队来说，这是一个关键的决策支持工具。
    - **预算负责人：** 开发团队的技术负责人或架构师。
    - **切换成本：** 中等。一旦团队习惯使用特定平台的基准报告和 API，切换会涉及重新学习和集成，形成一定的粘性。

- **产品逻辑与技术路径：**
    - **适合初学者的 MVP 范围：** 一个功能聚焦的基准测试平台。专注于支持 5-10 个最流行的开源或闭源模型，并提供 3-5 种核心评测（如：通用问答、代码生成、逻辑推理）。
    - **核心工作流：**
        1.  用户选择测试模型和测试数据集。
        2.  系统并发地向选定的模型 API 发送预设的测试请求。
        3.  系统接收并评估模型输出（准确性、速度等）。
        4.  生成并排对比报告。
    - **需要的数据或输入：** 公开的基准测试数据集（如 MMLU, HumanEval, GSM8K）、目标模型的 API Key。
    - **推荐技术栈：**
        - **前端：** Next.js + React + Tailwind CSS
        - **后端：** Next.js API Routes 或 FastAPI
        - **数据库/认证：** Supabase
        - **支付：** Stripe
        - **AI：** OpenAI, Anthropic, Google, 以及各种开源模型的 API。
        - **任务调度：** 使用队列系统（如 BullMQ）来管理并发的 API 调用。
    - **AI 模型用法：**
        - **核心功能：** 需要调用各种 AI 模型的 API 以进行“评测”，而非生成内容。重点是**编排**和**评估**。
    - **如果“我”来开发，会遇到的最大难点：**
        - **保证基准测试的公平性和准确性：** 不同模型的 API 参数、定价模式、速率限制不同。必须设计一个标准化的测试流程，确保测试结果（如速度、成本、性能）是可复现和可比较的。控制变量是难点。
        - **评估的自动化与可靠性：** 如何用另一个 AI 模型（如 GPT-4）来评估测试模型的输出是否准确和优质？这被称为“评估的评估”，本身就是一个开放性问题，容易出现偏差。
    - **可降低难度的捷径或更简单的第一版：**
        - **不做自动化评估，只做数据展示。** 首版可以只做“测试执行器”。用户提交一段文本和要测试的模型列表，系统调用多个 API 返回原始结果。让用户自己判断好坏。这降低了技术门槛，但产品价值也相应降低。
        - **只做一个垂直领域的基准测试。** 比如，只做“代码生成”领域的基准测试，并且只聚焦于测试 AI 生成的代码是否能通过预设的单元测试。这样评估标准非常明确。

- **适合 OPC 初学者的机会：**
    - **切入更小众的版本：** 专注于一个具体行业，如“法律合同 AI 总结模型的基准测试”或“简历解析 AI 模型的基准测试”。这个垂直市场的用户（法务部门、HR）付费意愿可能更强。
    - **第一批应该访谈的客户群体：** 在 Upwork 或 Freelancer 上的 AI 开发者、中小 AI 公司的 CTO、正在为学校或公司选择 AI 平台的负责人。
    - **1 周验证实验：**
        1.  手动调用 3 个主流模型的 API（如 GPT-4, Claude 3, Gemini）。
        2.  对同一个测试问题（比如“写一个 Python 函数排序字典”）收集它们的输出。
        3.  制作一个简单的对比表格（可以是 Notion 或 Google Sheet），展示给 5-10 位目标用户，问他们：“如果能自动生成这个表格，你愿意每月付 20 美元吗？”

    - **预算负责人：** 婚礼策划师、品牌营销预算或新人直接支付。
    - **切换成本：** 较低。客户可能根据不同的婚礼风格选择不同的工具，但优秀的模板库和易用性是壁垒。

        2.  用户在表单中填写婚礼信息。
        3.  AI 根据模板和信息生成定制化设计。

    - **需要的数据或输入：** 大量的婚礼设计素材（用于训练的合法图像/模板，例如从 Unsplash 或设计市场购买版权）、预设的婚礼文案模板。

        - **设计引擎：** **关键部件**。使用 react-print-to-pdf 或 HTML2Canvas 等技术，将前端 React 组件渲染为高清可打印的 PDF 或图片。或者，可以调通像 `Canva API` 之类的设计平台（更简单但需考虑成本）。

- **适合 OPC 初学者的机会：**
    - **切入更小众的版本：** 不做婚礼，做“生日派对”、“公司年会”或“婴儿满月宴”的内容生成。这些场景同样高频，且有付费意愿。

    - **预算负责人：** 营销经理或小企业主。

        1.  用户通过 OAuth 授权，连接自己的邮件营销账户。

        4.  用户复制洞察或导出列表。

    - **推荐技术栈：**
        - **前端：** Next.js + React
        - **后端：** Next.js API Routes + 定时任务（用于数据同步）

    - **AI 模型用法：**
        - **自然语言生成 (NLG)：** 将分析结果（如“本周最优发送时间是周三上午 10 点，打开率提高了 15%”）转化为一段人类可读的建议文案，方便用户快速理解。
    - **如果“我”来开发，会遇到的最大难点：**
        - **数据集成和清洗：** 不同邮件服务商的 API 结构、字段、速率限制千差万别。你需要处理很多边缘情况（如用户从未发送过邮件、数据量巨大等）。
        - **做出有商业洞察的分析报告：** 真正的价值不在于展示“打开率”，而在于告诉用户“你应该怎么做”。这需要对邮件营销有深刻的理解，而不仅仅是会调用 AI API。简单的 AI 可能给出错误或无关的建议。
    - **可降低难度的捷径或更简单的第一版：**
        - **只做一个平台：** 只针对 Shopify 用户，并且只分析 Klaviyo 的数据。这样集成问题少一半。
        - **完全不做后端分析：** 让用户上传 CSV 文件。我们的 MVP 读 CS V，进行统计，然后生成一个带图表的 PDF 报告。这样就变成了一个纯前端应用，开发速度快很多。

- **适合 OPC 初学者的机会：**
    - **切入更小众的版本：** 只针对“独立开发者 SaaS 产品的用户欢迎邮件”进行分析和优化。这是一个非常具体、需求明确的场景。
    - **第一批应该访谈的客户群体：** 在 Indie Hackers 或 Product Hunt 上的独立开发者，问他们“你发送欢迎邮件后，有人打开了，但只有 2% 的人注册。你对于如何优化这个漏斗有什么问题？”
    - **1 周验证实验：**
        1.  找到 5 个在 Reddit 或 Twitter 上抱怨邮件打开率低的小商家。
        2.  手动分析他们提供的一个月邮件发送数据。
        3.  告诉他们你的建议（如：你周二下午 3 点发最好）。
        4.  问他们：“如果我开发一个工具能自动做到这点，你愿意每月付 10 美元吗？”

### 今日模式

**名为“垂直领域”的 AI 效用套装：** 真正的商业机会在于将 AI 嵌入到一个**已有清晰付费习惯和明确工作流**的垂直行业中。与其发明一个万能 AI 工具，不如围绕一个特定角色（婚礼策划师、开发者）的日常工作，开发一系列 AI 赋能的微型效用工具。Weddx 和 BenchLM 就是这种模式的代表。它们不是“AI 生成一切”，而是“AI 辅助你当前手动做的某个特定任务”。

### 建造雷达

1.  **AI 简历筛选器 (面向小型招聘机构):** 许多小型猎头公司需要快速筛选大量简历。开发一个工具，让 HR 上传批量简历（PDF/Word），输入职位要求，AI 自动给简历打分（0-100 分）并高亮候选人的匹配点和风险点。
2.  **AI 社交电商评论分析器 (面向 Shopify 卖家):** 卖家需要分析产品评论来改进产品。开发一个工具，让它定期抓取 Shopify 店铺的评论，AI 自动识别用户最常抱怨的 3 个问题（如“尺寸偏小”、“掉色严重”），并生成改进建议。售价可为 $9/月。
3.  **AI 合同审核器 (面向个体户/自由职业者):** 许多自由职业者收到客户合同时看不懂。一个简单的工具，上传 PDF 合同，自动高亮风险条款（如“无限责任”、“非常规版权”、“长期保密”），并用大白话解释每条风险。这是一个极度细分但有明确付费意愿的市场。

### 用户访谈问题

1.  （针对你正在解决的具体问题）“告诉我上一次你*手动*完成 [核心任务] 的完整过程。从任务启动到结束，你花了多少钱，心烦了几次？”
2.  （验证付费意愿）“如果有一个工具能把这个任务的耗时从 3 小时缩短到 15 分钟，但是第一次使用时需要你花 15 分钟学习。你愿意为它每月付 20 美元吗？为什么？”
3.  （了解决策流程）“你通常是独自决定使用哪类工具，还是需要请示老板或团队？如果自己决定，你下决定的最快速度是多久？如果老板拍板，你需要提交什么证据（如 ROI 分析）？”
