## 1. Aiebooks Store

**来源链接**：  
- 候选市场页：[TrustMRR / aiebooks-store](https://trustmrr.com/startup/aiebooks-store)  
- 抓取摘要来源：[TrustMRR 首页](https://trustmrr.com/)

### 1）产品
- 名称：Aiebooks Store / 摘要中显示为 `aiebooks.store`  
- 类别：AI、数字产品、电子书相关  
- 目标用户：从名称推测，可能是想快速生成或销售电子书、数字指南、AI 电子书的人。**低置信度**。  
- 具体功能摘要未说明，无法确认它是“AI 写书工具”“电子书商店”还是“AI 电子书模板库”。

### 2）用户问题
如果它确实是 AI 电子书或数字指南产品，它解决的是：  
- 写一本电子书很慢，大纲、章节、封面、排版都很费时间。  
- 独立创作者想卖数字产品，但不知道写什么、怎么包装、怎么交付。  
- 用户可能为“省时间 + 看起来能帮我赚钱”付费，而不是单纯为 AI 好奇付费。

但关键问题是：电子书生成本身已经不稀缺。真正难的是分发、选品和信任。  
如果只是“输入主题，生成一本电子书”，用户很容易试用后离开。

### 3）商业信号
- 定价模式：未知。摘要未显示定价页。  
- 收入类型：市场平台披露，非公司官方。  
- 月收入：`$115/月`  
- 年化收入：约 `$1.38k/年`  
- 售价：`$6k`  
- 倍数：`4.4x`  
- 置信度：中低。TrustMRR 页面声称是 verified startup revenues，但本次摘要没有展示验证方法。  
- 证据：TrustMRR 列表显示：`aiebooks.store Artificial Intelligence Revenue $115 Price $6k Multiple 4.4x`。

增长或牵引力：  
- 有出售挂牌，说明至少存在一个可转让的数字资产。  
- 4.4x 倍数在 TrustMRR 小产品里偏高，通常意味着买方可能在为“品牌、分发渠道、增长故事”付费，而不只是当前现金流。  
- 评论、流量、用户数、转化率：未知。

### 4）为什么可能赚钱
- 使用频率：中低。写书不是每天发生，但内容创作者会反复做数字产品。  
- 紧迫程度：中。想快速上线数字产品的人有紧迫感。  
- 预算负责人：个人创作者、小团队、营销人员。  
- 切换成本：低。用户很容易换工具。  
- 习惯优势：如果它绑定了销售页、邮件列表、模板库，习惯优势会变强。

商业判断：  
这不是一个靠“生成能力”赚钱的产品，而是靠“帮用户卖出第一本电子书”赚钱。  
如果 Aiebooks Store 只卖生成，收入 $115/月很合理；如果它能卖“选题 + 模板 + 销售页 + 分销建议”，价值会更高。

### 5）产品逻辑与技术路径
适合初学者的 MVP：
- 选择一个高付费利基，例如“AI 自动化会计对账指南”“宠物店私域营销手册”“房产经纪人短视频话术包”。
- 用户输入行业、目标读者、痛点。
- AI 生成大纲、章节、行动清单、封面文案。
- 导出 PDF/EPUB。
- 附带一个简单销售页和 Stripe 支付。

核心工作流：
1. 选择模板或输入主题。  
2. 填写目标读者和痛点。  
3. AI 生成大纲。  
4. 逐章生成内容。  
5. 生成封面和卖点。  
6. 导出并交付。  
7. 可选：生成落地页文案。

需要的数据或输入：
- 行业术语、用户痛点、成功案例。
- 模板库、提示词库、标题库。
- 支付和邮件交付数据。

推荐技术栈：
- 前端：Next.js + Tailwind CSS。
- 后端：Next.js API Routes 或 Supabase Edge Functions。
- 数据库/认证：Supabase。
- 支付：Stripe 或 Lemon Squeezy。
- AI：OpenAI API 或同类模型。
- 封面：图像生成模型。
- 数据分析：PostHog 或简单事件表。

AI 模型用法：
- 生成：大纲、章节、卖点、邮件。
- 分类：判断主题属于哪个利基。
- 抽取：从用户输入中提取读者画像和痛点。
- 检索：可选，检索行业资料，降低胡编。

如果我来开发，最大问题：
**不是生成，而是分发和信任。**  
用户为什么不自己用 ChatGPT 写？为什么相信你的电子书能卖？退款和版权怎么处理？  
技术上，PDF 排版、封面生成、支付交付都不难；难的是获客成本和“用户觉得值”。

捷径或更简单的第一版：
- 不做通用 AI 写书平台。
- 只做“某个行业的电子书包 + 销售页模板”。
- 先预售，再生成。有人付钱才做。

### 6）适合 OPC 初学者的机会
- 更小众版本：不做电子书商店，做“某个职业的 AI 内容包”，比如“保险代理人 30 天朋友圈内容包”。
- 第一批访谈客户：已经在小红书、Etsy、Gumroad、公众号卖数字产品的人。
- 1 周验证实验：做一个落地页，承诺“7 天帮你生成一本可卖的行业指南”，定价 $19-$49，目标收集 10 个预订。没有预订就换利基。

**证据不足说明**：Aiebooks Store 的具体功能、定价、用户评价均未在摘要中确认。以上产品逻辑按“AI 电子书/数字产品”假设展开，置信度低。

## 2. Verbatik AI

**来源链接**：  
- 候选市场页：[TrustMRR / verbatik](https://trustmrr.com/startup/verbatik)  
- 抓取摘要来源：[TrustMRR 首页](https://trustmrr.com/)

### 1）产品
- 名称：Verbatik / Verbatik AI  
- 类别：AI，可能是语音、配音、转录或文本转语音相关。**功能未在摘要中确认，低置信度。**  
- 目标用户：从名称推测，可能是内容创作者、视频团队、播客、企业培训、有声书制作者。

### 2）用户问题
如果它是 AI 语音/配音工具，它解决的是：  
- 视频、课程、广告、有声书需要配音，但真人录音贵、慢、难修改。  
- 多语言版本制作麻烦。  
- 创作者不想自己录音，或者声音条件不好。  
- 企业培训需要统一、可更新的语音内容。

用户付费原因：  
- 配音是反复发生的需求。  
- 一条视频改文案就要重录，AI 配音可以快速重生成。  
- 如果涉及多语言出海，付费意愿更强。

### 3）商业信号
- 定价模式：未知。摘要未显示定价页。  
- 收入类型：市场平台披露，非公司官方。

- 年化收入：约 `$27.6k/年`  
- 售价：`$40k`  
- 倍数：`1.5x`  
- 置信度：中。TrustMRR 页面声称 verified startup revenues，但非公司官方财报。  
- 证据：TrustMRR 列表显示：`Verbatik AI Artificial Intelligence Revenue $2.3k Price $40k Multiple 1.5x`。

增长或牵引力：  
- 有稳定月收入，且在出售。  
- 年化收入约 $27.6k，售价 $40k，倍数约 1.5x，属于小现金流资产。  
- 用户评价、流量、语音质量、市场份额：未知。

### 4）为什么可能赚钱
- 使用频率：高。视频、广告、课程持续需要配音。  
- 紧迫程度：中高。内容上线时间紧，重录成本高。  
- 预算负责人：内容团队、营销团队、培训部门、独立创作者。  
- 切换成本：中。如果用户保存了品牌语音、发音词典、项目，切换会麻烦。  
- 习惯优势：中。一旦进入视频工作流，会重复使用。

商业判断：  
语音工具的收入通常来自“省录音成本”和“多语言版本”。  
但通用 TTS 竞争激烈，ElevenLabs、OpenAI、Azure、Google 都在做。  
小产品必须切垂直场景，比如“房产视频配音”“亚马逊产品视频多语言”“企业培训旁白”。

### 5）产品逻辑与技术路径
适合初学者的 MVP：
- 选择一个垂直场景：例如给房产经纪人做房源视频配音。
- 用户粘贴文案，选择声音和语言。
- 生成配音，支持下载 MP3/WAV。
- 提供简单时间轴或分段编辑。
- 按条数或订阅收费。

核心工作流：
1. 输入文案。
2. 选择声音、语速、情绪。
3. 调用 TTS API 生成。
4. 试听、局部重生成。
5. 导出音频或视频工程文件。
6. 保存历史项目。

需要的数据或输入：
- 文本、语言、声音偏好。
- 品牌词典、专有名词发音。
- 用户项目历史。
- 可选：语音样本用于克隆。

推荐技术栈：
- 前端：Next.js + Tailwind CSS。
- 后端：Next.js API Routes 或 FastAPI。
- 数据库/认证：Supabase。
- 支付：Stripe。
- 语音：ElevenLabs、OpenAI TTS、Azure Speech、Deepgram 等。
- 存储：Supabase Storage 或 S3。
- 数据分析：PostHog。

AI 模型用法：
- 语音生成：TTS。
- 语音克隆：需额外授权和合规。
- 文本处理：LLM 改写文案，让语音更自然。
- 抽取：从文案中提取多语言版本。

如果我来开发，最大问题：
**语音质量、延迟、成本和版权。**  
- 高质量 TTS 按字符收费，成本会吃掉利润。  
- 用户对声音非常敏感，稍有机械感就流失。  
- 语音克隆涉及版权和伦理，必须获得授权。  
- 与 ElevenLabs 等成熟工具正面竞争很难。

捷径或更简单的第一版：
- 不做通用配音平台。
- 只做“房产房源视频多语言配音”，内置模板和发音词典。
- 用第三方 TTS API，不自己训练模型。
- 按视频收费，而不是按字符收费。

### 6）适合 OPC 初学者的机会
- 更小众版本：房产、汽车、电商、在线课程、播客摘要的垂直配音。
- 第一批访谈客户：房产经纪人、汽车经销商、跨境电商卖家、课程创作者。
- 1 周验证实验：找 10 个房产经纪人，问他们每月做多少条房源视频，是否愿意为“多语言配音 + 字幕”付 $29/月。先手动交付。

**证据不足说明**：Verbatik 的具体功能未确认。以上按“AI 语音/配音”假设展开，置信度低。下一步应验证官网、定价页和用户评论。

- 类别：AI 语音转文字、听写、写作润色。  
- 目标用户：知识工作者、写作者、开发者、客服、学生、任何需要大量打字的人。  
- 来源摘要描述：`Don’t type, just speak. The voice-to-text AI that turns speech into clear, polished writing in every app.`

### 2）用户问题
它解决的是：
- 打字慢，尤其在手机、邮件、Slack、Notion、浏览器里。
- 语音转文字后文本很乱，需要润色。
- 用户希望“说完就能用”，而不是说完再改半天。
- 跨应用输入麻烦，系统键盘和听写体验不统一。

付费原因：
- 每天都要输入文字。
- 时间节省直接可感知。
- 如果能在所有 App 里用，会形成习惯。

增长或牵引力：

### 4）为什么可能赚钱
- 使用频率：极高。输入文字是每天几十次的行为。  
- 紧迫程度：中高。打字慢的人会立刻感到痛苦。  
- 预算负责人：个人用户；企业可能为团队采购。  
- 切换成本：中高。一旦习惯语音输入，很难回到打字。  
- 习惯优势：高。系统级工具一旦融入工作流，留存通常不错。

商业判断：  
Wispr Flow 属于“输入层 AI 工具”。它的护城河不在模型，而在：
- 系统级集成。
- 低延迟。
- 隐私。
- 跨应用兼容。
- 润色质量。

这类产品很难做，但一旦做好，用户粘性强。

### 5）产品逻辑与技术路径
适合初学者的 MVP：
- 不做全系统听写。
- 先做 Chrome 扩展或网页版，专注一个场景：Gmail 回复、Slack 消息、Notion 笔记。
- 用户按住快捷键说话。
- Whisper/Deepgram 转写。
- LLM 润色成邮件/消息语气。
- 自动插入输入框。

核心工作流：
1. 用户按下快捷键。
2. 录音并上传。
3. 语音转文字。
4. LLM 根据场景润色。
5. 插入当前输入框。
6. 用户确认或修改。

需要的数据或输入：
- 音频。
- 当前应用场景。
- 用户语气偏好、常用词、专有名词。
- 隐私设置。

推荐技术栈：
- 前端：Next.js + Tailwind CSS，或 Chrome Extension。
- 后端：Next.js API Routes / FastAPI。
- 语音转写：OpenAI Whisper、Deepgram、AssemblyAI。
- 润色：OpenAI API 或同类模型。
- 数据库/认证：Supabase。
- 支付：Stripe。
- 数据分析：PostHog。

AI 模型用法：
- 语音转文字：Whisper 或 Deepgram。
- 生成/改写：LLM 润色。
- 分类：判断当前场景是邮件、聊天还是文档。
- 抽取：提取姓名、项目名、日期。
- 检索：可选，检索用户术语库。

如果我来开发，最大问题：
**系统级集成、权限、延迟、隐私。**  
- 麦克风权限、辅助功能权限、键盘权限都很麻烦。  
- 用户要求实时，网络延迟会毁掉体验。  
- 音频隐私敏感，企业客户会问数据是否上传。  
- 转写和润色 API 成本会随使用量上升。  
- 跨 App 插入文本在不同操作系统上兼容性差。

捷径或更简单的第一版：
- 先做 Chrome 扩展，只支持 Gmail 和 Slack。
- 不做实时流式，先做“按住说话，松手 2 秒后插入”。
- 让用户自己选择润色风格：简洁、正式、友好。
- 用第三方 API，不自己部署模型。

### 6）适合 OPC 初学者的机会
- 更小众版本：面向医生、律师、客服、房产中介的垂直听写+模板。
- 第一批访谈客户：每天写 20 封以上邮件的人、客服主管、销售。
- 1 周验证实验：做一个 Chrome 扩展原型，只支持 Gmail 回复。找 10 个销售测试，观察他们是否愿意每天用 5 次以上。

**收入未知说明**：Wispr Flow 没有公开 MRR/ARR。TAAFT 摘要只显示 `Try for Free` 和赞助位，不能推断收入。置信度低。

## 今日模式

**模式：小现金流产品的价值，不只在收入，而在“可转移的分发和习惯”。**

今天 TrustMRR 上的几个小产品给了很清楚的信号：

- Verbatik AI：约 `$2.3k/月`，售价 `$40k`，年化收入倍数约 `1.5x`。
- Krato：约 `$1.2k/月`，售价 `$20k`，年化收入倍数约 `1.4x`。
- Aiebooks Store：约 `$115/月`，售价 `$6k`，年化收入倍数约 `4.4x`。

这说明：
1. 有稳定月收入的小产品，可以按年收入 1-1.5x 出售。  
2. 收入很低但倍数很高的产品，买方可能买的是“增长故事、品牌、分发渠道或模板资产”。  
3. 对个人创业者来说，从第一天就记录用户来源、邮件列表、转化率、留存，比单纯堆功能更重要。  
4. AI 产品护城河不在模型，而在场景、集成、隐私、习惯和分发。

一句话：  
**不要只做“AI 能生成什么”，要做“谁每天必须用它完成什么工作”。**
