## 一、AutoReels.AI

- **产品**：AI 短视频自动生成工具（从名字看，面向 Instagram Reels / 短视频场景）
- **目标用户**：个人创作者、社媒运营、中小电商商家
- **URL**：[TrustMRR 挂牌页](https://trustmrr.com/startup/autoreels-ai)

### 用户问题

持续产出短视频是社媒运营最耗时的环节：想选题、写脚本、找素材、剪辑、加字幕、配音乐。AutoReels 要解决的，就是“把每周产出 3-7 条短视频的流程自动化”。

用户付费不是因为“AI 很酷”，而是因为：

- 手动剪辑一条 30 秒视频，至少花 1-2 小时；
- 外包剪辑每条要 50-200 元，不稳定；
- 个人创作者和实体店老板都没时间学专业剪辑软件。

### 商业信号

| 维度 | 数据 |
|---|---|
| 定价模式 | **未知**（TrustMRR 摘要未提供定价页信息，推测为订阅制，低置信度） |
| 月收入估算 | **$1,500/月**（卖方申报，置信度：中） |
| 售价 | $65,000（收入倍数 3.6x） |
| 增长线索 | 能以 3.6x 倍数挂售，说明卖家认为它有增长潜力，或客户关系/素材库有额外价值 |

证据：[TrustMRR 列表](https://trustmrr.com/startup/autoreels-ai) 显示 Revenue $1.5k，Price $65k，Multiple 3.6x。

### 为什么可能赚钱

- **使用频率高**：做社媒的人每周都要发多条视频；
- **紧迫程度高**：发不发内容直接影响账号更新和流量；
- **付费习惯成熟**：Canva、CapCut、剪映的会员说明这类人群已经为“效率”付过费；
- **切换成本中等**：如果产品绑定品牌素材库、常用模板，用户不会轻易换。

### 产品逻辑与技术路径

**MVP 范围**：第一版不要做“AI 从零生成视频”，那又贵又不稳定。应该做“半自动剪辑器”：

> 用户上传手机拍摄的视频或商品照片 → AI 根据文案生成脚本 → 自动挑选片段 → 拼接 → 生成字幕 → 输出带字幕的短视频。

**核心工作流**：

1. 用户输入主题（例如“美甲店的新春促销”）；
2. 调用 LLM 生成 20-30 字的口播文案；
3. 用 Whisper 或云端 API 生成字幕；
4. 用 FFmpeg 拼接素材、加转场和背景音乐；
5. 导出成 MP4，用户自己上传到 Reels/抖音/小红书。

**推荐技术栈**：

- Next.js（前端）
- Supabase（数据库 + 认证 + 存储）
- FFmpeg.wasm 或服务端 FFmpeg（视频处理）
- OpenAI API（文案生成）
- Whisper API（字幕）

**如果我来开发，会遇到的最大问题**：

1. **视频处理成本不可控**：FFmpeg 渲染吃 CPU，并发一多云账单就飙升；如果直接用 Runway / Replicate 等视频生成 API，单条视频成本可能达 $0.5-$2，订阅费根本 cover 不住。
2. **输出质量难稳定**：AI 生成视频容易出现人脸变形、字幕不同步，用户会怪到你头上。
3. **平台 API 限制**：自动发布到 Instagram / 抖音需要官方审核，搞不好封号。

**降低难度的捷径**：

> 第一版不做“生成视频”，只做“素材混剪 + 文字转字幕”。这种效果虽然不那么“AI”，但成本低、速度快、质量稳定，足够让第一家客户付钱。

### 适合 OPC 初学者的机会

**更小的切口**：垂直行业模板生成器，例如“美甲店专属视频生成器”。

- 商家上传 5 张开业照片，AI 自动生成一条带促销文案、字幕、背景音乐的短视频；
- 定价对标外包剪辑费的 1/5，按月订阅。

**第一批访谈客户**：

- 本地餐饮店 / 美甲店店主
- 在小红书 / Instagram 卖货的个人卖家

**1 周验证实验**：

> 手动服务 5 家美甲店或餐厅：每天用剪映帮他们剪 1 条视频，收体验价。观察他们最在意的元素（文案、音乐、字幕？），再决定开发哪块自动化。这比先写代码便宜得多。

## 二、Search1API

- **产品**：开发者工具（AI 搜索 / 搜索聚合 API）
- **目标用户**：AI 应用开发者、Agent 开发者、RAG 应用团队
- **URL**：[TrustMRR 挂牌页](https://trustmrr.com/startup/search1api)

### 用户问题

现在的 AI 应用大量需要实时信息，比如“根据今天的新闻回答”“查竞品价格”“获取最新动态”。但开发者自己爬百度/Google 很容易被封，接入 Tavily、Brave、SerpAPI 等又要管理多个密钥和多份账单。

Search1API 的卖点很可能是：**用一个 API 完成搜索 + 内容提取 + 结构化输出**，帮开发者省掉集成时间。

这类产品商业模式不新但有效：**把多个搜索源封装起来，按调用量收费**。开发者付费是因为省下的集成时间远大于 API 费用。

### 商业信号

| 维度 | 数据 |
|---|---|
| 定价模式 | **未知**（推测为按量计费或月套餐，低置信度） |
| 月收入估算 | **$1,300/月**（卖方申报，置信度：中） |
| 售价 | $50,000（收入倍数 3.3x） |
| 增长线索 | 3.3x 倍数说明卖家认为还有增长空间；但 $1.3k/月也说明这是低价走量型市场 |

证据：[TrustMRR 列表](https://trustmrr.com/startup/search1api) 显示 Revenue $1.3k，Price $50k，Multiple 3.3x。

### 为什么可能赚钱

- **使用频率高**：对真做 LLM 应用的团队，搜索是每天调用几十到几千次的刚需；
- **预算负责人明确**：开发者 / 技术负责人，算得清“省下 10 小时集成时间”值多少钱；
- **切换成本高**：一旦集成进代码，只要稳定就不愿意换，客户留存好，收入有复利。

### 产品逻辑与技术路径

**MVP 范围**：一个轻量代理服务：

> 接收查询请求 → 调用一个搜索源（先用 Tavily 免费档或 Brave Search API）→ 结果去重 → 返回 JSON。

**核心工作流**：

1. 客户端传 query + language；
2. 服务端查缓存，缓存未命中则调用搜索 API；
3. 可选：用 LLM 对搜索结果做摘要；
4. 返回前 10 条结果 + 摘要。

**推荐技术栈**：

- FastAPI（后端）
- Supabase（认证 + 用量统计）
- Redis 或 Postgres（缓存，防重复查询）
- Stripe / Lemon Squeezy（按量计费）

**如果我来开发，会遇到的最大问题**：

1. **上游成本不可控**：搜索 API 本身按次收费，如果缓存命中率不高，毛利会很薄；
2. **搜索结果质量**：如何排序、去重、过滤垃圾站，需要长期调优；
3. **按量计费的基础设施**：要精确记录每次调用、按月出账单，这个“计费系统”本身也是工作量。

**降低难度的捷径**：

> 第一版只做“单源 + 缓存”，先跑通需求。不要一上来就聚合多个搜索源，那会把自己累死。

### 适合 OPC 初学者的机会

**更垂直的切口**：不做通用搜索 API，做“AI 产品经理竞品情报 API”。

- 输入竞品官网 / App Store 链接；
- 每天自动抓取竞品的定价页、更新日志、Product Hunt、X 热帖；
- 输出一份 200 字摘要：“竞品这周做了什么变化，对你有什么影响”。

这类用户（产品经理、创始人）付费意愿强，且愿意为“省调研时间”按月付费。

**第一批访谈客户**：

- 做 RAG 或 Agent 的独立开发者
- 小团队 CTO / 技术负责人

**1 周验证实验**：

> 用 Tavily 免费档手动做一个网页 demo，自己录一段视频发给 10 个做 AI 产品的人，问一句：“如果输入竞品名就能每周自动收到竞品动态摘要，你愿意付 $20/月吗？”先验证付费意愿，再写代码。

### 产品逻辑与技术路径（以 AI 演示工具为例，明确标注是假设）

**MVP 范围**：

> 不做多人协作、不做复杂动画，只做：用户输入一句话主题 → AI 生成 10 页大纲 → 用户逐页用自然语言修改 → 导出 PDF / HTML。

**核心工作流**：

1. 用户输入：“给一家奶茶品牌做一份小红书营销方案”；
2. LLM 返回结构化 JSON 大纲（每页标题 + 要点 + 备注）；
3. 前端用 Tailwind 模板自动渲染成幻灯片；
4. 用户逐页微调；
5. 导出 PDF。

**推荐技术栈**：

- Next.js + Tailwind CSS
- OpenAI API（生成内容）
- Supabase（保存文档）
- pptxgenjs（后续导出 PPTX 用）

**如果我来开发，会遇到的最大问题**：

1. **模板设计**：AI 生成内容越来越容易，“排版好看”才是真付费点。Tailwind 新手做出来的页面和 Word 差不多，用户不会买单。
   - **解法**：不要自己设计，用开源 Decker 模板或基于 react-pdf / HTML2PDF 做几套高质量模板，把视觉部分“外包”给模板。
2. **导出格式**：用户想要 PPTX 而不是 PDF。但生成可编辑 PPTX 复杂度很高。
   - **解法**：第一版只导出 PDF，等验证有付费用户后再加 PPTX。不要一上来就追求完美导出。

- 先收集他们的 3 份旧提案，总结出结构；
- 用户输入客户公司名和需求，AI 用他们的结构填充内容。

**第一批访谈客户**：

- 独立顾问
- 淘宝 / 闲鱼上接 PPT 代做订单的人，但他们是“卖家”，对提效工具付费意愿极强；

**1 周验证实验**：

## 四、Finest（收入未知的 B2B 基础设施）

- **产品**：LLM 推理成本优化 / 统一模型 API 网关
- **目标用户**：AI 产品团队、有推理账单的独立开发者
- **URL**：[Finest 官网](https://finest.so/)

### 产品是什么

Finest 的官方描述是：

> “When your product takes off, your inference bill shouldn’t. One API. Up to 70% less. Quality holds.”

翻译过来就是：**同一套 API 接入，自动选择最优模型 / 缓存策略，最多节省 70% 推理成本，同时保持输出质量。**

这类产品本质是“LLM 网关 / 模型路由”：系统自动判断请求复杂度，简单请求走便宜小模型，复杂请求才走 GPT / Claude 级别的大模型。

### 用户问题

对 AI 产品创业者来说，最尴尬的事是：“我的产品有人用了，但我越成功越亏钱”——API 账单随流量上涨。Finest 卖的是一个极其直接的结果：**省钱**。

### 商业信号

| 维度 | 数据 |
|---|---|
| 定价模式 | **未知**（推测为按量抽成或月费订阅，低置信度） |
| 月收入估算 | **未知**（无公开收入数字） |
| 增长线索 | 出现在 TAAFT 首页赞助位，说明团队有市场推广预算，正在积极获取开发者用户 |

证据：来源目录赞助商链接 [Finest 官网](https://finest.so/)，注意是来源摘要补充，**证据不足，请按低置信度对待**。

### 为什么可能赚钱

- **痛点直接**：每个用 OpenAI / Claude API 的团队都能立刻看懂这个价值；
- **ROI 可量化**：“用了你，每月省 $X”，这是 B2B 销售里最强的文案；
- **预算负责人明确**：CTO 或创始人对“省钱”有决策权；
- **切换成本中等**：虽然是一个代理层，但接进来之后，只要稳定性好，开发者不会轻易换。

### 产品逻辑与技术路径

**MVP 范围**：一个“低成本推理路由器”。

> 接收用户请求 → 判断复杂度 → 路由到不同模型 → 返回结果。

**核心工作流**：

1. 用户请求带提示词长度、模型优先级；
2. 规则引擎判断：是否需要视觉能力？是否需要最强推理？
3. 简单请求路由到 Claude Haiku / GPT-4o-mini 等便宜模型；
4. 对重复请求做缓存；
5. 返回结果，并记录“本次请求帮你省了多少钱”。

**推荐技术栈**：

- FastAPI 或 Go 网关（Go 更适合高性能代理）
- Redis（缓存）
- Supabase（用量统计）
- Stripe（计费）

**如果我来开发，会遇到的最大问题**：

1. **质量保证难**：用户说“质量不允许下降”，但如何评估路由后的输出质量？需要大量测试集和 A/B 评估体系，这是一个大工程。
2. **信任问题**：用户不会轻易把 API 流量转发给一个陌生网关。必须有透明仪表盘，显示每次请求用了什么模型、成本是多少。
3. **毛利很薄**：如果你只做“转卖”，上游模型厂商自己降价或推出原生网关，你的生意就被做掉了。Finest 的真正壁垒应该是路由策略和成本优化算法，而不是单纯代理。

### 适合 OPC 初学者的机会

如果不想做基础设施（这个方向对新手太重），可以做**垂直的成本监控工具**：

- 连接用户的 OpenAI 账单；
- 识别浪费点：重复 prompt、长上下文未压缩、一直用最强模型；
- 每月生成一份“可节省金额清单”；
- 按节省金额的 10% 抽成。

**第一批访谈客户**：

- 每月 API 账单超过 $200 的独立开发者
- AI 创业公司 CTO

**1 周验证实验**：

> 用 OpenAI 的 Usage API 拉取自己的账单，手做一份“在过去 3 个月，你浪费了多少钱”的分析报告模板。发给 10 个做 AI 产品的朋友看，如果有人主动问“怎么做到的”，这个方向就有戏。

## 今日模式

今天 4 个产品，表面上看是不同的领域（视频、API、演示、基础设施），底层是同一个模式：

> **在“AI 能力”和“用户实际工作流”之间，增加一层确定性服务。**

- AutoReels 不做“AI 生视频”，而是“AI 帮你把素材变成一条能发的视频”；
- Search1API 不做大模型，而是“AI 应用需要的搜索能力”；
- Flowboard 大概率是把“想法”变成“能演示的 Deck”；
- Finest 不提供模型，而是“让现有模型更便宜”。

这给 OPC 创业者的启示是：**你不必追最前沿的模型，而是选一个具体场景，用确定性的输出（一段视频、一个 JSON、一份 PPT、一张账单分析）帮用户省时间和钱。**
